# C077 V3 上位机与工厂 CLI

本轮固件来自 C060 `184e6b0` 重建的 `codex/c077`，目录 `E:/sync/git/me/c060/new c060/c077-v3`，运行合同为该工程 `docs/c077-contract.md`。上位机在 `codex-c077-host-v3` 独立分支维护，基线 `5a010fd039777bf99bf7b02e02c868bfef759248`；所有新事实来自本轮固件合同与实际源码。客户WPF、工厂WPF、CLI共用 BmsClient / Shared；没有复制协议实现。

## 参数

D170明确识别板号C0770016、APP08001C00和51KiB槽，16串，缺位61001。65个保护默认值逐项保留旧工程，本轮客户端支持三级/恢复值相等及完整uint16非零Filter，按当前固件校验顺序。软件充电12A与最低硬件OCC40A分别生效，界面不把最低硬件档位当作软件门限下限。

仅AFE1开启CADC，采电流、RAM校零和SOC；AFE2电流和校零显示“未启用”。16路单体、AFE1/AFE2电压校准、总压、充/放电电流K/B、真实NTC槽0/1/3/4和MOS NTC系数可维护；无效串位及未装NTC保持只读。固定16串、4颗2mΩ/片。

短路参数可以编辑：按旧整数规则将0.1A除20换为mV，选择首个不低于该值的档位；延时按64μs向上量化，AFE2再高一级电流/延时。默认请求300A发布为AFE1 340A/128μs、AFE2 400A/192μs。参数保存只提交Flash，硬件档位改变时客户端先核对输出/均衡关闭，固件再次直接读回确认；随后须明确执行工厂配置，不会因参数写入自动编程EEPROM。

保留新鲜整组读取、先验证全部候选再写、按组回读、无变化不写、部分失败报告已完成组、结果不确定不重发、JSON产品标签隔离。C060与C077参数包互相拒绝导入。

## 诊断与完成判据

单帧03读取2A40/64字，要求schema2。两片分别报告配置匹配、CONF/BSTATUS/BFLAG、原始25字节配置及只读TR、采样有效、最近错误及寄存器；显示实际OCC/OCD1/SC档位。最近错误是保留诊断，不能替代当前资格。全局报告工厂阶段、结果和芯片/寄存器位置、MCU输出、两片许可/FET交集、均衡关闭、pack有效、AFE1校零状态/偏置/样本及MOS开启待确认/控制故障。

06写2A7F=C077执行双片差异配置，5A07只重试AFE1 RAM校零。工厂编程只在内部WPF和显式CLI入口提供。ACK表示受理；完成必须工厂阶段0、无结果错误、两片配置及测量有效、AFE1校零READY、pack有效、均衡关闭、无开启待确认及控制故障。AFE2不等待校零。失败/取消/超时均不自动重发写命令；报告部分配置及实际失败位置，要求明确重试。

```powershell
bms-cli afe309 check --serial COMx --json
bms-cli afe309 zero --serial COMx --yes --json
bms-cli afe309 program --serial COMx --yes --json
bms-cli parameters get --serial COMx --json
bms-cli parameters export --serial COMx --output C077_parameters.json --json
bms-cli ota firmware.c077 --serial COMx --target stm32 --yes --json
```

`check`是`get`只读别名；zero/program仍需显式`--yes`。已有CLI JSON envelope保持，snapshot更新为schema2语义，新增ServiceError/ServicePosition及每片LastError/LastRegister/CurrentEnabled。所有工厂操作以固件读回门禁为准。

包解析继续使用format2及D170能力校验，C077专用Boot，错板包拒绝；首次安装须配套工厂HEX，不能通过现场APP包迁移旧Boot。外置EEPROM不读入、不写入；内部Flash使用本轮C077格式及产品标识。
