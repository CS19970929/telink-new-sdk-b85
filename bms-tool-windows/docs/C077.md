# C077 / 双SH367309 上位机配套

## 范围与源码

本次分支 codex-c077-host 基于13682956。用户指定的 bms-tool-windows 为唯一真源；客户WPF、内部WPF、CLI使用相同BmsClient/Shared，Core显式引入C077Parameters.cs。Telink SDK和其它产品固件保持原范围。

C077通过D170 v1明确识别C0770016、APP08001C00、容量CC00、format2；IsC077独立于IsC060，UsesC060Protocol只表示复用原线协议。采集16串，缺失串位61001，主界面沿用正放负充；309原始诊断电流明确标注充正放负。无可靠身份不猜测309硬件模型。

## 参数与维护

产品参数页动态显示C060/C077及20/16串。C077复用65字软件保护和常规分组保存/回读、Flash无变化；软件门限候选须在双309固定硬档案内。309最低充电硬件门限40A；无法按当前软件12A配置成13A。16串、4×2mΩ、硬件短路400A/448μs固定只读，不用BQ档位量化。C077不读取已退役的分段电流校准区域，未使用的串位/电流系数/温度通道保持只读。JSON产品标签隔离，C060/C077互相拒绝导入。

“读取双309诊断/零偏”展示两颗配置匹配、独立signed offset counts、8个样本状态、CONF、BSTATUS、TR、当前原始方向电流和测量资格。0x2A40起64字schema1；58..60为全局采样、MOS开启待确认和驱动故障。既有3510/3520的2500/2540模型不用于309。

客户版的零偏重试需高级功能解锁及明确操作，偏置仅RAM；工厂版另提供明确EEPROM维修入口。维修只发06 2A7F=C077，零偏重试为5A07；ACK仅代表受理，继续轮询直至两颗配置/零偏/测量和全局资格确认。失败、超时、取消均不自动重发写命令。EEPROM寿命、混合配置和真实零电流约束在确认界面明确提示。

无脉冲启动关断依赖两颗309已配置CTLC=11。空白芯片须先在断开负载/充电器的工装中完成档案设置，再接成品通路；MCU CTL低不能证明未知CTLC芯片关闭。GPIO请求、CONF许可、BSTATUS3和物理VGS是不同证据，实板必须单独验收。

## CLI与升级

```powershell
bms-cli afe309 get --serial COMx --json
bms-cli afe309 zero --serial COMx --yes --json
bms-cli afe309 program --serial COMx --yes --json
bms-cli parameters get --serial COMx --json
bms-cli parameters export --serial COMx --output C077_parameters.json --json
bms-cli ota firmware.c077 --serial COMx --target stm32 --yes --json
```

zero/program必须显式--yes，设备端再次核对输出/均衡关闭；JSON保持现有envelope，新增命令不改变旧命令。程序按包内板号识别C077，D170与包内身份/APP地址/长度须一致；C060包不能发C077，反向也拒绝。IAP完全共用，C077使用自己的APP/包及工厂产品记录。首次装机按固件工厂方案，不能借现场APP包迁移未知旧Boot。
