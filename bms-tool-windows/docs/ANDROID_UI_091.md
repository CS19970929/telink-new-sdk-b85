日期：2026-11-06。沿用现有安卓App与公共协议核心，根分支`codex-d015-ymodem-host`。本次不修改BMS固件、Windows页面、寄存器或升级格式；不增加K/B功能。

## 六项调整

| 要求 | 当前行为 |
| --- | --- |
| 当前设备信息移到电池页 | “设备信息”显示蓝牙名、MAC、SN、硬件/软件版本、Build ID；断开或换设备先清旧身份 |
| 客户版隐藏SOH、满充、额定容量 | 客户版电池页及占位文案均不显示；保留剩余容量、循环和温度；内部版保留完整数据 |

| 固件升级放入服务设置 | 客户版设备→进入服务设置→固件升级，沿用原服务密码；内部版在服务与设备设置区域直接进入 |
| 删除手动/上次设备 | 两版仅扫描和MAC扫码选择；不再读写last_bms_mac；内部自动化保留显式目标参数 |
| 升级页简洁 | 保留目标、选择文件、折叠的已导入列表、进度、开始/取消；只留一条供电/蓝牙提示，不写项目或协议说明 |

## 客户操作

1. 设备页展开“连接其他电池”，扫描并点选设备，或扫码MAC连接。
2. 电池页查看实时数据和下方“设备信息”。
3. 记录页点击“读取设备事件”，查看设备历史。
4. 需要升级时，设备页点击“进入服务设置”，输入现有密码`hs456`，再打开“固件升级”。
5. 选择固件，核对设备MAC和文件，确认开始。升级期间保持供电和蓝牙连接。

升级中断且APP无法通信时，仍先扫描/扫码明确选择原模块，再进入服务设置；服务入口不依赖APP probe，公共升级核心继续识别Boot。普通参数写入仍要求有效APP连接。

外部分享/文件Intent可导入固件，不能让客户绕过服务设置打开升级操作。密码弹窗期间目标MAC或会话变化时拒绝授权；升级确认后再次检查所选MAC，防止离线恢复向旧目标发送。断开后退出客户服务模式。客户的可选SN输入收起，内部版在折叠的“额外身份核对”中保留。

## 数据与兼容

隐藏只影响页面展示，原协议字段和共享模型不变。软件保护与常规参数读写、整组提交、回读确认保持。升级仍按固件内容预检、设备/地址匹配及最终版本/长度/CRC确认；页面文案精简不降低检查。

仅普通客户不再通过Intent/偏好恢复MAC。内部自动发送仍须显式授权且匹配当前已有连接，不自动扫描第一台；自动化不会因删除输入框而失去目标。
