# D015编译提交号与上位机显示

固件在编译前取Git HEAD前8位作为32位Build ID，另有dirty和debug/production标记。既有TryReadFirmwareBuildIdAsync接口保持返回uint?；新增TryReadFirmwareBuildIdentityAsync返回带状态的身份，客户版和内部版身份页同时显示。CLI既有Build ID读取/JSON字段不变。

读取2A00起24字，magic4447/schema1，2A0D bit2=production、bit3=dirty，2A16低word/2A17高word组合32位值。capability=0是仅身份固件；完整诊断读取只展示身份，不继续请求不存在的运行快照/Trace。旧固件不支持时显示不可用；取消仍传播，不将缺失ID猜成当前版本。

固件Git信息只在PC构建阶段取得；没有Git或误识别父仓库会拒绝构建，不沿用旧标识。dirty表示提交本身不能复现整个工作树；前8位不是唯一镜像哈希，不能替代完整SHA、构建模式、编译命令及镜像CRC。D015的参数/Flash/IAP布局和版本号保持。

验证：客户/内部WPF及CLI实际编译通过，客户版仅既有CS0649。两版生产程序集调用真实D015 C业务模块（模拟AFE/Flash）核对Build ID字序、旧API兼容、最小诊断及原参数/校准/SN/IAP流程，未连接设备或执行升级。
