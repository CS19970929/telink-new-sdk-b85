# 断线检测页与自动记录

2026-10-08：客户版、内部版共享同一实现，固件配套窗口为 Modbus 03 `0x3600`、48 words，magic `0x4F57`、schema 1，capability `0x0100`。窗口只读；现有 OTA、参数地址和格式不变。

连接设备并保持电池实时刷新，打开“断线检测”。“自动监控并写盘”默认开启，和 MOS 页共用；OTA、连接中断、用户暂停及磁盘失败沿用同一生命周期。旧固件显示不支持，过期或读失败显示状态未知。

“实时监控”主界面的“单体电压”区域直接显示已锁存故障通道，例如 `C1, C3`，故障为红色。串号来自固件 `FaultMask`，不根据普通电压、零值或 61001 猜测。`Cn` 表示现有固件映射的测量通道，不直接等同于某根物理采样线；SH 明示“通道映射待实板确认”。未完成检测、疑似异常、正在检测都不能显示为健康；只有有效、完整、确定的健康结果显示“最近完整检测未发现断线”。暂停、OTA、断连、读失败或超过 5 秒未刷新显示当前串号未知。

当前配套固件自动调度：正常启动先等 10 秒，再累计 50 个合格空闲样本（200 ms 服务周期，约 10 秒）；正常完成后等 300 秒，再重新累计空闲资格。疑似采样异常可跳过空闲累计，但不能绕过既有等待/退避。确认故障或失败后等 10 秒重试。资格要求 AFE 样本可信、充放电上报电流均为零、没有加热请求/运行、参数及安全门禁允许，启动前停止并确认均衡。持续充放电会推迟检测；倒计时到零仍可能等待资格。检测中资格变化则中止并记录，不能据此判断线。

界面区分检测中、最近健康、已锁存故障、检测失败和激励待清理；显示启动/完成/失败计数、周期/退避剩余时间、耗时、当前及保留的最近失败、原始 IND=0/1 掩码。检测中可以同时存在以前已锁存的真实故障：此时 MOS 仍因故障保护阻断。软件请求/阻断及 AFE 报告不等于物理 Gate 实测。

“MOS 监控 → 打开记录目录”：`%LOCALAPPDATA%\BmsAssistant\MosMonitor\<session>\mos_*.jsonl`。

- `kind=openwire`：每次读取原始 `Words[48]`，计数、序号、构建号、更新时间与状态摘要。
- `kind=openwire-gap`：暂停、过期或读失败。计数跨越和序号/tick 回退提示期间结果缺口或重启。
- 与 `sample`、`firmware`、`diagnostic`、`gap` 共用接收分段和背景，便于判断上位机变化是否有固件证据。

“诊断 → 读取完整诊断 → 导出 AI 诊断包”包含 `EvidenceBlocks.OpenWire`；CLI `diag --json` 或 `--output <zip>`也包含此窗口，便于 AI 直接分析。文件分卷且不自动删除，窗口列表只保留最近 300 次变化。快照仅保存正在检测/最近结果及累计计数，不保证复原两次轮询间的全部事件。

固件行为：检测启动/运行/超时/重试不主动写 MOS 关闭，完整确定的故障仍保护阻断；真实 AFE I/O 故障仍可通过通信安全门禁关闭 MOS。SH 手册奇偶掩码映射有冲突，原始异常不能按既有映射确定时显示不确定，不能报健康或清旧故障；逐路通道和物理 Gate 尚需实板验收。

本轮固件源码尚未编译/测试/OTA；旧板运行新上位机时显示不支持是正常的配套版本差异。上位机实际三入口构建、只读协议/诊断回归和界面验收的证据在本次交付目录。
