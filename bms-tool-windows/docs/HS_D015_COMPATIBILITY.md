# STM32F030C8 / SH3673520 HS-D015 适配

2026-10-28，基于 `feature/windows-afe-hw-protection-editor-v2@a6bcc552`，实现分支 `codex-f030-3520-host-compat`。
配套固件仓库 `D:\TODO\030 3520`、分支 `codex/io-iap-windows-compat`。
本仓库已有 `codex` 分支，Git 不允许同时创建 `codex/...`，因此使用上述分支名。

客户版与内部版共用“3520 参数”页，读取确认本板 `0x2500` 的 magic/version、w24=`0xD015`、w25=13 后才可修改。
客户版写入保留高级功能解锁要求；内部版仍使用现有 OTA 页面，客户版原有 OTA 隐藏边界不变。
其它型号继续使用原业务/AFE页面；不会把 Telink 35-word AFE profile 当成3520的24-word参数。

页面支持原子写入并读回保护参数、SN、额定容量、SOC及循环次数。
电压、电流、温度等由原实时页读取，不能写入遥测值。
先断开弱电开关，设置容量（1.0～655.3 Ah）、硬件保护和恢复条件；核对完整配置后显式点击核准。
只写容量不会自动使能MOS。首次SOC应按已知电量设置，之后SOC/循环次数保存受固件人工保存间隔限制。
SN最多32字节可打印ASCII，`0xC002`一次写16 words；容量`0x2318`为0.1Ah，SOC`0x1005`为百分数，循环`0x2319`为整数。
硬件型号和软件版本仍从`0xC012/0xC022`读取。

3520保护写入`0x2500`完整24 words，读取32 words。NTC电阻按芯片档位量化，保存后按code比较请求与读回，再刷新配置值。
本板固定必要保护及TS1/TS2/TS4，TS3固定电阻不参与保护，对应9个使能字段不可编辑。
恢复电流在本板保留1mA精度，其他3520型号保持原100mA规则。
AFE未确认配置时页面明确显示保存配置/编辑模板，不能把MCU保存值解释成物理保护已经验收。
不为HS-D015增加独立软件保护、加热或任意AFE寄存器写入。

升级继续沿用参考`E:\TODO\030-iap`的`0xFFFD/0xFFFE/0xFFFF`。
页为1024字节，quantity=1024、byte-count=0、总帧1033字节；最后一页用FF补齐。
ENTER前读取本板能力：APP起址`0x08002800`，最多23页/23552字节；保留SRAM前256字节，SP八字节对齐且允许栈顶`0x20002000`。
未知3520板型或不匹配镜像在发送ENTER之前拒绝。旧STM32没有3520能力窗口时保留原升级路径和容量边界。
页ACK丢失不自动重传，因为参考协议没有页号；写入结果未知时停止。设备30秒会话超时后可从头开始，或复位后重启。
COMPLETE成功后等待200ms复位及2秒恢复窗口，留出启动余量再重新连接实际APP，读取`0xD130`板型、`0xD13D`安装CRC32和补齐长度并与当前文件比较。
CLI复用同一发送器，因此具有相同的本板预检与升级后验证。ACK单独不构成升级成功。

固件需要先更新配套IAP；原XMODEM IAP不能接收此协议。未执行任何自动烧录或升级。
原Windows SN共享页面中调用不存在的`RefreshIdentityAsync(ct)`会阻止两版编译，本次改为取消检查后调用现有无参方法。

## 验证

- `test-hs-d015-ota.ps1`：使用实际BmsClient及STM32升级发送器，48项检查覆盖线缆帧、FF补齐、本板预检、CRC回读、ACK丢失不重发和旧STM32回归。
- `test-ota-protocol.ps1`：原Telink OTA回归及HS-D015 SP/Thumb/入口/容量边界、独立IEEE CRC32 golden。
- `test-3520-parameters.ps1`：17项编码/量化/滞回/读回及固定使能检查。
- `test-main-window-experience.ps1`：两版主窗口离屏检查，包含3520入口、列定义、测量只读说明和未连接拒绝操作。
- 客户WPF、内部WPF和CLI均须构建；所有obj/bin/测试缓存重定向至用户临时区。

以上均为软件证据。没有实板通信、升级掉电、保护触发、Gate、NTC/电流精度或低功耗验收。
