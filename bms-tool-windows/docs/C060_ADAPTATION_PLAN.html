1. 结论与建议路线

连接、实时数据、常规参数和保护参数，主要由新上位机适配；当前 C060 不需要为这些功能改成 D008/D015 协议。 新上位机已经具备公共 Modbus 客户端、保护表格和分组写入机制，应该在这些实现上增加明确的 C060 配置与分支。

要求“所有参数均可无损备份还原”、BQ76930 硬件保护编辑或完整运行诊断时，仅改上位机不够。 C060 的分段电流校准读接口缺少完整 K/B、端点；AFE 硬件保护和运行诊断也没有现成的配套接口。这些需要单独界定最小固件扩展，不能把未实现功能显示为可用。

推荐先完成 P0～P2，使现有 C060 可以稳定连接、监控、读写全部已有常规参数和 65 个保护字段；再推进 P3 的完整校准与可选固件能力；升级按正在开发的新 C060 IAP 独立接入。每个阶段分别验证、分别提交。

2. 分析对象与范围

新上位机仓库是用户指定的 Telink SDK 目录，但本次适配对象是其中的 bms-tool-windows/，不是 TLSR8251 产品固件：

  • BmsTool.Windows/：客户版 Windows WPF。
  • BmsFactoryTest.Windows/：内部完整测试版；截图的报错文案来自此项目。
  • Shared/、BmsTool.Core/：身份、参数、诊断、协议等公共实现。
  • BmsTool.Cli/：复用公共协议的 CLI，应同步支持 C060 识别和基本读取。
  • BmsTool.Android/：本轮不扩展 Android 页面；公共 Core 的修改应保持其编译/API 兼容。

上位机源码基线为 7d6ba37ea261d97a931c638de7e2f3c556f09349，分支 codex-d015-ymodem-host。C060 通信分析基线为 c767f4659346350164ff41be44eaa4128a085299，分支 new-dev-c060；工作区另外存在正在开发的新版 IAP 和工程改动，且本轮分析期间仍在变化。因此，旧 APP 当前通信行为、新 Boot 开发进度、实际装机 Boot 版本必须分开记录。本文后附源码 SHA-256，可用于复核漂移。

本轮只做源码核查、读取既有本机日志和离线模型验证；没有连接或写入实板，没有生成固件 BIN/HEX，没有改变产品源码。旧 BMS-upper 方案暂停，不作为新上位机的实现入口。

3. 连接失败的确定原因

3.1 现场证据

本机日志 BmsAssistant_20261105_200835_606.log 记录了 20:09:05～20:09:07 的完整失败过程：

顺序实际行为结果
1Windows BLE 建连、发现 GATT，协商 MTU 247成功
203 / D120 / 2，再回退 03 / D000 / 4探测成功，记录 legacy-compatible
303 / 0000 / 3 读取 MCU MACC060 返回异常，但代码已有回退处理
403 / C002 / 16 读取 SN成功
503 / C012 / 16 读取硬件版本返回 01 83 01 80 F0，异常未被隔离，弹出“连接失败”

关键请求是 01 03 C0 12 00 10 D8 03。应答 01 83 01 80 F0 是 CRC 有效的设备异常应答；C060 的 01 表示 地址不合法。不能照标准 Modbus 的编号把它解释为“不支持功能码 03”。固件明确支持 03。

现场已经建立 BLE 并收到正常 Modbus 回应。因此，此次弹窗的直接原因是 身份读取地址不兼容。修改蓝牙驱动、无差别重建 GATT 或重复连接，都不能修复这个地址错误。

3.2 两端协议为什么不一致

新上位机 ReadIdentityAsync() 固定读取三段独立地址：C002/16、C012/16、C022/16。C060 则把 C002 实现为一个 96 字节整体选择器，其中依次存放 SN、硬件版本、软件版本，各 32 字节；C012、C022 不是这个窗口的合法偏移入口。

C060 正确读法：一次 03 / C002 / 48，按字节 [0..31]、[32..63]、[64..95] 拆分三段。文本按历史编码兼容处理，保留原始字节；旧协议存在 GBK 文本，不能直接全部按 ASCII 解码或按字符数限制 32 字节。BLE MAC 从所选蓝牙端点取得；MCU 不提供的蓝牙名称/改名寄存器按能力禁用。

3.3 修完身份之后仍有第二处故障

ReadBatteryAsync() 先读取 D000/63 和 D115/2，随后 无条件读取 D120/11，最后才检查扩展窗口 magic。C060 支持前两项；其 D120 只是旧实时结构尾部的切片，D120/2 恰好合法，D120/11 则越界，仍返回 03/01。

所以只对身份异常加 catch 不足以完成适配。C060 轮询必须直接使用已确认的旧格式，不再周期探测扩展实时窗口；扩展能力属于会话级结果，不能每轮重复试错。

4. 适配结构与连接顺序

建议增加轻量的 BmsDeviceProfile / C060Legacy 和 C060 参数编解码文件，复用现有传输、CRC、接收组帧、事务锁和日志。不要为本次适配引入第二套协议服务或通用插件框架。

  1. 打开用户明确选中的 BLE/串口端点，保留当前 GATT/串口实现。
  2. 只读连通性探测；明确选择 C060 时优先读其已知旧窗口。
  3. 只读取得 C002 整块身份、D000 基础数据及参数结构，确定配置。
  4. 再创建页面能力、读取首份完整实时数据与保护参数。
  5. 成功后启动轮询和后台参数采集；初始化期间不启动参数页定时器、诊断和自动重连的并发初始化。

当前身份是可写文本，c767及现场旧协议没有可靠的不可变板型能力头；工作区开发中的新版已开始加入D170能力。对于旧版本，第一版提供 明确的 C060 选择项，以只读结构校验辅助确认；不能仅凭“20 串”“BT_ 名称”或 SN 文本自动授权参数写入、升级或 MOS 操作。未知产品保持受限只读，不能自动套用 D008/D015。对于新版C060，优先校验D170的magic、schema、板型C0600020、地址和51KiB容量后选择配置；这只声明升级能力，不代表自动支持D008参数、AFE或实时扩展。

配置与可选能力缓存绑定当前客户端/端点，断开或换设备后清除。业务错误提示应包含操作、地址、数量、设备解释与应对动作，例如“C060 不支持 0xC012 身份地址”；已知不支持的可选功能显示“不支持”，真实断链/CRC/timeout 仍需记录并处理。

串口沿用 19200、8N1、站地址 1；C060 不依赖 D011 的一线通切换识别。唤醒等待与重试上限按 C060 验证，不借本次修改改变底层低功耗策略。

6.1 参数运行含义

容量保存后需保持活 SOC 百分比，不能用旧启动快照覆盖当前状态；以当前固件参数发布逻辑为准。C060当前运行SOC/日志主要保存在RAM，深睡或升级时提交快照；因此普通SOC设置或循环编辑不能笼统承诺所有运行状态断电不丢。

电流采样比例来自采样电阻与并联数。改变它会影响测量与保护；在内部版给出原值、候选值、范围和影响预览。保护电流和实时显示按现有旧缩放处理，不改变线协议。

SOC表选择保存在2308组里，但不同化学体系还涉及SOC端点、软件保护、AFE硬保护、均衡阈值和编译设置。第一版不提供未经完整映射的一键“切换三元/磷酸铁锂”。

InitShortCur()在参数发布后修改活配置中的2308～230B，再尝试写AFE寄存器；当前路径没有给上位机提供实际AFE寄存器的确认结果。因此，任意输入后按整个8字候选逐字相等校验可能报假失败；RAM参数回读也不能证明硬件写成功。

基础方案先由上位机限制为明确可编码的硬件档位，按生产算法计算规范化候选并展示回读，保存后与预计有效值比较；对不能稳定往返的组合暂不开放写。若要求“输入值=持久值=活配置=硬件实际值”的强合同，需要固件最小修正：候选先规格化/验证，再保存发布，并提供硬件读回/失败结果。保留旧地址和Flash布局，单列验证，不将其藏在UI的忽略回读差异逻辑里。

7.2 校验规则

为C060独立生成字段范围和交叉校验：编码范围、SOC 0～100、Filter有效计数、高/低方向的阈值关系、恢复滞回、总压与实际串数的合理性。优先按受支持的产品配置给出明确可写范围；历史min/max宏作为核查依据，但不能伪称当前固件逐字段强制了这些范围。

现有 ProtectionBatch.Plan() 主要校验前12组，并区分D015/其他产品；不能直接作为C060完整校验。C060的0阈值不具有D015“禁用该级”的通用语义：其扫描直接比较阈值，盲目套用0禁用可能导致持续保护。对读回的历史异常值保留显示与导出，说明具体冲突；不得自动改为默认。

7.3 一键读、一键写的确定流程

  • 一键读：一次2100/65，成功后一起更新设备值；保留正在编辑的候选值或明确提示覆盖；失败不把表格填0。
  • 单组写：先取得该组新鲜原值，合并本次修改，完整校验后10/5写入；等待ACK，再03/5回读核对。
  • 一键写：先读取当前65字，生成所有候选，整体检查，再只写实际变化组；逐组串行，展示进度和已确认结果。现有分组、变化检测和回读机制可保留。
  • 所有组都成功回读才显示“全部确认成功”。失败报告必须包含组名、地址、发送/ACK/回读阶段、异常码、已成功组数、当前组结果未知状态，并提供重新读取。
  • 13组不是跨组原子事务；中途失败可能已保存前几组。取消只停止后续事务，不能宣称回滚已经提交的Flash。连接变化立即终止，禁止向新端点续写。

主界面原有保护写入口、业务参数页、快捷循环/SOC按钮和CLI必须走同一C060方法，不能只修新页面而漏掉旧按钮。

8. 写入时序、BLE分包与Flash寿命

8.1 事务与超时

当前新客户端默认响应timeout为4秒，直接串口应答后有20ms转换间隔；它已经不同于旧上位机的一秒批量等待，不能把旧问题结论直接套来。C060参数采用候选→Flash完成→发布→ACK；主机应等待真实提交结果，不建议固件提前回ACK来掩盖等待问题。

实施时测量C060直连和BLE在最大合法负载下的ACK时间分布，区分普通读、配置写、运行命令、升级交接。可为C060配置写单独设置有界timeout；数值由实测上限加裕量确定，不能把离线模型耗时当成实板时限。

超时不等于未写入：恢复同一端点后先回读，再决定是否还有差异。不可自动重发恢复默认、深睡、升级、清除、校准提交等有副作用命令。UI、定时轮询、参数页、日志与诊断共用现有单事务串行规则，写期间暂停主动轮询。

8.3 寿命与参数包

一组变化通常仍提交一份完整参数记录，主机每增加一组无意义重复写都会增加保存开销。保留现有Flash A/B布局和掉电合同，使用“先比差异、只写变化组、同值跳过”，不要为了“批量”引入新的固件事务协议或新增参数副本。

C060参数包建议记录schema版本、产品/profile、读取时身份、源码/固件版本可用证据、UTC采集时间、各块地址/长度/原始字、工程值、缺失项、文件hash。导入先校验产品和格式，显示全部差异，再逐组执行；保护参数默认导入，校准/SN/HW/SW/采样电阻属于内部高级选项。不能默认覆盖生产身份、自动补默认值、补写未读取块或把D008/D015包强行应用C060。

备份完整性必须分项报告：常规参数完整、校准只读摘要、未提供的K/B/端点清单。当前协议不允许称为整机无损克隆。

10. 日志、诊断与校准的实际边界

10.1 事件与保护历史

C008/100是最新100条、每条2字节的事件，现有事件页读法可复用。C001/70是另一种保护历史/旧RTC编码，不能当成相同的事件表。事件20旧名为EEPROM错误，当前存储已改Flash，显示可注明“存储故障（兼容旧编号）”。

当前C060 LogTime_Map()：≤60秒编码171、>7天编码170，中间表达式存在历史运算优先级问题，多处实际成为1；时间源也不补STOP。上位机可以显示原始编码和有限解释，不能靠UI换算恢复不存在的真实时间。若用户要求准确间隔或绝对UTC日志，需另列固件版本升级和兼容方案。

10.2 诊断与工厂测试

C060没有现有2A00诊断/trace、D015运行日志、开线测试或AFE会话协议。先提供基础诊断：端点、profile、原始收发、CRC/timeout/异常统计、各块读取时间、实时/保护/参数/系统错误原字和可确认的业务解释。未知状态显示“未提供”，不推导“无故障”。

客户版保留现有高级解锁边界；内部版可以导出参数证据包与原始数据。CLI复用相同profile和capture，保持已有JSON schema兼容，新增C060能力/不支持清单，不创建第二套脚本协议。

10.3 分段电流校准为什么不能直接套用

3000/3050目前只编码10个内部source、10个内部dest，以及1字节点数（最后一个word含填充）；首尾端点和全部K/B没有完整返回。写接口却要求49字完整结构。读取结果即使长度为21，也不是可直接回写的完整配置。

基础适配先支持普通通道K/B的明确读写和分段校准只读摘要。需要完整分段校准时，新增版本化、完整只读校准块，使12点source/dest/K/B和点数可全部取得；保留现有写地址、编码和Flash布局。新生成候选必须按实际固件算法验证区间、点数、端点、B编码和插值，之后完整写入与完整回读比较。

如果还要求自动采样标定，需要可辨识的新鲜样本和内部电流精度证据；D000只有旧量化电流，不能伪装成D008 2E28的新鲜原始采样接口。相关固件只读扩展应单列合同，不能从缓存/旧值生成校准。

11. C060 升级适配单独处理

新上位机已有Telink OTA、旧串口页协议和新D015 YMODEM三条路径。它们并不自动等于支持C060。

  • 当前通用旧页入口允许55KiB，C060现分区是 APP从08001C00到0800E800（不含），0xCC00=52224字节=51KiB，51页。不能使用通用55KiB保护上限。
  • 现场装机Boot版本未知，不能仅根据当前APP文本版本认定装机已具备51页保护，更不能自动发送FFFD进入升级探测。
  • 工作区已经有新版C060 IAP阶段1：D015 format2风格的YMODEM CRC16、板型C0600020、51KiB分区、双启动记录；本轮阅读期间阶段2正在修改，已看到D170/12能力、D17C/8镜像信息及3500=B007的进入命令；这些开发中变动还需以阶段提交、构建与验收结果固定。推荐上位机最终对接这一新C060合同，而不是继续扩充未识别的旧STM32入口。
  • UpgradeDetection.ParseCapabilities() 当前只接受D015板号/地址/容量；新C060应有独立板型配置和包预检，保留公共YMODEM机制，避免复制状态机。现有.d015包的UI/类型命名和硬编码也要核对，不把改扩展名当成协议适配。
  • 新Boot还需要有效启动记录；旧00AB标志不能授权新Boot启动。首次Boot迁移和工厂烧录独立于普通在线升级；上位机先只读识别能力，再选择唯一匹配的协议，不轮流试升级命令。
  • 若保留已确认的旧C060页协议，必须另设明确Legacy profile、51页上限、包向量与目标板核验、升级后回读；禁止默认勾选“未识别旧STM32”。

待C060新APP能力、邮箱、包格式和Boot阶段完成后，固定对应提交做联合适配。参数/运行快照四页保持不变；F800/FC00在新Boot用于启动记录，与旧标志语义不同，必须按版本分别处理。本轮不生成镜像、不运行升级或烧录。
