# SOC加速擦写测试

2026-09-07。仅完整版上位机提供控制界面；本次交付测试固件、上位机及模拟验证，未对实板执行擦写压力或烧录。

## 使用

1. `python tools/build_flash_endurance.py` 生成专用固件 `Project/Users/Objects_Endurance/FD_Endurance.bin`。脚本在用户临时区创建独立Keil工程，设置 `FLASH_ENDURANCE_TEST_ENABLE=1` 和ARMCC O3，不修改用户工程选项，检查BIN不超过38912字节。正式产物及编译日志保存在 `Objects_Endurance`。
2. 仅用于稳定供电、断开充电器和负载的专用测试板。App地址固定 `0x08004800`，不能写到IAP的 `0x08000000`。如需烧录，使用现有 `tools/soc_flash_app_safe.ps1 -Bin "103 + 309/Project/Users/Objects_Endurance/FD_Endurance.bin" -Flash`；该脚本的地址校验和dry-run仍必须保留。本次未执行。
3. 完整版连接板子，打开 **Flash寿命测试**。设置提交次数（1..1000000）、模式、日常提交次数、耐久指标和已知历史擦除次数。序列号为空则拒绝开始，防止备份无法绑定设备。
4. SOC循环变化为0..100，重复为50，小幅往返为49/50。未勾选持续压力时使用当前SOC变化判断，其他保存触发字段固定；勾选后每次提交都真实保存，包括重复值。每个请求完成后再发下一笔，不等待实际充放电，也不并发堵塞串口。
5. 开始后先冻结正常SOC持久化，把原40字节快照保存到电脑，然后才提交测试数据。正常保护、采样和SOC计算继续执行，测试不改运行SOC或MOS控制。
6. **停止并恢复**在当前请求结束后恢复原快照并回读校验。失联10秒会尝试一次恢复；保存/回读失败锁定测试，拒绝继续写，保留状态供诊断。恢复失败时继续阻止正常SOC持久化，不伪报成功。
7. 中途掉电/重启会丢失RAM计数和RAM备份，不能延续原测试会话。连接后使用 **从备份恢复SOC**，选择原 `SOC备份.json`；序列号必须一致。恢复持久化快照后需重启，让运行SOC重新加载。**重启后校验备份**对比正常加载路径读出的快照，记录结果；正常运行中的SOC保存也可能造成差异，不将差异直接认定为Flash损坏。不自动复位或随机断电。

## 存储与估算

SOC原有双页为 `0x0800F000`、`0x0800F400`，每页1024字节，40字节payload加16字节header，每页18条。复用原追加、CRC、页选择、擦除、提交及加载实现，不通过直接擦指定地址假装SOC保存。测试数据带保留字标记，测试固件及本次正常固件均拒绝把带标记快照作为运行SOC加载；中断测试后仍应恢复原备份，不能把默认SOC当作原SOC恢复成功。

统计8个存储物理页的擦除尝试和校验成功次数，以及提交、保存、跳过、保存失败、回读不一致、半字编程失败。计数在RAM，本次会话开始清零；配置/日志正常活动产生的擦除也会按页记录，但SOC寿命估算只取SOC两页。压力写入结束后的恢复开销不计入压力样本估算。

默认每页耐久指标为10000次，来自 [ST STM32F103x8/xB DS5319 Rev20表29](https://www.st.com/resource/en/datasheet/stm32f103cb.pdf)：6后缀器件对应-40..85℃，10 kcycles最低耐久值。达到该指标不表示芯片一定立即损坏；加速擦写不能验证多年数据保持能力。

`每日最忙SOC页擦除 = 样本中最忙SOC页擦除 / 样本提交次数 × 设定日常提交次数`

`推算剩余年数 = max(0, 耐久指标 - 已知历史擦除 - 本次最忙页擦除) / 每日最忙页擦除 / 365`

历史填0表示未扣除未知历史，结果不能称为真实剩余寿命。未观察到擦除时显示样本不足，不给无限寿命。数据模式及持续压力选项决定提交到保存的比例，日常负荷须采用同类场景，不能直接用加速测试每秒写入次数推算日常寿命。

## 工程与协议

默认 `FlashEndurance.h/FLASH_ENDURANCE_TEST_ENABLE=0`。关闭时不编译测试控制器、测试读写地址及计数器；保留测试标记拒绝判断以兼容从工程固件退回正常固件。`FlashEndurance.inc`由 `Flash.c`条件包含，使用同一真实journal，无需修改Keil文件列表。只允许现有host-write配置开启时写命令，未更改原寄存器含义。

| 操作 | 功能/地址/数据 |
|---|---|
| 读取状态 | 0x03，0x2700，96字 |
| 开始SOC变化判断测试 | 0x06，0x2700=0xA501 |
| 开始强制保存压力测试 | 0x06，0x2700=0xA502 |
| 提交SOC测试值 | 0x06，0x2701=0..100 |
| 停止并恢复 | 0x06，0x2700=0 |
| 无活动会话时从PC恢复快照 | 0x10，0x2720，20字 |

状态字：0=0x4654、1=协议版本1、2=模式（0空闲）、3=故障（1保存失败/2回读失败）；4..15依次为提交、保存、跳过、保存失败、回读不一致、编程失败的32位计数（高字在前）；16..31为8页擦除尝试，32..47为成功次数，物理页从0x0800E000开始每次+0x400；48=快照字数20、49=当前快照有效；50..69当前快照，72..91原备份。快照按原结构每个16位字传输，32位成员低字在前，与计数区的高字在前不同。

0x06成功ACK表示该次保存及校验完成；失败返回命令异常，不自动重发。PC每500ms采集一次状态，并验证提交计数连续，防止重启/超时后的样本混入同一报告。上位机关闭、断连或异常时可能无法及时恢复，应保留备份文件。

## 测试记录

自动写入用户文档 `BmsFlashTests/时间-随机编号/`：

- `SOC备份.json`：设备序列号、时间及原始快照，第一笔测试写入之前落盘。
- `流程.log`：开始、备份、实时进度、各物理页擦除尝试/成功、错误及恢复结果。
- `数据.csv`：时间、提交/保存/跳过、错误、各页擦除计数及测试SOC，便于Excel分析。
- `结果.json`：模式、负荷、次数、计数快照、耗时、推算年数、是否恢复成功。
- `恢复校验.log`：后续从备份恢复或重启后校验结果。

## 验证

`tools/run_flash_endurance_host_test.py`使用真实Flash journal和测试控制器，模型中执行3000次变化保存、1000次重复值、500次强制保存，检查两页擦除、备份恢复、10秒超时、失败锁定、测试快照隔离和SOC区外字节不变。既有Flash/参数/CRC/串口差分和100/500日志测试通过。

Windows `test-flash-endurance.ps1`验证三种实际数据模式、32位计数、备份恢复字节序、CRC和ACK拒绝；`test-event-log.ps1`回归日志功能。两版已构建，客户版没有Flash测试页。
