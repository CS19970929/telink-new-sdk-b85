# SH3673520 软硬件保护与参数读写

日期：2026-09-07。本文说明当前源码及本次新增接口，**不表示板上已烧入此版本**。
固件资料位于 STM32 工程 `Source/afe3520`。规格书依据见该目录 `SH36735XX_规格书软件.md`；休眠细节见 `BMS休眠逻辑与MOS现场调试.md`。

## 保护运行逻辑

`Afe3520Config.h` 的 `BMS3520_CFG_PROTECTION_MODE`：1 仅软件、2 仅硬件、3 软件+硬件，默认 3。模式需重新编译。
三模式都必须保留 `Bms3520_Service200ms()`，它承担采样有效性、通信恢复、硬件配置校验、MOS 请求/反馈和最终仲裁。
不能再通过注释服务函数选择模式。正常 MOS 请求在启动阶段由 `MosStartup_ApplyInitialState()` 发出一次。

- 软件保护读取有效采样，8 项保护各有触发和恢复计数。当前规则表使用成员名定位参数，不依赖硬件阈值。
- 硬件由 AFE 比较器、延时和锁存动作；MCU 根据独立硬件恢复阈值，分别累计各锁存的安全时间，执行 LTCLR/FLAG 清除并检查通信结果。
- 模式 1 屏蔽可配置的 AFE 硬件保护使能，TS 采样保留；模式 2 不执行软件阈值保护；模式 3 任一来源都能禁止对应 MOS，恢复一方不会清除另一方的禁止。
- 充电过压/充电过流/充电温度禁止充电；欠压/放电过流/放电温度禁止放电；硬件短路、通信/配置故障、系统禁止等进入公共仲裁。
- MOS 最终由用户请求和所有有效禁止条件决定。手动关断请求不会被保护恢复覆盖。
- 默认同口 `AFE3520_CFG_COMMON_PORT=1`，因此 MOS_EN=1；分口设 0。芯片可能因反向电流强开相应 MOS，实际反馈与 MCU 请求分别保存，不能把实际反馈写回请求。
- AFE WDT 默认关闭；MCU IWDG 是另一项配置，当前开启。芯片固有内部过温保护不等同于可关闭的外部 TS 保护；软件模式还在内部温度达到 105℃时设置公共禁止。
- 当前 `__SOC_5_PROTECT_` 未开启；公共临界低压/持续故障保底休眠仍独立运行。

## 软件保护默认值

当前电池化学体系为 LiFePO4。以下是源码默认值，实际保存值应以上位机读取为准。

| 保护 | 触发值 | 触发延时 | 恢复条件 |
| --- | --- | --- | --- |
| 单体过压 | 3750 mV | 1000 ms | ≤3500 mV，稳定 1 s |
| 单体欠压 | 2500 mV | 1000 ms | ≥2800 mV，稳定 1 s |
| 充电过流一级 | 12 A | 配置 100 ms，调度实际最小 200 ms | ≤触发阈值的 80%（默认 9.6 A），稳定 1 s |
| 放电过流一级 | 15 A | 1000 ms | ≤触发阈值的 80%（默认 12 A），稳定 1 s |
| 充电高温 | 50℃ | 200 ms | ≤45℃，稳定 1 s |
| 充电低温 | 0℃ | 200 ms | ≥3℃，稳定 1 s |
| 放电高温 | 70℃ | 200 ms | ≤60℃，稳定 1 s |
| 放电低温 | -20℃ | 200 ms | ≥-10℃，稳定 1 s |

电压取有效串数的最大/最小值；软件温度取当前上报的前两个外部温度通道最大/最小值。
软件延时单位是 10 ms，执行时向上取整为 200 ms 周期；触发比较包含等于。
`0x2400` 中二级充放电过流及短路共 6 个兼容字段不参与当前软件保护，上位机只读显示，不能用它们调整硬件短路。
软件温度编码 `(℃+40)*10`，写入还受 0..1400 的实际温度域约束。

## 硬件保护默认值

分流器：2 mΩ × 8 并联，等效 0.25 mΩ。下表电流仅按此电阻换算；实际采样还涉及校准。

| 保护 | 触发参数 | 延时 | 恢复参数 |

| UV | 2650 mV | 490 ms | 有效最低单体 ≥2900 mV |
| OCD1 | 分流压差 50 mV，约 200 A | 980 ms | 充、放电报告电流均 <1 A |
| OCD2 | 分流压差 40 mV，约 160 A | 25 ms | 同上 |
| SC | 2×OCD2，约 320 A | 256 µs | 同上 |
| OCC | 分流压差 11000 µV，约 44 A | 140 ms | 同上 |
| 充电高温 | NTC 3550 Ω，约 55℃ | 芯片固定行为 | ≤50℃ |
| 放电高温 | NTC 1935 Ω，约 75℃ | 芯片固定行为 | ≤70℃ |
| 充电低温 | NTC 27513 Ω，约 0℃ | 芯片固定行为 | ≥5℃ |
| 放电低温 | NTC 116110 Ω，约 -30℃ | 芯片固定行为 | ≥-15℃ |

上述硬件恢复默认连续稳定 5000 ms；每一锁存独立累计。WDT 按通信恢复计数清除，不继承用户硬件保护稳定时间。
OV、UV、OCD、SC、OCC、TS1/2/3 默认开启，TS4 保护默认关闭。温度恢复检查仅统计启用保护的 TS 通道。
NTC 电阻在固件中转换为芯片分压编码，存在档位量化；“约多少℃”不代替规格书或实际 NTC 参数。

因此当前并非“一切配置都能上位机修改”。改编译默认值不会覆盖已保存的有效硬件档案；需要上位机写入新值。

## 版本化协议

Modbus 地址仍为 0x01；功能 0x03 读取、0x10 写入。旧 `0x2100` 和 `0x2400` 含义不变，不把 309 编码套到 3520。

- 软件区 `0x2400..0x2417`：24 字，原格式；新上位机整组写入，固件保留旧合法子区间写兼容。
- 硬件区 `0x2500..0x251F`：32 字读取，支持合法子区间读取。
- 硬件写仅接受从 `0x2500` 开始的完整 24 字（48 数据字节），状态区只读，拒绝部分写和 0x06 写。
- 字节为 Modbus 大端；32 位 NTC 电阻由低 16 位寄存器在前、高 16 位在后组成。

| 相对字偏移 | 定义 |
| --- | --- |
| 0 / 1 | 型号标识 0x3520 / schema 1 |
| 2 | bits0..9 OV/5mV；bits10..12 OV延时编码；其余0 |
| 3 | bits0..9 UV/5mV；bits10..12 UV延时编码；其余0 |
| 4 | 低字节：OCD1 延时码<<4、压差/5mV-1；高字节：OCD2 延时/25ms-1<<4、压差/10mV-1 |
| 5 | 低字节：SC倍率码<<4、SC延时码；高字节：OCC延时码<<5、压差/1375µV-1 |
| 6..13 | 四个 uint32 Ω：充高、放高、充低、放低 |
| 14 / 15 | OV恢复mV / UV恢复mV |
| 16..19 | int16 ℃：充高、放高、充低、放低恢复 |
| 20 / 21 | 过流恢复mA / 恢复稳定ms |
| 22 | bits0..7：OV/UV/OCD/SC/TS1/TS2/TS3/TS4；bit8 OCC；其余0 |
| 23 | 保留，必须0 |
| 24 | 编译模式 1/2/3，只读 |
| 25 | bit0 configValid；bit1 configDirty；值1表示当前配置已校验，只读，不等于 MOS 必然开启 |
| 26 / 27 / 28 | 同口0/1 / WDT0/1 / 硬件SPI0/1，只读 |
| 29 / 30 / 31 | 单个分流器mΩ / 并联个数 / 软件字段数24，只读 |

公共延时码 0..7：140/280/490/980/2030/3010/4970/10010 ms。
UV 延时码：490/770/980/1470/2030/3010/4970/10010 ms。
SC 倍率码：2/3/4/6；SC 延时码：0/32/64/96/128/192/224/256/288/320/384/448/480/512/544/576 µs。
OCD1 5..80 mV，步进5；OCD2 10..160 mV，步进10；OCD2延时25..400 ms，步进25；OCC1375..44000µV，步进1375。

## 保存、失败与兼容

硬件档案使用现有 `BMS_CONFIG.reserved[24]`，不改变 Flash 地址、结构大小、双槽/CRC 格式。
旧保留区为空时保留编译默认；有档案时核验型号/版本/保留位/物理范围/滞回，再在启动时恢复。
普通软件、校准、其他参数保存会携带当前硬件档案。非法请求不写 Flash；保存失败不改变运行硬件档案。

硬件保存成功后，关闭 MOS 请求输出、写 AFE 并回读。通信失败时新档案已保存，但处于 pending，禁止 MOS，后续服务重试。
所以 **0x10 ACK 只表示已保存，不能只凭 ACK 宣称已生效**。上位机比较所有24字，再检查状态字25；超时提示重新读取，不能假定“未保存”。
软件参数成功保存后只重新计软件触发/恢复时间，已有禁止状态保留到满足新参数的恢复条件，不清除硬件锁存。

软件和硬件是两个独立事务，不存在跨两组的全局原子提交；新页面分别提供两个保存按钮。

客户版与完整版共用 `Shared/Sh3673520Parameters.cs` 和 `Shared/MainWindow.Sh3673520.cs`。
客户版遵守原高级功能解锁；完整版直接显示。保存期间阻止重复编辑操作，暂停轮询，拒绝与 OTA/Factory Session 同时发起。
读取连接身份、写前重新识别、检查设备参数是否已改变、写后回读；断开重连需要重新读取。
识别为3520后，旧保护页/旧309硬件页阻止写入；未知设备超时不能被当作确认的旧设备。

BLE 保留已有整帧通信。完整参数写帧57字节，需要ATT MTU至少60且桥接模块支持透明传送该帧；不支持时用串口，不能把保护事务随意拆为多个ATT包。
MTU检查不等于桥接固件兼容性实测。当前旧OTA的STM32 App起址为0x08001C00，与本工程0x08004800不匹配；已识别3520时禁止走旧OTA，旧设备OTA路径保留。
