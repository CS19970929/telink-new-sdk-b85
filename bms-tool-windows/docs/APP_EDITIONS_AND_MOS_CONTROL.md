# Android 两版 App 与 MOS 控制

## 两个安装包

同一 Android 工程通过 `BmsAppEdition` 生成两个包，不维护第三套源码。

| 项目 | 客户版 | 测试版 |
|---|---|---|
| 构建属性 | `-p:BmsAppEdition=Customer` | 默认，或 `-p:BmsAppEdition=Internal` |
| 包名 | `com.cs.bmsbattery` | `com.cs.bmstool.android` |
| 名称 | BMS Battery | BMS Tool 测试版 |
| 主导航 | 电池 / 单体 / 记录 / 设备 | 电池 / 保护 / 日志 / 工具 |
| OTA、原始寄存器、自动测试、完整诊断 | 不提供入口和外部 BIN Intent | 保留 |
| 软件/硬件保护、SOC 与业务参数 | 设备页进入服务设置后显示 | 直接显示 |
| 充/放电 MOS 独立控制 | 保留，逐次确认 | 保留，逐次确认 |

客户版的服务设置在断开设备后自动退出。它用于把低频、高风险编辑从日常页面收起，不是账户或人员身份认证；每次参数写入仍使用原有确认、事务和读回。需要真正的售后授权时，应另行设计账号、一次性授权或设备端凭据，不能把本地模式开关当成安全边界。

## 客户版页面

- **电池**：突出 SOC、总压、电流、容量、最高温度、充/放电 MOS、保护摘要和数据更新时间。MOS 卡片分开显示用户许可、产品请求、AFE 报告与保护门禁。
- **单体**：按物理串号显示有效电芯，过滤协议哨兵 `61001`，标出最高、最低和均衡串。
- **记录**：设备事件和最近通信记录。通信日志持续写入 App 文件，暂停只暂停界面刷新。
- **设备**：扫描、手动连接、断开、身份信息，以及本次连接有效的服务设置入口。

## 测试版页面

测试版保留现有软件/硬件保护编辑、D008 参数、SOC 校正、默认恢复、健康检查、快速/完整诊断、自动测试、事件/通信日志、蓝牙名、休眠、长期监控、OTA、原始寄存器读写及外部 BIN 导入。工具页按设备操作、长期监控、OTA 和专业调试折叠，减少手机长页面滚动。

长期监控开始后每 5 秒立即追加 CSV，界面内存只保留最近 500 条；停止或界面长时间运行不会等到导出时才一次性保存全部记录。

## MOS 控制语义

共享 `BmsClient.MosControl.cs` 供 Android、Windows 客户版和 Windows 内部版使用。客户端先读取 `0x2F10..0x2F17` 的 magic/version，再只写目标通道的 `0x2F12` 或 `0x2F13`，随后重新读取并核对许可。旧固件返回非法地址时只禁用按钮。

按钮使用“禁止充电/放电 MOS”和“允许充电/放电 MOS”。“允许”只解除用户关闭许可，不强制 MOS 开启；保护、通信、采样资格、产品策略和 AFE hardware protection 继续拥有最终控制权。界面不会把实时状态位或寄存器报告描述成物理 Gate/Vgs 证据。

## 当前验证状态

2026-10-13 已用 .NET 10 Release 分别构建 `BmsAppEdition=Customer` 和 `BmsAppEdition=Internal`，两次均为 0 warning / 0 error；随后在 Xiaomi 23127PN0CC / Android 16 上安装并检查两版四个主入口、状态栏/导航栏避让、禁用态和长页面滚动，未发现启动崩溃或导航错位。截图保存在用户交付目录，不提交到源码仓库。

测试版按正式包名 `com.cs.bmstool.android` 覆盖安装。HyperOS 要求小米账号密码才能首次安装新的 `com.cs.bmsbattery` 包名；为在用户不在手机旁时完成并存检查，另生成了源码不变、仅命令行覆盖 `ApplicationId=com.telink.bms.mobile` 的手机兼容客户包，利用手机上同一开发签名的旧 Telink BMS 包位升级安装。正式客户构建仍是 `com.cs.bmsbattery`，手机兼容包不作为发布包。

本次真机检查没有连接 BMS，没有读取或写入保护参数，没有切换 MOS，没有执行休眠、烧录或 OTA；因此只证明两版 APK 能构建、安装、启动和切页，不能证明协议与实板功能。

新增的 `test-mos-control.ps1` 使用共享 `BmsTool.Core` 与受控传输替身，覆盖能力探测、单通道地址、写后读回不一致和旧固件降级；本轮未执行该脚本。
