# 统一 YMODEM 升级与串口蓝牙使用说明

> 更新日期：2026-11-06。当前 C060 已通过指定蓝牙模块完成一次真实升级。客户版、内部版、CLI 共用协议实现；本次没有修改 BMS 固件，没有重新生成固件镜像。

## 2026-11-17 C060 BIN 与 Windows BLE 实测

同一 `BT_BM56EA` / `DC:8E:95:7C:56:EA`、同一 39,936 B APP（CRC32 `4E059210`）实测：旧 20 B / 每片额外等待 15 ms 方案全程 286.0 s；120 B 有响应写入、计入 GATT 已消耗的 UART 排空时间后，分别为 68.8 s、67.1 s，均读回 APP 版本、长度和 CRC 一致。240 B 和 120 B 无响应写入未通过逐包校验，不能作为可用方案。测试中一次人为关闭电脑蓝牙导致的中断不计速度结果。

Windows BLE 仅在 YMODEM 数据发送时启用 120 B 上限，并受协商 MTU 限制；MTU23 仍最多发送20 B。按照19200/8N1计算串口排空时间并留4 ms裕量；GATT写入耗时计入该时间。普通 Modbus 写入、Telink OTA 和旧 STM32 页协议沿用原有路径。其他未显式启用该能力的传输（含 Android）保留20 B / 15 ms行为。

C060 可直接选择带 `0xC0600020` 嵌入身份的 APP BIN，上位机核对 `0x08001C00`、51 KiB边界、向量、链接长度及页对齐后，生成现有格式2的32 B包头；APP载荷保持原样。已有 `.c060` 包继续校验原CRC，不重新封装修复损坏包；Telink及其他旧BIN的加载规则保持。

现场模块实际为 Nordic UART 服务 `6e400001-...`，TX `6e400002-...`、RX Notify `6e400003-...`，支持有响应/无响应写入，MTU247；制造商 `Silicon Labs`，软件 `V0003,Dec 21 2022,14:01:04`。UUID和行为以实机为准，不套用模块手册默认值。MTU不等于模块UART缓存容量，声明无响应写入也不等于持续流传输已通过。

## 1. 新项目怎样无需更新上位机

上位机按升级合同匹配设备，不要求预先认识项目名称。采用同一套合同的新项目，可以更换板号、APP 起点和容量；设备公布的信息与所选固件包一致，即可使用同一套 YMODEM 发送与确认流程。

C060 与 D015 的名称只用于友好显示。未收录的板号会显示为十六进制编号，不阻止升级。回归中使用上位机产品表不存在的模拟板号1234ABCD、不同APP地址及128KiB镜像，已通过包与能力匹配。

新项目需要沿用下面的字段语义、包格式和指令。新的传输协议、包结构、地址区域或非Cortex-M镜像属于合同变化，届时才需要扩展上位机。业务参数页的地址和含义另由对应参数映射管理，统一升级不等于任意新参数布局都已识别。

## 2. 统一升级合同

### 2.1 固件包

包头32字节，字段小端；设备Modbus寄存器仍按大端字序传输。32字节头后为1024字节对齐的APP载荷。后缀用于方便选择，实际识别依据是内容。

| 字节偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 4 | 包标记32553044 |
| 4 / 6 | 各2 | 格式2 / 头长32 |
| 8 / 12 | 各4 | 板号 / APP地址 |
| 16 / 20 / 24 | 各4 | 载荷长度 / 版本 / 整载荷CRC32 |
| 28 | 4 | 前28字节CRC32 |

APP自身在偏移192、196、200、204处分别保存板号、APP地址、版本和实际链接长度；向量、页填充和身份必须一致。上位机检查Cortex-M SRAM地址区域和结构，Boot负责核对实际MCU SRAM、供电、Flash权限及写入结果。

目前客户端支持08000000～08FFFFFF这一Flash地址区域、1024字节对齐、最多16MiB的结构边界；每次还受设备自己声明的APP容量约束。旧STM32页协议的55KiB限制保留在旧路径，不再错误限制新包。

### 2.2 能力与升级后确认

| 接口 | 合同 |
| --- | --- |
| 03读D170/12字 | 5550标记、能力版本1、32位板号、传输协议2、包格式2、32位APP地址、32位容量、模式、保留0 |
| 模式 | 0正常APP；1允许写入的Boot；2安全关断失败；3上电进入窗口 |
| 06写3500=B007 | 请求原设备安全交接至Boot |
| 03读D17C/8字 | 32位版本、32位载荷长度、32位CRC32、有效状态1、保留0 |
| 传输 | YMODEM CRC16，128字节元数据块和1024字节数据块，EOT与空结束块 |

今后项目保持这些语义，就不需要增加板号白名单或复制一套发送器。新项目Boot与APP应公布同一分区；APP启动后提供D17C完整确认。主机命令相同，实际Flash分区和硬件操作仍由各项目固件维护。

## 3. 上位机如何保证匹配与恢复

1. 选择文件时检查包头、身份、长度及CRC；坏包清空候选，尚未发送升级指令。
2. 通过所选串口或固定蓝牙地址读取能力；核对板号、APP地址和容量。未知协议拒绝本次升级，基础通信仍可使用。
3. 模式2停止。其余模式按现有3500合同交接；应答丢失后只读重新确认，确认还是同一APP或上电窗口才有限重发，20秒内最多3次。
4. 只有确认原设备处于安全Boot后才发送固件。不切换设备、不轮流尝试其他升级命令。
5. 数据包有限重试。最终提交ACK丢失时改为重连确认，不因结果未知立即重新擦写。
6. 回到APP后核对能力、版本、长度、CRC及有效状态；这些确认通过才报告升级成功。身份字符串和实时视图属于附加读取，缺少旧BMS视图不推翻已经确认的升级结果。

早期D015没有标准D17C确认窗口，保留其D130/D13D只读确认路径。普通新项目直接使用D17C，不需要增加项目专用分支。旧D015 APP 2.x和用户明确选择的旧STM32页协议仍保留；新包不能通过旧Boot迁移，也不能仅改后缀混用。

## 4. Windows、串口与蓝牙的操作

C060、C077、D015 分别可选 .c060、.c077、.d015。沿用同一升级合同的项目也可使用 .bms 或原有后缀，由包内容和设备身份确认匹配。

Windows 先在顶部选择目标蓝牙模块，或选择 COM 口与波特率，再选匹配的升级包并点击“开始升级”。上位机直接在该端点读取 D170。APP 在线时按既有流程进入 Boot，已经处于可擦写 Boot 时直接从文件起点传输。蓝牙模块暂时停止广播或实时监控连接中断后，已选模块以“已选 · 待连接”保留，可再次点击“开始升级”连接同一模块。需要重新上电捕获 Boot 窗口时保持所选端点不变。C060、C077 的 Boot 使用直连串口或 BLE 透传。C073 的 CAN Boot 恢复能力取决于分区版本，44 KiB 设备留在 Boot 时请改用直连串口或 BLE。

蓝牙串口模块传送的是MCU的YMODEM字节流；Telink模块自身的OTA服务属于另一目标。标准BMS包会自动选择串口透传通道，避免发到模块自身OTA服务。Windows BLE YMODEM 优先按协商 MTU 和透传上限分片，最大 120 字节。启动或数据块未得到 Boot 确认时，本次升级自动切换到 20 字节分片，每片写入后等待 15 ms，并重发当前块。日志记录阶段、块号、应答与分片尺寸。

当前模块实际广播名为BT-1234567890，地址EC:F6:4C:E9:F1:3D，最终协商MTU247。当前C060的保护5字、常规8字、热冷24字组均小于这一载荷限制。参数组需要MTU≥28/60等既有边界时仍明确提示，不借用YMODEM分片去改变参数事务合同。

当前Modbus站址为1；C060串口/Boot当前为19200/8N1。BLE模块UART也应与固件匹配。使用较小MTU、其他串口波特率或不同模块时应验证模块透传、缓存和节流；本轮实板结论只覆盖指定模块。

## 5. CLI与自动化

CLI使用与Windows相同的BmsClient、包解析和YMODEM发送器。指定MAC或COM，不在多设备场景选择第一台。

```powershell
bms-cli info --mac EC:F6:4C:E9:F1:3D --json
bms-cli parameters export --mac EC:F6:4C:E9:F1:3D --output C060-parameters.json --json
bms-cli ota C060_APP.c060 --mac EC:F6:4C:E9:F1:3D --yes --json
bms-cli ota C060_APP.c060 --serial COM18 --baud 19200 --yes --json
```

C060参数命令先识别身份，再复用桌面页的C060原始块采集和JSON导出；原D008参数ZIP接口保持。OTA JSON原有字段保留，新增runtimeReadbackAvailable和upgradeReadback。仅统一升级元数据可读时，实时数据字段可空，软件版本回退显示包版本十六进制；不能把缺数据伪装成零。

目标版本输入用于额外校验软件版本字符串；未来项目未提供该字符串时，可使用确认结果里的数值版本。只要仍使用同一升级合同，项目名称无需写入CLI。

## 7. 新项目的复用步骤

- 固件复用D015/D016同类升级核心，项目自身设置板号、Flash分区和硬件实现；不要复用其他板的物理默认值。
- 生成统一格式2包，APP身份与包一致，Boot按自己的物理范围校验与写入。
- APP/Boot提供D170，APP提供D17C；保留模式和3500语义。不要只复制YMODEM收发而遗漏能力与成功确认。
- 使用本轮包/能力回归加项目生产接收器互通，再做串口和实际模块验收。首次新板号无需修改上位机产品表。
- 旧固件没有完整自描述信息时保留明确的兼容入口；不为“能连接”强制升级固件，不自动试写未知地址。

本轮需要修改的BMS固件项：无。当前C060已有完整合同。新项目需要在其固件端沿用合同；未来若改变合同，应提升版本并同步扩展主机。
