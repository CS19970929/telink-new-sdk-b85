# 新、旧 BMS 上位机功能与 C060 兼容对比

> 核对日期：2026-11-06。旧版指 BMS-upper 的 WinForms 程序；新版指已完成前三阶段 C060 适配的 Windows 客户版与内部完整版。本文是源码对比，未操作设备。

## 1. 结论

**当前 C060 的连接、实时监控、保护参数和常规参数，优先使用新版。** 新版已经针对实际协议修正身份读取、实时窗口、整组保存、校准符号编码和失败反馈，并提供自动识别及旧项目手动选择。

**新版还不是旧版所有功能的完整替代品。** 旧版的多站地址管理、串机汇总、旧Excel参数模板、逐通道两点校准操作流程、模块AT配置等，没有全部按原样迁移。新版的一些诊断、AFE编辑和校准功能属于其他固件，不能直接算成C060已支持。

**当前C060新Boot升级，两套Windows上位机都不能直接视为已经配套。** 旧版发送FFFD/FFFE/FFFF；新版虽有D015 YMODEM，但其升级识别仍固定D015板号和容量。C060当前工程已有独立新版升级工具，需要按C060合同另外接入Windows上位机。

## 4. 当前C060：新版本具体改善了什么

### 4.1 连接和实时

截图报错对应读取C012/16，而C060身份需要C002/48整体拆分。此前新版的D120/11还会越界。当前新版已针对C060使用正确窗口；D170只用于它实际声明的能力，旧固件仍可通过已有身份/结构识别，或由用户明确手动选择参数协议。

旧版直接使用原传统窗口，因此没有同一C012握手问题。但它没有统一的设备识别或能力隔离，不能由“以前能连接”推导它对新版全部行为都配套。

### 4.2 保护及批量写入

旧版一键写每步只等约1s，设备90异常应答也可能没有结束全局等待，最终出现同一句“全部参数写入异常”。此前生产函数模型已复现“正常提交尚未结束，ACK迟到而被误判超时”的机制；没有实际抓包就不能认定每次现场都只有这一种根因。

新版保护与常规参数各自先读设备当前值，合并修改、检查完整候选及长度，再按规定整组发送。保护每组5字，19字节RTU请求，MTU23可承载；容量/循环/端点每组4字，17字节请求。错误会定位到组和回读阶段，不自动重发。

| 内容 | C060规定写组 | 新版处理 |
| --- | --- | --- |
| 软件保护 | 2100+5×组号，5字 | 13组，包含SOC低和Filter验证 |
| 均衡 | 2300，8字 | fresh read保留其余字段；关闭压差标为兼容项 |
| CBC及SOC表 | 2308，8字 | 档位规格化/有效值预览；不把参数回读等同AFE确认 |
| Sleep兼容参数 | 2310，8字 | 主动勾选后才编辑，不改变当前RTC宏 |
| 容量/循环/端点 | 2318，4字 | 容量raw/10 Ah；循环快捷写也保存完整4字 |
| 系统/采样参数 | 231C，4字 | 当前20串固定；采样参数按内部边界开放 |
| 热冷 | 2320，24字 | 前5字兼容编辑，保留19字；未启用实际控制 |
| 普通通道K/B | 2000+2×通道，2字 | 47对，读补码/写符号幅值；整对预检 |

跨组保存仍可能部分成功。提交后ACK、回读一致和Flash寿命/掉电可靠性还取决于当前固件与硬件，不能因换了上位机就承诺永不超时或所有保护实板生效。

### 4.3 BLE长度与旧模板

旧工具主要走COM，不处理BLE ATT载荷限制。新版连接BLE后必须核对整组请求长度：8字需MTU≥28，16字生产信息需≥44，24字热冷需≥60。MTU不足时整个本次常规批量在预检阶段停止，保留连接与可用短组写；当前没有对未验证的模块强行启用普通长帧分片。

旧.xls的121行是固定UI模板，可能含尚未发送的编辑值。新JSON来源是读回capture；导入只载入候选，保护和常规参数仍分开确认保存。文件不互通不是单位自动换算已经完成，不能仅改后缀或照行号填入新页面。

## 5. 新版尚未完整替代的旧操作

| 旧操作 | 新版缺口 | 当前C060是否必须靠旧版补齐 |
| --- | --- | --- |
| 一次按钮写19组 | 新版保护/常规分开保存 | 不必；分开确认更易定位，按现流程操作 |
| 固定.xls模板业务流 | 缺少老模板到类型化参数包的转换 | 有大量旧模板时需单独迁移；本轮未实现转换 |
| 逐通道两点测量校准 | C060当前主要为原始K/B维护；通用新向导依赖2E00能力 | 不能直接认定旧电流校准能影响当前分段电流算法；需核对真实消费者 |
| 多站轮换、地址修改、串机汇总 | 未有等价新UI/客户端可变站址合同 | 当前C060固定地址1且缺旧汇总协议；保留旧工具也不能凭空获得固件能力 |
| 蓝牙AT及旧Wi-Fi页面 | 无同等专用新页面，旧Wi-Fi也未完成 | 属模块配置需求，分开处理 |
| 中英文标签切换 | 新版缺同等语言入口 | 中文使用不受影响，有英文交付时另补 |
| 32串全部均衡位显示 | 新版当前均衡mask只用高字低8位，IsCellBalancing限制24槽；旧版解32位 | 当前20串C060不受影响；移植25～32串产品前必须补齐 |

## 6. 两端共同受固件能力限制的功能

- 完整分段电流校准：C060现有3000/3050只返回部分点及点数，不能还原写接口所需全部K/B/端点。新版读了摘要，也不能称无损备份。
- BQ76930硬件保护：旧2400/24项和新2500/35项、0x42分别属于不同合同；C060没有直接匹配完整编辑器。CBC参数组存在，不代表已经确认实际AFE寄存器。
- SOC表、铜损、RTC写入和部分控制/清除：当前C060仍有旧空实现或只读/保留字段。两版都不能把ACK当作业务完成。
- 热冷/旧Sleep：当前无热冷运行控制，新的RTC与预充策略使用固件宏。UI可保存兼容字段，不代表策略改变。
- 事件时间：新版正确识别170与171，但C060中间时间编码及STOP时间源问题仍在；“EEPROM错误”事件旧标签也仍保留，当前实际存储为Flash。
- MOS/诊断/工厂测试：新平台已有针对其他产品的扩展，不等于C060实现2F10、2A00、0x41或0x42。可用通信应继续保留，对缺失功能逐项说明。
- 当前C060新升级：固件使用3500=B007、D170/D17C、C0600020板号、51KiB及.c060格式包；旧FFFD已明确拒绝。新版Windows升级能力解析仍只认D015。C060仓库自己的tools/c060_upgrade.py是另一入口，不等于Windows页面已完成接入。

## 7. 实际使用与迁移建议

| 场景 | 建议 |
| --- | --- |
| 当前20串C060监控、改保护、改常规参数 | 使用新版；调试优先内部完整版，客户使用客户版及既有解锁流程 |
| 同一软件兼容新旧项目 | 先自动识别，缺身份时选明确映射；新增项目补地址/组长/单位/校验，不要求旧固件为连接而统一升级 |
| 手里有历史参数.xls | 保留原模板、读取设备现值，核对单位后迁移；需要批量转换再实现有版本与列校验的转换器 |
| 校准当前C060电流 | 先明确普通K/B与分段算法消费者；需要自动采样、完整备份时先补固件接口 |
| 维护已出货多机/串机产品 | 保留旧工具作专用辅助，逐产品核对协议；不要把当前C060当成主机汇总产品 |
| 升级当前C060新固件 | 走已匹配的C060工具/交付流程；Windows升级接入另作任务 |

后续优先级：C060新升级接入 → 旧模板转换（确有历史批量文件时）→ C060校准接口与向导 → 按实际产品需求补多机、32串均衡与语言。它们不属于本次“对比”已实施内容。

## 8. 验证边界

新版cea8fcda已有客户/内部/CLI构建、C060契约、两版离屏UI和相关回归；c767传统协议生产函数模型验证了身份/实时、13组提交、常规组、负B和中文SN。该模型不代表当前新Boot或真实设备验收；详细结果在C060_IMPLEMENTATION_EVIDENCE.json。

旧版的一秒批量等待问题已有实际处理函数模型证据；不能把模型的1ms/3ms节拍、437步状态机或新客户端4s timeout当成实板性能测试。

本次只核对源码、既有文档和验证证据，生成比较文档；没有再次运行旧程序（其启动会自动开COM）、连接设备、写参数、升级、编译或烧录固件。未修改两版产品代码。
