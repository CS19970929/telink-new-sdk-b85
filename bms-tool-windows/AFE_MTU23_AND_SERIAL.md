# AFE MTU23 写入和串口唤醒探测

配套固件：D008 `d48a682f`，access protocol version 2。BLE MTU不变，原0x10完整写入和串口路径保留。客户版和内部版共享客户端/协议实现，两版参数模型和提示同步。

## 使用

1. 更新配套固件和本次EXE。连接后先读取硬件参数。
2. 修改所需参数；开启短路时设置“SCD 使能=1”，输入已确认的短路电流和延时。其他保护使能位保持原值。
3. 保存发送完整候选，自动 OPEN → 8个带token/offset/CRC的小包 → COMMIT → Requested/Effective/状态回读。不调整MTU，每包最多20字节。
4. 成功以回读/状态验证为准。失败、超时或提交应答丢失时重新读取，不能直接认为参数未改变或自动重试提交。CONFIG_INCONSISTENT仍需检查硬件应用/回滚原因。

DVC电流按板级Rsense换算10..630mV，再按10mV档位量化。启用SCD检查延时8..1999us，硬件档位7.81us。Requested和Effective可能不同；未确认的安全阈值不会由客户端补默认。HW=0固件不能通过写参数打开硬件保护。

## 串口

串口默认一线通的设备可能丢失第一帧。保持COM口打开，650ms只读探测、100ms间隔，最多24次并有20秒截止；只收到有效Modbus身份或既有兼容窗口才连接成功。支持取消，超时提示检查接线/波特率/供电。BLE仍使用原3次重建流程，其错误提示单独显示。

## 验证

- `test-afe-fragments.ps1`：真实客户端序列化/分片，重组79字节帧一致，每包≤20字节；旧版本拒绝、确认不匹配、取消均不提交；SCD零值拒绝和有效启用；模拟串口前三次无响应后连接成功且无重开。
- `test-diagnostics.ps1`：既有诊断解码、部分失败导出、旧固件、超时/取消、只读帧回归。
- `build-release.ps1 -TargetFramework net8.0-windows10.0.19041.0`：两版自包含x64发布。
