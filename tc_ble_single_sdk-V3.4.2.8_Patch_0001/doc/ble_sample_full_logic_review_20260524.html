2. 结论摘要

启动模型
普通上电进入 user_init_normal()，初始化 BLE/BMS/AFE/SOC/Runtime，再按充电唤醒或 Runtime 模式控制 MOS。
调度模型
main_loop() 每轮跑 BLE、Runtime、通信、SOC KV 和 PM；SOC 为 200ms，AFE/event 为 1s。
SOC 模型
电流积分为主，端点/OCV 修正为辅，普通修正按 1% 小步收敛；3000mV 安全端点直接同步 0%，早于 2750mV 过放保护。
存储模型
flash_kv32 是 append-only transaction KV，SOC hot KV 只存 SOC/DSG/CYCLE。老化 deep sleep 不补偿，只累计 awake runtime。
ID优先级模块结论
BUG-001P0全局数据/链接g_stCellInfoReport 在 app.c 和 modbus_rtu.c 重复定义。
BUG-002P1老化工厂模式写 0x1102=0x0003 只打开 factory MOS，没有让 Runtime 重新进入 factory 计时，也不会按 factory 禁止 RTC mode。
BUG-003P1低功耗命令写 0x1102=0x000A 设置 deepsleep_en，但 PM 判断已注释，命令无效。
BUG-004P1/P2SOC OCVOCV 表到 4180mV，但有效样本最大值是 4000mV；当前高 SOC 主要依赖满电端点同步，是否放开高压 OCV 需要实测确认。

5. AFE 与运行数据主线

g_stCellInfoReport 是核心共享运行数据。app.c:54 定义该变量，SOC、SIF、Modbus、AFE 均围绕它读写。

  • App_AFEGet() 成功时读取 SH367309 RAM，刷新电压、温度、电流、MOS 状态和 fault 状态，并清 AFE 通信错误，见 sh367309_datadeal.c:1889-1909。
  • 失败时立即清电流；连续 10 次失败后置 AFE 通信错误，并清空 AFE report 但保留 SOC/MAC，见 sh367309_datadeal.c:1911-1919。
  • 电流经 DataLoad_CurrentRawToScaled_mA() 缩放，最终写入 u16Ichg/u16IDischg，非 C11 型号约为 0.1A 单位，<=2 置 0，见 sh367309_datadeal.c:19-30 和 sh367309_datadeal.c:1372-1382。

6. SOC 模块

状态与初始化

SOC 主状态在 SOC_Calculate_Element 中，包含真实 SOC、放电累计百分比、循环次数、工厂容量、SOH 后满容量、当前容量等。g_soc_display_soc 是显示 SOC，对外上报前按 SOC_DISPLAY_STEP_TICKS 平滑跟随真实 SOC。启动时先 App_AFEGet()，再 soc_kv_store_init()、soc_kv_store_get()、soc_param_lib_init()。

默认值来自 soc_kv_store.h:28-37：SOC 为 FAC_INIT_soc，DSG 和 cycle 为 0。

电流积分

  • SOC_INTEGRAL_PERIOD_MS = 200，见 SocEnhance.c:90。
  • 充电积分只在新 SOC 大于旧 SOC 时更新，见 SocEnhance.c:375-397。
  • 放电积分在最低电压仍高于 SOC_0_VAL 时不会直接打到 0，而是先钳到 1%，见 SocEnhance.c:398-425。
  • 放电 SOC 下降会累计 cycle，满 100% 增加 1 cycle，并重算 SOH/full capacity，见 SocEnhance.c:335-360。

OCV 与端点修正

策略顺序是：启动 OCV、满电/空电端点、放电低压端点表、延迟 OCV 目标运行中消化、放电 OCV、静置 OCV 目标记录。普通自动修正通过 soc_apply_step_towards_value() 每次只移动 1%，显示 SOC 再按约 1s/1% 跟随；放电 VCELLMIN <= 3000mV 持续约 2s 是安全例外，会直接同步 real/display SOC 到 0%。

输出与持久化

SOC_Result_Pass() 将 SOC 状态同步到 g_stCellInfoReport.SocElement。当前对外 u16Soc 使用显示 SOC，u16CapacityNow 使用显示 SOC 换算；真实 SOC 仍用于积分、校准和 KV 持久化。main_loop() 每轮调用 SOC hot KV 更新，但 soc_kv_store_update_and_log_if_changed() 会先比较当前 KV，只在 SOC/DSG/CYCLE 变化时写 Flash。

SOC 修改点、可调参数、增减影响和验证场景详见 soc_user_experience_tuning_20260524.md；eBike 放电体验专项见 soc_ebike_discharge_experience_20260525.md。

runtime 2 个 sector，run/SOC KV 8 个 sector，event log 8 个 sector，见 flash_store_cfg.h:21-23。OTA 布局支持判断见 flash_store_cfg.h:44-62。

flash_kv32

  • 每个 sector 有 32B header，每次写入是 16B tx header + N 个 8B item + 4B commit。
  • 写入时最后才写 commit，见 flash_kv32.c:381-465。
  • 扫描 active sector 时只有 header、CRC、commit 都有效才加载，见 flash_kv32.c:480-575。
  • 尾部脏或空间不足时 compact 到下一个 sector，见 flash_kv32.c:605-667。
  • 值未变化不写入，见 flash_kv32.c:765-820。

SOC hot KV

soc_kv_store.c:7-20 定义 3 个 key：0x0001 SOC、0x0002 DSG、0x0003 CYCLE。soc_kv_store_factory_reset() 没有自动 init，见 soc_kv_store.c:182-185，作为公共 API 有边界风险。

cold KV 与升级 epoch

bms_cold_kv_store.c:7-12 保存 protect/system/control/btname。Param_UpgradeReset_Apply() 根据 FW_UPGRADE_RESET_*_EPOCH 执行一次性 reset，成功后写 control epoch，见 param.c:105-150。

8. 老化工厂模式

Runtime 有 MODE_FACTORY 与 MODE_NORMAL 两态，见 runtime.h:9-13。当前 FACTORY_TIME_LIMIT_MIN = 60 * 24 * 3，即 3 天，但注释仍是乱码 “7??”，见 runtime.h:6。

  • Runtime_Init() 扫描 Flash 中最新有效 runtime record；没有记录但布局支持时从 factory 0 分钟开始，见 runtime.c:373-408。
  • 布局不支持时强制进入 normal，避免不能持久化时长期停留 factory，见 runtime.c:380-388。
  • Runtime_Poll() 用 pm_get_32k_tick() 累加 runtime，见 runtime.c:415-428。
  • 每 1 分钟保存一次，达到 limit 后保存并调用 enter_fac_mode(false)，见 runtime.c:325-355。
  • 老化模式允许 deep sleep，但 deep sleep 时间不补偿进 runtime；Runtime_Init() 只从 Flash 恢复已保存分钟数，重新以当前 32k tick 作为 awake 计时起点，见 runtime.c:310-336。

enter_fac_mode(true) 只负责 MOS/AFE 行为：设置 CADCON、打开 CHGMOS/DSGMOS、写 MTP_CONF、拉高 MCC_C_PIN，见 app.c:370-385。它不是 Runtime factory state 的完整入口。

9. 低功耗逻辑

deep sleep

app_note_sleep_and_enter_deepsleep() 在 charger pad active 时拒绝进入；否则记录 sleep、可选 AFE_Sleep()、调用 Runtime_PrepareForDeepSleep()，再进入 DEEPSLEEP_MODE。如果函数返回，会调用 Runtime_CancelPendingDeepSleep()，见 app.c:138-160。

BLE suspend 与 RTC mode

后半段默认允许 SUSPEND_ADV | SUSPEND_CONN，但 charger active、总线非 OWC idle、放电、factory mode、OTA working 都会禁用 suspend 并退出 RTC mode，见 app.c:1261-1301。连接态也会退出 RTC mode，见 app.c:1302-1306。只有这些条件都不满足时才 enter_rtc_mode() 关闭 ADC 相关电源，见 app.c:739-749。

10. BLE、Modbus 与总线复用

BLE SPP 到 Modbus

module_onReceiveData() 从 ATT write packet 取 payload，调用 modbus_on_frame()，有响应时通过 notify 按 20B 分片回包，见 app_att.c:423-443。

注意：当前属性命名和方向容易混淆。手机写入入口是 TelinkSppDataServer2ClientUUID，回包 notify 用 SPP_CLIENT_TO_SERVER_DP_H，见 app_att.c:537-547。

UART Modbus 与 bus mux

  • modbus_uart_init() 配置 DMA RX buffer、PC2/PC3 UART、DMA IRQ，见 modbus_uart.c:16-46。
  • main_loop_modbus() 拉取一帧后调用 modbus_on_frame()，不管成功失败都 reset RX，见 modbus_uart.c:122-145。
  • bus_mux.c 初始 OWC idle，下降沿检测进入 UART Modbus，RX 高稳定进入 OWC TX，UART 空闲 5s 回 idle，见 bus_mux.c:56-80 和 bus_mux.c:183-219。
