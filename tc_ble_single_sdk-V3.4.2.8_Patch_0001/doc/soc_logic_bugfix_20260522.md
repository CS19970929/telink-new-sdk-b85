# SOC 计算与校准问题修复说明

更新时间：2026-05-25

## 背景

本次梳理发现 SOC 主积分单位已经是 200ms 口径，但采样异常、循环计数、容量同步、端点校准和对外容量单位仍有几个会影响准确度或用户体验的问题。本次只修 SOC 计算/校准相关逻辑，不调整保护阈值和通信框架。

2026-05-24 追加了用户体验优化：满电电压同步不再要求电流条件，real/display SOC 分离，静置 OCV 改为延迟目标，低压放电端点改为表驱动，并补充 `soc_user_experience_tuning_20260524.md` 作为参数调优文档。

2026-05-25 追加 eBike 放电体验优化：放电 OCV/延迟目标下修按 `CapacityFactory` 和 `IDSG` 自适应，不写死单一版型容量；静置只在大误差时慢速下修；`3000mV` 安全端点直接同步 0%，保证早于 `2750mV` 过放保护点；SOH 仍只按 cycle 计算，不做容量学习。

## 修复内容

1. AFE 读取失败时立即清零充/放电电流，避免 200ms SOC 任务继续用上一帧旧电流积分。
2. AFE 连续失败清空测量快照时保留 `SocElement` 和蓝牙 MAC，避免对外 SOC 短暂跳到 0。
3. 充电和放电电流统一走 64 位四舍五入换算，修复放电路径先除后乘导致的小电流截断误差，并避免极端 raw 值乘法溢出。
4. `DSG` 默认累计值改为 `0`，`cycle` 默认值改为 `0`，新板或 SOC 重置后不再提前累计首轮循环。
5. 循环次数按 100% 等效放电累计一次；每次 cycle 增加后立即重算 SOH、满容量和当前容量，保证 `SOC/SOH/CapacityFull` 同步。
6. 纯积分放电到 0% 时，如果最低单体仍高于 `SOC_0_VAL`，SOC 保持 1%，交给低端电压端点确认后再收敛到 0。
7. 满电端同步改为电压条件触发：`VCELLMAX >= SOC_100_VAL` 且 `VCELLMIN >= SOC_FULL_SYNC_MIN_MV` 持续约 60s 后，按约 2s/1% 限速拉到 100%，不要求 `isCHG()`，也不增加尾电流条件。
8. 放电低端电压收敛改为 `g_soc_dsg_terminal_rules[]` 表驱动：电压越低目标 SOC 越低，电流越大 1% 步进越慢，降低负载压降导致的提前拉低。
9. OCV 估算从单纯线性映射改为保守分段表；静置 OCV 只记录延迟目标，充/放电运行中再按方向消化，不在静置时快速跳变。
10. 对外显示改为 `display_soc` 平滑跟随真实 SOC，BLE/Modbus/SIF 上报不再直接暴露内部真实 SOC 的即时修正。
11. SIF 公共包容量字段保持原有协议口径，继续发送 `CapacityFactory` 原始值。

## 2026-05-24 用户体验追加优化

1. `real_soc/display_soc` 分离：`SOC_Calculate_Element.u8SOC_Now` 仍是真实 SOC 和 KV 持久化 SOC，`g_soc_display_soc` 用于对外上报，默认约 1s/1% 跟随。
2. 满电同步只看电压：取消 `isCHG()` 依赖，避免充电状态位异常导致满充后进不了 100%。
3. 静置 OCV 延迟目标：静置稳定后只记录目标；运行中按方向消化，长静置向下例外约 30min/1%。
4. 放电低端表驱动：`3300/3200/3150/3050/3000mV` 分别约束到 `12/6/3/1/0%`，并按电流档调节步进。
5. 放电压降 holdoff：大于约 5A 触发 holdoff，阻断非关键低压端点和放电 OCV 向下修正。
6. 修正静置长时间下调的计时口径：`SOC_LONG_REST_DOWN_STEP_TICKS` 按 200ms tick 计数，避免被 60s OCV 评估周期放大。

## 2026-05-25 eBike 放电体验追加优化

1. 放电修正节奏使用 `自然 1% 时间(s) = 36 * CapacityFactory / IDSG`，适配不同版型容量，不写死当前 C700。
2. `SOC_DSG_CORR_*` 按误差大小调节修正速度，小误差慢、大误差快，整体限制在 `10s/1% ~ 180s/1%`。
3. 静置 OCV 改为 confidence + 目标延迟：单体压差、变化率、confidence 达标才 latch target；已有 target 约 60s 刷新一次。
4. 静置下修增加 `SOC_IDLE_STATIC_DOWN_DIFF_THRESHOLD = 10%`，小误差停车不下修，大误差才按 `30min/1%` 慢修。
5. sag holdoff 改为 5~10A 约 60s、10A 以上约 90s，并加入回弹稳定判断。
6. `3050mV -> 1%` 不再被 sag holdoff 阻断；`3000mV -> 0%` 持续约 2s 后直接同步 real/display SOC 到 0。
7. SOH 逻辑保持 `bms_soh_from_cycle()`，只按循环次数计算，不按容量误差或放电修正结果学习。

## 验证

- 现有 `tests_flash_quick_check.py` 增加 SOC 静态契约检查：
  - 默认 `DSG/cycle` 从 0 开始。
  - AFE 失败清电流并保留 SOC。
  - 充/放电电流共用 64 位换算函数。
  - cycle 使用 100% 等效放电并触发容量重算。
  - SIF 容量输出使用 `SocElement` 的 `Ah*100` 口径。

## 待实测项

1. 固定 10A/20A 放电，确认 SOC 下降时间符合容量和电流换算。
2. 拔掉或干扰 AFE 通信，确认 SOC 不继续按旧电流下降，对外显示不跳 0。
3. 满充末端确认不依赖 `isCHG()`：电压满足 `4180/3980mV` 并持续约 60s 后，按约 2s/1% 逐步到 100%。
4. 高电流放电低端确认 sag hold 生效：5~10A 约 60s、10A 以上约 90s holdoff，非关键低端修正不会因瞬态压降快速掉格。
5. 静置 OCV 确认不会快速跳变：静置只记录目标；误差小于 10% 不静置下修；运行后再按方向消化；长静置大误差向下约 30min/1%。
6. 低端安全确认：放电时 `VCELLMIN <= 3000mV` 持续约 2s 后 real/display SOC 同步 0%，早于 `2750mV` 过放保护。
