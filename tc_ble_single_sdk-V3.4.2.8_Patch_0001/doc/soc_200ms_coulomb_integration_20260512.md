# SOC 200ms 安时积分优化说明

## 背景

当前主循环每 `200ms` 调用一次 `APP_SOC_IntEnhance_Ctrl()`。电流输入 `u16Ichg/u16IDischg` 的单位是 `A*10`，但旧积分路径每次 200ms 调用直接加减一次电流值，相当于把一次 200ms 调用当成 1s 处理。

同时，内部容量 `u32CapFactory/u32CapFull/u32CapNow` 需要与 `A*10` 电流单位匹配。当前 `CapacityFactory` 的配置单位是 `0.1Ah`，例如 `104` 代表 `10.4Ah`。若内部单位采用 `A*0.1s`，额定容量应为：

```text
CapacityFactory(0.1Ah) * 3600
```

## 本次修改

- SOC 积分入口不再等待连续 3 个周期进入充/放电态。
- 只要 `u16Ichg > 0` 就按充电积分，只要 `u16IDischg > 0` 就按放电积分。
- 200ms 周期积分改为：

```text
delta = current(A*10) * 200ms / 1000ms
```

- 对不能整除的积分余数做保留，后续周期继续累计，避免小电流长期丢失。
- 内部容量基准统一为 `CapacityFactory(0.1Ah)*3600`，对外 `u16Capacity*` 仍按 `Ah*100` 输出。
- 充电显示 SOC 使用容量向下取整，放电显示 SOC 使用容量向上取整，避免刚开始充/放电时因为整数边界立即跳 1%。
- 静置 OCV 只在无充电、无放电电流时参与，避免有电流时一边积分一边被静置修正。

## 体验策略

e-bike 仪表用户更关注连续、可信的电量变化。本次处理后：

- 内部容量每 200ms 都更新，响应实际电流变化。
- 显示 SOC 仍以 1% 为步进，不显示小数，避免频繁抖动。
- 充电不会因为容量小幅波动向下跳。
- 放电不会因为刚出现负载立即掉 1%。
- 低电端、满电端、放电 OCV 对比修正仍保持原有策略层约束。

## 计算校验

以 `C11_AND_C11pro` 当前 `CapacityFactory = 104` 为例，该配置代表 `10.4Ah`：

```text
满容量 = 104 * 3600 = 374400
1% 容量 = 3744
20A 电流 = 200(A*10)
200ms 积分 delta = 200 * 200 / 1000 = 40
1% 所需时间 = 3744 / 40 * 0.2s = 18.72s
```

这与 `10.4Ah` 电池在 `20A` 下每 `1%` 约 `18.72s` 的理论值一致。

## 验证建议

1. 固定 20A 放电，确认 SOC 每 1% 变化时间接近 `18.72s`。
2. 固定 10A 充电，确认 SOC 每 1% 变化时间接近 `37.44s`。
3. 充放电方向快速切换，确认 SOC 不因为方向切换立即反向跳变。
4. 小电流持续运行，确认积分余数累计后仍能推动 SOC 变化。
5. 满充、低电和静置场景继续确认端点同步与 OCV 修正符合预期。
