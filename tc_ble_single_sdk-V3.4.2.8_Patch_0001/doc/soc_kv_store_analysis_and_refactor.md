# soc_kv_store 分析与整体优化方案

## 1. 背景

`soc_kv_store` 当前承担以下 3 个运行时参数的持久化：

- `soc`
- `dsg`
- `cycle`

模块位于：

- `tc_ble_single_sdk/vendor/ble_sample/soc_kv_store.c`
- `tc_ble_single_sdk/vendor/ble_sample/soc_kv_store.h`

上层主要调用路径：

- `tc_ble_single_sdk/vendor/ble_sample/app.c`
- `tc_ble_single_sdk/vendor/ble_sample/SocEnhance.c`

## 2. 当前实现存在的问题

### 2.1 恢复模型存在“默认值拼接”问题

当前实现扫描扇区时，先用默认值初始化 `soc/dsg/cycle`，随后按日志条目逐项覆盖。

但模块平时又采用“哪个字段变化就只写哪个字段”的增量记录模式。

这会导致一个问题：

- 如果 Flash 中只存在部分字段的有效记录
- 那么重启恢复时，未写过的字段会被默认值补齐
- 最终得到的并不是历史上真实存在过的一组参数

这类错误不依赖异常掉电，只要出现“只记录了部分字段”的持久化状态就可能触发。

### 2.2 双扇区切换缺少确定的新旧判定依据

当前 A/B 扇区的选择逻辑主要依赖“哪个扇区写得更靠后”。

这个规则并不等价于“哪个扇区更新”。

在以下窗口会出现回退风险：

1. 新扇区已写入新快照
2. 活动扇区已切换
3. 旧扇区尚未来得及擦除
4. 此时掉电

下次启动时，如果仍按写入偏移大小判断，有机会重新选回旧扇区，从而回退到旧数据。

### 2.3 脏尾记录后继续原地续写不可靠

当前扫描遇到非法记录时会停止，并将写指针停在该位置。

但 NOR Flash 只能从 `1 -> 0` 编程，不能对一个已被部分写坏的记录位置直接“补写成新记录”。

因此：

- 一旦尾部记录因掉电等原因写坏
- 后续若继续在同一偏移原地追加
- 写入结果并不可靠

### 2.4 默认值定义不一致

当前模块内部至少存在 3 套默认值来源：

- 扫描默认值
- 空仓初始化默认值
- 出厂清空后的内存默认值

这会导致：

- 首次启动行为不一致
- 恢复行为不一致
- 上层难以建立稳定预期

### 2.5 `cycle` 的业务语义与存储边界需要明确

`SocEnhance` 中的 `u32Cycle_times` 实际语义是“循环次数乘以 100”。

因此默认值不应简单视作 `1`，而应与上层原始逻辑保持一致。

否则即使模块本身能正常读写，也会在首启或清空后改变 SOH 计算行为。

## 3. 优化目标

本次整体优化目标如下：

1. 恢复结果必须对应一条真实写入过的完整参数快照
2. 扇区切换后，掉电重启时必须能稳定判定新旧
3. 尾部出现脏记录后，禁止继续原地续写
4. 默认值定义唯一化，并与 `SocEnhance` 语义对齐
5. 对外接口尽量保持兼容，减少上层改动

## 4. 优化方案

### 4.1 记录模型改为“完整快照日志”

不再存储“单字段增量记录”，改为每次持久化都写入一条完整快照，单条记录同时包含：

- `soc`
- `dsg`
- `cycle`
- 单调递增序号
- 校验字段

这样恢复时只需取“最后一条有效快照”，不会再出现默认值拼接问题。

### 4.2 使用序号判定 A/B 扇区新旧

每条快照记录携带 `seq`。

初始化时：

- 分别扫描 A/B 两个扇区
- 找到各自最后一条有效快照
- 以 `seq` 更大的扇区作为当前活动扇区

这样即使掉电发生在双扇区切换窗口，也能基于序号稳定选中最新数据。

### 4.3 遇到非法尾记录后直接触发切换

扫描若发现：

- 记录不是擦除态
- 但校验失败

则说明该扇区尾部已脏。

此时仍允许使用该扇区中“最后一条有效快照”恢复数据，但后续不得继续在当前扇区追加，必须切换到另一扇区。

### 4.4 统一默认值

默认值统一收敛为宏定义，并与 `SocEnhance` 当前业务语义对齐：

- `soc = 60`
- `dsg = 0`
- `cycle = 100`

其中 `cycle = 100` 表示“1.00 个循环”的内部计数格式，与现有 `SocEnhance` 初始化语义一致。

### 4.5 保持现有对外接口

以下接口保持不变：

- `soc_kv_store_init`
- `soc_kv_store_get`
- `soc_kv_store_put`
- `soc_kv_store_update_and_log_if_changed`
- `soc_kv_store_factory_reset`
- `soc_kv_store_get_dbg`

其中内部行为改为：

- `put` 更新缓存后写入一条完整快照
- `update_and_log_if_changed` 在任一字段变化时只写 1 条完整快照

这样既修复一致性问题，也避免同一轮更新写多条记录。

## 5. 预期收益

优化完成后，模块将具备以下性质：

- 恢复结果对应真实历史快照
- 双扇区切换具备确定性
- 对掉电导致的尾部脏数据更稳健
- 默认值行为统一
- 上层调用方式基本不变
