# SOC 200ms 安时积分移植说明

更新时间：2026-05-15

## 背景

当前分支为 `codex-kv32-flash`，版型配置为：

```c
#define FD_BMS_TYPE     T1_AND_T2
#define SeriesNum       (13)
#define CapacityFactory (225)
```

`CapacityFactory` 的单位为 `0.1Ah`，因此 `225` 代表 `22.5Ah`。当前分支原有 SOC 积分虽然由主循环每 `200ms` 调用一次，但旧实现需要进入充/放电状态延时，并且积分时直接使用一次电流值，相当于把一次 `200ms` 调用按 `1s` 计算。

本次按 `new-dev` 分支的 SOC 200ms 积分思路移植到当前分支，只处理 SOC 积分相关逻辑，不合入 `new-dev` 后续 AFE 电流零点校准和 pre-push hook 改动。

## 本次实现

- `SOC_VIRTUAL_CURRENT_CHG/DSG` 改为 `0`，只要 `u16Ichg/u16IDischg` 大于 0 就进入对应积分。
- `APP_SOC_IntEnhance_Ctrl()` 直接按当前电流方向调用充电或放电积分，不再依赖 3 个周期状态延时。
- 200ms 积分公式：

```text
delta = current(A*10) * 200ms / 1000ms
```

- 对不能整除的 200ms 积分余数进行保留，后续周期继续累计，避免小电流长期被截断。
- 充电按容量向下取整更新 SOC，放电按容量向上取整更新 SOC，减少刚进入充放电时的边界跳变。
- 充放电方向切换或静置时清理积分余数和方向状态，避免上一方向的残量污染下一方向。
- 保留当前分支原有低电端保护：放电积分算到 0% 时，如果最低单体电压仍高于 `SOC_0_VAL`，SOC 维持在 1%。

## 单位关系

内部容量仍沿用当前分支约定：

```text
u32CapFactory = CapacityFactory(0.1Ah) * 3600
u32CapFull    = u32CapFactory * SOH / 100
u16Capacity*  = 内部容量 / 360   // 对外 Ah*100
```

以当前 T1/T2 `CapacityFactory=225`、`SOH=100%` 为例：

```text
满容量 = 225 * 3600 = 810000
1% 容量 = 8100
对外满容量 = 810000 / 360 = 2250 = 22.50Ah
```

## 计算校验

20A 放电时：

```text
电流输入 = 200(A*10)
200ms delta = 200 * 200 / 1000 = 40
1% 所需时间 = 8100 / 40 * 0.2s = 40.5s
```

10A 充电时：

```text
电流输入 = 100(A*10)
200ms delta = 100 * 200 / 1000 = 20
1% 所需时间 = 8100 / 20 * 0.2s = 81s
```

## 验证建议

1. 固定 20A 放电，确认 SOC 每下降 1% 约 `40.5s`。
2. 固定 10A 充电，确认 SOC 每上升 1% 约 `81s`。
3. 充放电快速切换，确认积分余数被清理，SOC 不出现反向突跳。
4. 小电流持续运行，确认余数累计后仍能推动容量和 SOC 变化。
5. 低电端放电到 1% 附近，确认电压高于 `SOC_0_VAL` 时不会被纯积分提前拉到 0%。
