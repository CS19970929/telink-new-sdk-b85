# SOC 电压电流融合策略说明

## 背景

`C11放.csv` 是 2026-04-29 的 10A 放电记录。旧代码显示放电电流约 `12.4A ~ 12.6A`，与实际 10A 相比约有 `1.2x` 以上误差。放电电流按比例修正后，容量积分会比旧代码更慢下降，但低端电压已经进入快速塌陷区时，SOC 仍需要向端点收敛。

本次策略不修改 `CapacityFactory`。容量仍由版型参数定义，SOC 优化只在运行策略层处理。

## 数据结论

- 主放电段：`2026-04-29 14:42:37` 到 `15:44:16`
- 旧显示放电电流均值：约 `12.537A`
- 按 `/1.2` 修正后电流均值：约 `10.447A`
- 旧 SOC 首次到 `0%`：最低单体约 `3189mV`
- 继续放电到最低单体约 `2999mV`：修正后累计约 `10.62Ah`
- 主放电停止时最低单体约 `2812mV`：修正后累计约 `10.73Ah`

因此，单纯依赖电流积分会受电流校准、负载倍率和端点电压塌陷影响；单纯依赖电压又会受负载压降影响。需要融合策略。

## 策略原则

1. 电流积分仍是 SOC 主路径。
2. 充电接近满电端时，使用电流状态和最高单体电压共同确认，只做限速上调。
3. 放电接近低压端时，使用放电状态和最低单体电压共同确认，只做限速下调。
4. 未充电时不允许自动向上校准；空闲 OCV 只允许向下慢校准，避免静置后 SOC 被抬高。
5. 运行期 SOC 修正统一使用 `1%` 步进，不把 SOC 从高值直接拉到目标值。
6. 放电低端未真正到 `SOC_0_VAL` 前，不允许 SOC 继续跌到 `0%`，最低保持 `1%`；这属于下行钳制，不做 0% 后的反向抬升。

## 当前实现

代码位置：`tc_ble_single_sdk/vendor/ble_sample/SocEnhance.c`

开机 OCV 校准代码暂时保留但默认关闭，开关为 `SOC_STARTUP_OCV_CORRECTION_ENABLE`。当前值为 `0`，因此开机阶段不会自动校准 SOC；后续确认策略后可只改该宏恢复。

新增通用低端收敛阈值均基于 `SOC_0_VAL`：

| 条件 | 放电 SOC 上限 |
| --- | --- |
| `VCELLMIN <= SOC_0_VAL` | `0%`，但需连续确认后限速下降 |
| `VCELLMIN <= SOC_0_VAL + 50mV` | `1%` |
| `VCELLMIN <= SOC_0_VAL + 150mV` | `3%` |
| `VCELLMIN <= SOC_0_VAL + 200mV` | `6%` |
| `VCELLMIN <= SOC_0_VAL + 300mV` | `12%` |

这些阈值不是容量修正，而是低端用户体验和端点收敛策略：电压未进入低端区间时不干预容量积分；进入低端区间后，只限制 SOC 不能明显高于电压端点状态。

## 后续验证建议

1. 用同一版固件跑 10A 完整放电，确认 SOC 不再提前到 `0%`，也不会在低压保护前仍显示较高百分比。
2. 补 5A、15A 放电记录，检查低端阈值是否仍能平滑收敛。
3. 做一次满充到静置，确认满电端限速上调不会产生明显跳变。
4. 做一次放电后静置，确认空闲 OCV 只会缓慢向下校准，不会在未充电时抬高 SOC。
