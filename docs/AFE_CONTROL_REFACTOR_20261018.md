## 第一轮：失效轮次不重放旧远程关闭意图

guard 仲裁增加仅在本次调用有效的 `explicit_off_mask`，不增加跨轮缓存。
没有有效测量或本轮已有事务失败时，保留已开启的反向放行，不重新计算旧远程 OFF；
新用户关闭、产品撤销、参数/输出禁止和后端已确认保护仍可关闭指定方向。
完整有效轮次仍按最新方向重新执行远程关闭许可，协议响应时机不变。

补充 guard 的 CHG/DSG 对称场景：反向临时放行、读失败保持、新用户关闭另一侧、
完整读取后按最新方向重新仲裁。更新抽取签名与既有源码契约，不删除安全断言。
未改变通信 1000 ms 确认、watchdog 静默、配置门禁或产品参数。

## 第二轮：先标记失败，再补偿许可开启

第一轮提交 `e34c6eff`。首次许可开启事务失败后先通知通信观察，再恢复原许可；
补偿只撤销本次尝试开启的方向，不能再次进入正常 FET 开启仲裁。
若已达到静默条件，补偿遵守总线门禁。保持原同步失败响应和关闭意图。
新增首次控制失败、随后补偿成功的场景，核对正常 set 调用次数、原许可及下一完整轮次恢复。

## 第三轮：DVC 恢复事务失败参加本轮结算

传递已尝试事务的失败；只置位，不清除此前观察。证据不足不置位。
采样仍完成软件保护、硬件故障合并和历史边沿，然后以 READ_ERROR 交给 guard。
完整测量仍有效，控制失败不伪造零测量；guard 只允许必要关闭，持续失败按原 1000 ms 确认。
更新真实恢复函数的写失败、回读失败和无证据场景，保留锁存及 HW=0/1 边界，未执行。

## 第八轮：SH CADC 配置归 control 所有

第七轮提交 `023b486e`。唯一生产 Init 调用来自 control_init。
底层 Init 只负责端口、Reset、Probe 和传输就绪，不再先读改写 SCONF5 的 CADC 位。
control 的静态 SCONF5 完整写入/回读及独立 OCC 使能仍保留，全部配置和保护成功前不发布业务成功。
软件为单一主循环，初始化内未对外调度；任一配置失败清 control_ready，FET 保持禁止。

## 第九轮：均衡实际值在本轮同步调用中共享

第八轮提交 `ae2d26ee`。公共功能决策前先读一次均衡实际值，发布后再选串；

没有跨轮寄存器缓存、额外状态镜像或验证降频；写入仍保留最终回读和原续期时间。

### 条件项裁决

| 建议 | 最终处理与理由 |
|---|---|
| 删除 DVC 采样中的均衡读取 | 已迁移到功能决策前并同轮共享，保留实际状态消费者及通信失败观察 |
| 稳定均衡/LOAD/C+ 模式跨轮降频验证 | 保留每轮必要读取；降频会延迟发现芯片变化或总线故障，缺少批准的发现时限及实板依据 |
| 把所有无变化寄存器操作都改为一次读 | 只处理 SCONF3 配置未变化路径；LTCLR 自清及具体锁存清除不适用普通配置比较 |
| 删除所有 FET/保护状态或统一成一个状态机 | 只删除已证明无消费者的授权副本；请求、命令缓存、实际回读、保护锁存及物理恢复是不同事实 |
| 把 SH 短路恢复三阶段与九组恢复计数合并 | 保留 LOAD/C+ 互斥、模式建立等待及 VADC/CADC 分组证据；合并会隐藏硬件条件，未增加 Manager/FSM 层 |
| 所有开启请求只排队到下一轮 | 保留现有同步响应和许可回滚；本轮失败只走关闭，不擅自改变正常 Modbus 成功时机 |
| 合并通信禁止、配置禁止和故障锁存 | 保留独立所有者；通信恢复不能证明部分写入配置一致，也不能替代真实保护恢复 |
| 以代码精简推定资源收益 | 仅记录可见事务和职责变化；没有新 ELF/MAP，不给出 Flash/SRAM 节省值 |
