## 2. 分析目的与边界

本报告评估本次新增的 MCU 自检、Fail Safe、Flash 完整性、诊断接口和应用门控代码，确认其能够编译、链接并具备可追踪的安全行为。参考 IEC 60335-1 / IEC 60730-1 Class B 的软件诊断思路，但不声称本软件已经获得或自动满足认证。

已执行范围：

- TC32 GCC `-Wall -O2` 编译和链接检查。
- ELF/MAP/NM/LST 符号、段、地址和链接保留检查。
- CRC、Manifest、镜像损坏、控制流、正反码、双扇区选择和配置约束自动测试。
- 安全输出开启路径、只读诊断窗口和生产故障注入默认值的源码结构检查。
- 新增 C/TC32 汇编的人工逻辑审阅。

未执行范围：

- Cppcheck、PC-lint、LDRA、Polyspace 或经项目批准的 MISRA C 工具。
- MC/DC、目标机代码覆盖率、栈动态最坏值、WCET 和正式方法证明。
- MCU/AFe FMEDA、原理图级独立保护评估及认证机构独立评审。
- 实物板 MOS、均衡、ADC、AFE、看门狗、OTA、低功耗和复位测试。

### 5.2 告警分析

最终构建记录 81 个既有工程 warning，主要类别为 `#pragma pack` 与 `-fpack-struct` 重复、未使用变量、逗号表达式、隐式声明及既有非 void 函数返回路径。`vendor/ble_sample/bms_selftest` 新增目录 warning 为 0、error 为 0。

本报告不把历史 warning 判定为可接受偏差。项目必须为每个历史 warning 建立责任人、影响分析和关闭记录；本次提交只确认没有在新增安全模块中引入编译器告警。

## 7. 自动化分析结果

1. CRC-32 标准向量 `123456789 = 0xCBF43926`。
2. 最终 Manifest、镜像 CRC 和 Telink 尾部 CRC。
3. 单比特 BIN 损坏可被检测。
4. Manifest 范围和 Flash 应用槽边界。
5. MAP 布局和必需符号存在。
6. 控制流算法与 TC32 汇编链接。
7. 关键变量正反码算法。
8. 参数双扇区有效性/代际选择模型。
9. 故障码连续性和 Fail Safe 输出门控。
10. 生产构建故障注入编译保护。

## 9. 结论

在分析提交 `50c264f` 和列明工具环境下，新增安全自检模块完成 clean build、链接布局、双 CRC、反汇编符号和 11 项主机自动检查，新增模块无编译 warning。代码已经形成“上电安全输出—启动自检—运行分时检查—心跳喂狗—故障锁存安全态—只读诊断”的闭环。

本报告的工程级结论为：**软件实现和可自动化证据已具备进入目标板验证与独立静态分析的条件**。由于 MISRA 工具、目标板故障注入、独立时钟、硬件极性及认证机构评审尚未完成，最终认证/合规结论为：**待验证，不得宣称通过 IEC 60335 或 IEC 60730 认证**。
