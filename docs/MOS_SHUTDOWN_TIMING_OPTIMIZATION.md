# MOS 关断时序优化

2026-10-12；修改基线 `f4e11801ef49c25bcadc6bbe8677d601fbbf14aa`，分支
`codex-remove-openwire`。本轮处理 MOS 监控发现的错误温度资格判断和无必要 AFE 读取，
不把上位机显示“正常”作为允许输出的唯一依据。源码实施与实板验收分别记录。

## 已实施的修改

### 有效 AFE 配置按请求回读一次

`modbus_rtu.c::modbus_read_holding()` 对 `0x2540..0x2562` 先校验整个范围，
然后只调用一次 `bms_afe_hw_profile_get_effective()`，从请求内局部 profile 编码应答。
没有全局缓存、跨请求有效期或新包装层。新请求仍重新回读 AFE。

原实现每个 word 都重新读取整份 profile；查询 35 words 会调用 getter 35 次。
D008 每份成功 profile 至少进行 12 次语义配置读取，启用 SC 时为 14 次；
本轮从 420/490 次降为 12/14 次，实际总线重试和耗时须另测。
SH 同一请求的整份 effective getter 也由 35 次降为一次。

地址、缩放、word 顺序、大端编码与 CRC 保持原样。失败时整个请求范围返回原有未知值
`0xFFFF`，不再将多次回读的成功字段和失败字段混合。非法跨窗口请求不访问 AFE。
请求配置及元数据路径保持原读取语义，授权写入、验证与 rollback 事务保持原样。
局部 profile 为 70 B 自动变量；没有资源或目标栈水位结果，不能据此宣称 RAM 减少。

### D008 先确认本轮新转换，再判断温度资格

`DVC1124_App_AFEGet()` 原来在读取本轮 ADC 前，因旧电压时间戳超过 512 ms
清空所有 NTC 资格。即使随后取得正常新 VADF，探头也回到 1/3 的恢复阶段，
公共保护因必需温度无效关闭双 MOS。这是源码中确认的错误判断链。

本轮在整组读取成功、取得 VADF 后再处理旧缓存年龄：

| 本轮条件 | 处理 |
|---|---|
| 已合格通道、晚轮询但有正常新 VADF | 接受本轮有效原始值，保留资格，不制造 TEMP_BREAK |
| 新 VADF 的 GP/V1P8 换算失败或电阻越界 | 当轮撤销对应通道资格；必需探头仍阻断输出 |
| 超过 512 ms 且无新 VADF | 撤销 NTC 资格；过期快照仍无效，由既有 guard 处理 |
| 通道尚处恢复阶段，间隔超过 512 ms | 原恢复计数清零，本次好转换只计一次 |
| AFE 读取失败或 reset | 保留清除资格及既有通信恢复要求 |

冷启动和真实探头故障恢复仍要求三次有效新转换。未增加时间阈值，也没有在正常
晚轮询后人为清除已锁存的真实温度保护；公共保护继续按本轮输入和原恢复条件处理。
200 ms 应用调度、512 ms ADC 活性上限、公共 guard 三次新样本与 watchdog 静默保持原样。

### SH 不读取没有消费者的 C+

已核对当前 C+ 的使用者是 OCC 物理恢复和 D011 加热启动。
D013/D014 未支持 heater，只有当前 AFE OCC 标志或已锁存 Third `charge_ocp`
存在时才读取 C+；不需要时返回未知充电器状态，不伪造拔除证据。
软件 OCC 在本轮保护计算首次触发后，最早下一轮取得 C+，只可能推迟恢复。
D011 加热证据路径保持原样。

SCONF3 模式读回、负载/C+ 互斥、切换后 200 ms 等待、迟滞和原始值检查全部保留。
真正需要的 C+ 读取失败仍使采样失效并进入原 fail-safe；没有吞掉 SPI 错误。
SC/OCD/OCC 不能仅凭关 MOS 后的零电流恢复，清标志失败仍锁定失效。
此处是移除已确认无使用者的读取关联，未发现日志证明 SH 设备曾因它误关 MOS。
