# 实时休眠原因与倒计时

适用四产品固件 `codex-bms-monorepo` 和 Windows 上位机维护分支
`feature/windows-afe-hw-protection-editor-v2`。新增只读观察窗口，电源策略仍由
`bms/app/app_power.c` 持有；诊断读取不推进计时、不访问 AFE、不写 Flash。

## 显示内容与边界

客户版和内部版的“实时监控 → 系统监控信息”显示深睡/关机状态、触发原因、
已累计时间、设定延时、距计时到期的时间、阻止原因、失败重试等待及普通 suspend
策略是否许可。跟随原一秒自动刷新；PC 不自行递减倒计时。BMS 诊断的“低功耗”页
及导出包也包含该快照。

低压/AFE 异常到期即提交强制深睡，不受通信、OTA、保存或 AFE 失败阻止；普通 ACC/命令/开关入口仍有门禁与失败退避。执行规则见 [保护性深睡](LOW_POWER_POLICY.md)。
`COMMITTED` 表示前置动作完成、即将调用 SDK 深睡或切断 MCU 电源，不证明芯片
实际睡眠或 Gate 状态。断连、通信失败、超过五秒未更新均显示未知或过期，不能
把通信中断解释成已经休眠。真正深睡/掉电后无法实时读取；ACC 的 200 ms 窗口
也可能短于上位机刷新周期。

旧固件根据原 Diagnostics magic/schema/新增 capability 判定不支持，不显示虚构的零秒。
新快照只增加 RAM 观察数据，不改变 Config/State/Event、OTA 参数编号或已有寄存器含义。

## 当前策略如何映射

| 产品/入口 | 倒计时和门禁 |
|---|---|
| 四产品低压/AFE 异常 | 使用产品阈值和延时；两类计时独立；展示最早到期的一条，阻止位与退避为零，到期强制深睡 |
| D008 命令关机 | 无额外计时；等待 OTA、Flash、总线和 BLE 应答，失败五秒重试 |
| D008 ACC | 高电平连续 200 ms；BLE 断开、保存及 AFE shutdown 成功后深睡 |
| SH 开关 | 开关策略启用时关闭及对应 INT 条件累计三秒；保留普通门禁与三秒退避 |

普通 suspend 是否许可独立展示，不代表可以阻止保护性深睡。
AFE 和实板边界见 [AFE资料指南](AFE_REFERENCE_GUIDE.md) 与 [保护性深睡](LOW_POWER_POLICY.md)。

2026-10-09 普通 suspend 门禁：四产品均以有效、有符号 mA 判断充/放电，
电流绝对值达到已有可靠电流边界 200 mA 即禁止；D008 原 500 mA 门限已收紧，
SH 不再只看截断后的放电电流。测量无效/过期、采样任务到期、Flash 未恢复锁定时也禁止。
SH 固定 UART 禁睡开关保持为 1；未开放原本受阻的低功耗入口。

小于 200 mA 的区间沿用原测量可靠性限制，不能据此断言物理充放电为零；
允许普通 suspend 时仍依赖已有 200 ms 定时唤醒、主循环采样和 AFE 正常工作模式。
D008 正常产品配置的 `BMS_APP_SAMPLE_WAKEUP_ENABLE=1` 必须保留；关闭定时唤醒的
功耗实验不能作为本策略的正常运行配置。普通 suspend 不执行 AFE sleep，也不清 SOC 容量。
此次只修普通 suspend 门禁，尚未修正 SOC 正常转换等待被判 GAP 的问题；
未执行编译、host 回归、OTA 或实际 suspend 唤醒时序验证，不能称已保证实板保护/积分时序。

## 只读协议 schema 1

Modbus 03，`0x3300..0x3313`，一次读取20 words（45字节RTU响应）。
每个word为大端，u32沿用旧Diagnostics的**低word在前**，与运行日志u32顺序不同。
Diagnostics `0x2A02` 的 bit6（`0x0040`）表示支持。06/10写入以及跨边界访问拒绝。

| word偏移 | 内容 |
|---|---|
| 0 / 1 | magic `0x534C` / schema `1` |
| 2 / 3 | 状态 / 原因 |
| 4 / 5 | bit0普通suspend策略许可 / 保留零 |
| 6..7 | 深睡/关机阻止位图 |
| 8..9 | 已累计毫秒 |
| 10..11 | 设定延时毫秒 |
| 12..13 | 距计时到期毫秒，饱和至零 |
| 14..15 | 失败重试剩余毫秒 |
| 16..17 | 发布时32K tick |
| 18..19 | 读取时32K tick |

状态：0尚未发布，1无请求，2计时，3被阻止，4到期待执行，5重试等待，6已提交动作。
原因：0无，1命令，2ACC，3开关，4极低单体电压，5低压，6低压且无充电，7AFE异常。

阻止位bit0..10依次为OTA、Flash未锁、总线忙、BLE等待、固定UART门禁、UART发送、
PAD有效、采样无效/过期、保存失败、AFE入睡/关断失败、BLE广播控制失败。
普通入口失败位记录最后失败，下一次实际尝试或原因变化时清除；保护性原因不沿用这些失败位。
五秒新鲜度判断使用无符号32位tick差，处理自然回绕。
