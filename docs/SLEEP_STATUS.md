# 实时休眠原因与倒计时

适用 D008 / D011 / D013 / D014，固件分支 `codex-bms-deep-simplification-20261016`，
Windows 上位机维护分支 `feature/windows-afe-hw-protection-editor-v2`。
2026-10-19 起，该功能是开发版、生产版均常驻的只读协议，不再受服务诊断开关控制。
电源策略与实际计时仍由 `bms/app/app_power.c` 持有；读取不推进计时、不访问 AFE、不写 Flash。

## 常驻接口与兼容

- `bms/core/bms_sleep_status.c/.h` 独立维护 36 字节 RAM 快照。PM 主循环发布原因、
  原有计数和最终策略许可；读协议只编码快照并读取一次当前 32K 时间。
- 无需启用 `BMS_SERVICE_DIAG_ENABLE`、trace、运行日志、栈扫描或 AFE 寄存器调试。
  其他诊断的默认关闭和生产构建禁用规则保持。
- `modbus_rtu.c` 直接处理 `0x3300` 的 03 读取，06/10 及跨入该窗口的写入始终拒绝。
  状态与倒计时不进入 Config/State/Event，不增加 Flash 字段，不改 OTA 参数组或一次性标识。
- `0x2A02` 的旧能力位 `0x0040` 始终声明支持，保留给已有 Windows 客户端发现接口。
  服务诊断关闭时，此头仍是原 magic/schema，其 capability 仅有休眠位，其他诊断位为零。
- 地址、schema、原因/状态/阻止位编码、u32 字序均不变，已有 Windows 客户版和内部版
  的实时显示不需要更新 EXE。固件更新后断开再连接，重新创建客户端以刷新能力缓存。
  旧固件不支持时仍显示不支持；不能靠上位机本地推算假倒计时。

## 显示内容与边界

客户版和内部版的“实时监控 → 系统监控信息”显示深睡/关机状态、触发原因、
已累计时间、设定延时、距计时到期的时间、阻止原因、失败重试等待及普通 suspend
策略是否许可。跟随原一秒自动刷新；PC 不自行递减倒计时。BMS 诊断的“低功耗”页
及导出包也包含该快照。

低压/过放/AFE 异常到期即提交保护性休眠：D008 拉低 PC4 关闭 MCU 供电，SH MCU 深睡；不受通信、OTA、保存或 AFE 失败阻止。四产品命令复用强制入口，应答空闲即执行，等待最长 500 ms；D008 ACC与SH开关均直接锁存深睡，无业务门禁与失败退避。执行规则见 [保护性休眠](LOW_POWER_POLICY.md) 和 [完整休眠梳理](SLEEP_LOGIC_REVIEW.md)。
`COMMITTED` 表示前置动作完成、即将调用 SDK 深睡或切断 MCU 电源，不证明芯片
实际睡眠或 Gate 状态。断连、通信失败、超过五秒未更新均显示未知或过期，不能
把通信中断解释成已经休眠。真正深睡/掉电后无法实时读取；开关立即请求的过程也可能短于上位机刷新周期。

旧固件根据原 Diagnostics magic/schema/新增 capability 判定不支持，不显示虚构的零秒。
新快照只增加 RAM 观察数据，不改变 Config/State/Event、OTA 参数编号或已有寄存器含义。

## 当前策略如何映射

| 产品/入口 | 倒计时和门禁 |
|---|---|
| 四产品低压/AFE 异常 | 使用产品阈值和延时；两类计时独立；展示最早到期的一条，阻止位与退避为零，到期 D008 断电、SH 深睡 |
| D008 命令关机 | 等待已有 UART/BLE 应答，最长 500 ms；一线通/OTA/Flash及保存/AFE/BLE失败不拒绝关机，无失败退避 |
| D008 ACC | 宏启用时ACC高电平立即锁存；一次收尾后保留PC4高并深睡，通信/保存/AFE/BLE失败不拒睡 |
| SH 开关 | 宏启用时OFF立即提交，延时为零；不要求INT条件，无业务阻止位和失败退避 |
| SH 命令 | 等待已有 UART/BLE 应答，最长 500 ms，到期强制深睡 |

四项目 `BMS_PRODUCT_SWITCH_SLEEP_ENABLE` 默认1，置0只关闭开关/ACC请求。SH命令休眠后OFF不恢复业务，再ON才恢复，见 [SH低功耗](SH_LOW_POWER_FAILURE_HANDLING.md)。

普通 suspend 是否许可独立展示，不代表可以阻止保护性深睡。
AFE 和实板边界见 [AFE资料指南](AFE_REFERENCE_GUIDE.md) 与 [保护性深睡](LOW_POWER_POLICY.md)。

2026-10-09 普通 suspend 门禁：四产品均以有效、有符号 mA 判断充/放电，
电流绝对值达到已有可靠电流边界 200 mA 即禁止；D008 原 500 mA 门限已收紧，
SH 不再只看截断后的放电电流。测量无效/过期、采样任务到期、Flash 未恢复锁定时也禁止。
2026-10-10 移除 SH 固定 UART 禁睡门禁；串口连续静默 30 秒才许可普通 Suspend，RX PAD 唤醒首帧丢弃，定时采样唤醒不刷新静默计时。详见 [SH低功耗策略](SH_LOW_POWER_FAILURE_HANDLING.md)。

小于 200 mA 的区间沿用原测量可靠性限制，不能据此断言物理充放电为零；
允许普通 suspend 时仍依赖已有 200 ms 定时唤醒、主循环采样和 AFE 正常工作模式。
2026-10-10 删除关闭定时唤醒的实验配置，四产品统一使用下一次 200 ms 应用采样期限；
不是每轮处理完再睡满 200 ms。普通 suspend 不执行 AFE sleep，也不清 SOC 容量。
SOC 使用应用实际时间和最新有效电流积分，AFE 独立负责数据活性；新样本资格另行保留。
该历史阶段未执行编译、host、实板或 OTA，不能把历史阶段的验证范围当成当前固件结论。
2026-10-09 另修复保护性低压计时被短暂采样过期清零：只有有效采样证明恢复才撤销
低压区域，等待新样本不延后已确认低压的到期时间，见 [保护性深睡](LOW_POWER_POLICY.md)。
普通 suspend 门禁与低压计时是不同判断；host/链接结果均不代表实际功耗或 Gate 验收。

## 只读协议 schema 1

Modbus 03，`0x3300..0x3313`，一次读取20 words（45字节RTU响应）。
每个word为大端，u32沿用旧Diagnostics的**低word在前**，与运行日志u32顺序不同。
旧 Diagnostics 头 `0x2A02` 的 bit6（`0x0040`）作为兼容发现入口表示支持，
不要求其他诊断能力。06/10写入以及跨边界访问拒绝。

| word偏移 | 内容 |
|---|---|
| 0 / 1 | magic `0x534C` / schema `1` |
| 2 / 3 | 状态 / 原因 |
| 4 / 5 | bit0普通suspend策略许可 / 保留零 |
| 6..7 | 深睡/关机阻止位图 |
| 8..9 | 已累计毫秒 |
| 10..11 | 设定延时毫秒 |
| 12..13 | 距计时到期毫秒，饱和至零 |
| 14..15 | 失败重试剩余毫秒 |
| 16..17 | 发布时32K tick |
| 18..19 | 读取时32K tick |

状态：0尚未发布，1无请求，2计时，3被阻止，4到期待执行，5重试等待，6已提交动作。
原因：0无，1命令，2ACC，3开关，4旧极低单体电压（新固件不再产生），5下档低压，6上档低压且无可靠充电，7AFE异常，8过放未恢复（固定180秒）。两档电压与延时可配置，AFE延时固定30分钟，见 [休眠配置](SLEEP_CONFIGURATION.md)。

阻止位bit0..10依次为OTA、Flash未锁、总线忙、BLE等待、固定UART门禁、UART发送、
PAD有效、采样无效/过期、保存失败、AFE入睡/关断失败、BLE广播控制失败。
2026-10-14起D008 ACC不再发布失败阻止位或5秒退避，旧bit/状态编码保留用于旧固件解码。开关、命令和保护性原因的阻止位/失败退避为零；命令应答等待发布计时，不把普通Suspend门禁显示为深睡/关机阻断。
五秒新鲜度判断使用无符号32位tick差，处理自然回绕。
