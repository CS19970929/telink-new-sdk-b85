# 实时休眠原因与倒计时

适用四产品固件 `codex-bms-monorepo` 和 Windows 上位机维护分支
`feature/windows-afe-hw-protection-editor-v2`。新增只读观察窗口，电源策略仍由
`bms/app/app_power.c` 持有；诊断读取不推进计时、不访问 AFE、不写 Flash。

## 显示内容与边界

客户版和内部版的“实时监控 → 系统监控信息”显示深睡/关机状态、触发原因、
已累计时间、设定延时、距计时到期的时间、阻止原因、失败重试等待及普通 suspend
策略是否许可。跟随原一秒自动刷新；PC 不自行递减倒计时。BMS 诊断的“低功耗”页
及导出包也包含该快照。

时间到期不等于已经进入休眠；门禁和失败退避仍可能阻止执行。
`COMMITTED` 表示前置动作完成、即将调用 SDK 深睡或切断 MCU 电源，不证明芯片
实际睡眠或 Gate 状态。断连、通信失败、超过五秒未更新均显示未知或过期，不能
把通信中断解释成已经休眠。真正深睡/掉电后无法实时读取；ACC 的 200 ms 窗口
也可能短于上位机刷新周期。

旧固件根据原 Diagnostics magic/schema/新增 capability 判定不支持，不显示虚构的零秒。
新快照只增加 RAM 观察数据，不改变 Config/State/Event、OTA 参数编号或已有寄存器含义。

## 原有策略如何映射

| 产品/入口 | 倒计时和门禁 |
|---|---|
| D008 命令关机 | 无额外计时；等待 OTA、Flash、总线和 BLE 应答，失败按原五秒重试 |
| D008 ACC | 高电平连续200 ms；BLE断开、保存及AFE shutdown成功后按原流程深睡 |
| D008 自动低压 | 2550 mV以下一小时；其余阈值/时长来自当前产品头文件；只有新鲜测量、无OTA/Flash/总线忙且BLE断连才累计；失去资格会按原逻辑重置 |
| SH 开关 | 编译启用开关策略时，开关关闭及对应INT条件累计三秒 |
| SH 低压 | 2550 mV以下一小时，其他区域使用产品宏；按原逻辑累计，固定UART/发送/OTA/Flash/PAD门禁阻止执行 |
| SH AFE异常 | 不在更高优先级电压区域时，累计三十分钟；进入失败按原三秒重试 |

SH 多条计时并行时展示最早到期的一条，不改变其他计数或执行顺序。
D008 自动关机与普通 suspend 分开判断：±500 mA、采样待处理等阻止 suspend，
不应误作自动低压关机门禁。SH 的固定UART门禁继续保留。

AFE身份和未决项继续见 [AFE资料指南](AFE_REFERENCE_GUIDE.md) 与固定审查。
DVC1124-2 RM V1.2、SH36735XX V1.0A 的原有睡眠/唤醒实现没有修改；
本功能只暴露项目电源策略，不能由诊断值推定原手册中的实际功耗或板级唤醒保证。

## 只读协议 schema 1

Modbus 03，`0x3300..0x3313`，一次读取20 words（45字节RTU响应）。
每个word为大端，u32沿用旧Diagnostics的**低word在前**，与运行日志u32顺序不同。
Diagnostics `0x2A02` 的 bit6（`0x0040`）表示支持。06/10写入以及跨边界访问拒绝。

| word偏移 | 内容 |
|---|---|
| 0 / 1 | magic `0x534C` / schema `1` |
| 2 / 3 | 状态 / 原因 |
| 4 / 5 | bit0普通suspend策略许可 / 保留零 |
| 6..7 | 深睡/关机阻止位图 |
| 8..9 | 已累计毫秒 |
| 10..11 | 设定延时毫秒 |
| 12..13 | 距计时到期毫秒，饱和至零 |
| 14..15 | 失败重试剩余毫秒 |
| 16..17 | 发布时32K tick |
| 18..19 | 读取时32K tick |

状态：0尚未发布，1无请求，2计时，3被阻止，4到期待执行，5重试等待，6已提交动作。
原因：0无，1命令，2ACC，3开关，4极低单体电压，5低压，6低压且无充电，7AFE异常。

阻止位bit0..10依次为OTA、Flash未锁、总线忙、BLE等待、固定UART门禁、UART发送、
PAD有效、采样无效/过期、保存失败、AFE入睡/关断失败、BLE广播控制失败。
失败位记录本次休眠原因的最后失败，下一次实际尝试或原因变化时清除；不作为新增控制门禁。
五秒新鲜度判断使用无符号32位tick差，处理自然回绕。
