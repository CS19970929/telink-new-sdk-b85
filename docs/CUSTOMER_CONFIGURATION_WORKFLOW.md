# 同板多客户的源码配置流程

同一硬件产品使用一份产品源码，每个客户、每个版本保存独立 JSON 方案。源码窗口负责载入、编辑、预览和写回；构建仍读取已保存的源码。

## 日常操作

1. 双击 `bms_tools/configure_parameters.cmd`，选择 D008、D011、D013 或 D014。
2. 填写客户/方案名称和版本，例如“客户 A 8S”“v2”。在装配页核对实际 AFE、串数、编译化学体系、容量及分流器。
3. 参数页修改软件一级/二级/三级、恢复、滤波与独立 AFE 硬件阈值。表头 LFP/NMC 用于编辑对应默认分支，切换不会丢弃另一分支的待编辑值。
4. 寄存器页默认只显示可配置项。选中寄存器、双击字段，可点击每一位或输入编码；详情显示公式、枚举、跨字节组合和原 PDF 页。
5. 点击“另存客户方案 JSON”。默认位置 `configurations/customers/<product>/<客户>-<版本>.json`；建议另存新版本，保留旧方案并提交 Git。方案保存不写源码。
6. 要制作某客户固件时，先选对应产品，再载入方案。检查窗口值，点击“预览 Git 差异 / 保存源码”，确认具体差异后写回。
7. 在原编译窗口明确选择已有设备需要覆盖的参数组，审查差异后提交、验证、编译。发布时保存客户 JSON、Git 提交、构建 manifest 和固件，依 manifest 的 `configuration.customer_profile` 追溯客户/版本。

例如 D014 客户 A 与客户 B 都是 8S LFP，可各存一份方案，只改变各自保护值。切换到客户 B 时载入其完整参数集合，再写源码，不需要复制整个固件工程。载入 D014 方案到 D011 会被拒绝。

## 所有权与保存范围

| 内容 | 唯一源码入口/行为 |
|---|---|
| 四产品默认参数 | 各自 `bms/products/<product>/dXXX_protection_config.h`，互不共享默认值 |
| SH 参数范围检查 | `bms/products/sh3673510_parameter_checks.h`，只共用校验逻辑 |
| 板级接线、能力 | 产品 `bms_product.h`，不随客户方案任意更换 GPIO/NTC 角色 |
| 保护寄存器字段 | 反解回物理阈值/延时/开关，由原 profile 编码；不写 raw 保护覆盖 |
| 稳定固定字段 | 产品 `afe_register_config.h` 中的受控预设；运行时命令不保存 |
| 客户标识 | 同文件中的 `BMS_SOURCE_CUSTOMER_NAME/REVISION`，仅用于源码和构建收据追溯 |

JSON 保存当前产品可编辑标量、LFP/NMC 两套默认分支、装配、分流器、调试开关和固定字段预设。**它不是完整工程备份**：多行 OCV 曲线点、GPIO/NTC 接线、编译模式与固件来源仍由 Git/manifest 追溯。JSON 不含设备校准、SN、SOC 运行值、事件、Flash 镜像、OTA 组和一次性标识。

载入严格检查产品、AFE、目录版本、参数集合、单位表示范围和掩码；目录/宏集合变化后须重新核对并另存新方案，不能静默忽略未知字段。载入先完整验证，再修改窗口，不直接写设备或源码。

源码保存检查读取以来的文件字节，遇外部编辑要求重新载入；写入异常有尽力回滚。该多文件操作不构成操作系统掉电原子事务，Git 差异必须复核。

## 按位配置的边界

可按位编辑不表示每个编码均适合硬件。SH OV/UV 必须按 10 位整体解释；OCD1/OCD2 共用 `OCD_EN`，TS1/TS2 使用当前 profile 的同一温度保护许可，修改其中一个许可会联动另一项。温度阈值按生产 10K NTC 表反解。

若物理参数的整数单位无法精确表示某个原始编码，窗口拒绝静默换档。用物理值输入，或在内部版冻结后临时试验。恢复阈值、延时关系和实装能力仍由固件校验，GUI 保存不代表产品参数已经签核。

RO、保留位、W0C/RC、FET、均衡、模式、复位、触发位没有普通客户预设。装配串数和板级测量/看门狗策略须走原拥有者；每项在“配置入口”列说明，取消“只看本窗口可配置项”可查完整目录。

## 与在线参数、临时调试的区别

- 源码客户方案：用来反复制作某客户固件，重启后仍按原 Flash 优先和 OTA 组规则生效。
- 上位机普通参数页：按既有事务保存设备持久参数，35-word 硬件保护接口保持。
- 内部版“AFE 全寄存器”：核对实际编码/状态，冻结后台后临时修改 AFE RAM。不会自动变成源码客户方案，也不保存 raw 寄存器到 Flash。

已有设备的有效持久参数优先。只改源码不等于覆盖设备；在原窗口明确选择 SW/AFE/BUSINESS/SOC 等组。不会自动选择 `factory_reset`。详见 [OTA 参数规则](OTA_PARAMETERS.md) 和 [寄存器操作](AFE_CONFIGURATION_EDITOR.md)。
