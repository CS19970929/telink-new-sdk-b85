# 源码参数窗口与内部版 AFE 寄存器调试

本次实现日期：2026-10-19。源码参数、设备持久参数、AFE 原始读回和物理动作是不同证据。
当前交付的编译、测试和实板状态以本次会话交付记录为准，本文不将历史报告当作验收。

## 源码阶段操作

VS Code 执行任务 **BMS: 修改源码参数与 AFE 寄存器配置**，或在原编译窗口点击
**保护参数 / AFE 位配置**。也可从仓库根执行：

```powershell
python -X utf8 -B bms_tools/configure_parameters.py --product d014
```

窗口只编辑源码，不编译、不连接设备、不生成 BIN、不 OTA。

1. 选择产品。参数表初始显示当前产品化学体系；表内 LFP/NMC 选择只选择要编辑的默认值表，
   **不会切换设备或产品当前电池类型**。切换类型仍用原编译窗口的四组 Config 规则。
2. 在保护参数表双击数值，编辑软件一级/二级/三级/恢复/滤波，或独立 AFE 硬件参数。
   单位保持原协议：`A10=0.1 A`，`FILTER_10MS=10 ms`，`X10=(℃+40)*10`。
   D011/D013/D014 共用默认值的项目明确显示影响三个产品。
3. 寄存器页查地址、名称、位掩码、RW/RO/RC/W0C、编码说明、原厂复位值和原 PDF 页。
   复位值不是源码初始化值，也不是设备读回。可通过按钮跳到对应硬件保护参数。
4. 稳定固定字段可双击设置源码预设，也可取消本寄存器覆盖。保护字段继续由 profile 管理；
   FET/均衡/模式/触发/清标志等运行时命令不写入通用预设。
   需要试验原始保护编码时，选中字段导出调试 JSON，内部版导入后只修改 AFE RAM。
5. 分流器页填写精确比例 `element_uohm / parallel_count`。D014 为 `2000 / 3 µΩ`；
   未知实装组合的其它板保留原等效电阻 `/1`，不猜测电阻只数。
   DVC 当前采样接口使用整数微欧，窗口拒绝不能整除的组合，不进行隐式近似。
6. 保存前预览源码差异。保存按原规则更新受影响产品的参数摘要与一次性标识，
   保留已选择的 OTA 组，不自动选择出厂重置。多文件写入有异常回滚和并发字节检查，
   不宣称操作系统掉电时多文件原子保存。

保护预设仍遵守 [存储](STORAGE.md) 和 [OTA 参数规则](OTA_PARAMETERS.md)：有效 Flash 值优先，
修改编译默认不会直接覆盖设备。固定寄存器预设属于编译输入，在后端完整初始化中应用并读回；
它们不增加 Flash schema。恢复、类型切换和在线 35-word 事务仍由原模块管理。
参数关系、型号能力、保证范围及恢复条件由固件原有校验继续约束，GUI 保存不代表参数已签核。

## D014 分流器与硬件档位

名义电阻为 `2 mΩ / 3 = 2000/3 µΩ`。旧代码的 `667` 单位是 **µΩ**，不是 mΩ。
电阻近似误差约 +0.05%，对应同一寄存器实际动作电流比旧模型换算值约高 0.05%。
但阈值向上选择寄存器档位时，这个误差可造成跨档：

| 请求与字段 | 精确 2000/3 µΩ | 旧 667 µΩ 模型 |
|---|---|---|
| OCD1 请求 7.5 A | 5 mV，code 0，名义 7.5 A | 5.0025 mV，进入 10 mV 档，实物名义 15 A |
| OCD2 请求 15 A | 10 mV，code 0，名义 15 A | 10.005 mV，进入 20 mV 档，实物名义 30 A |

这不是“所有配置都误差一倍”；只说明档位边界不能先将并联电阻取整。
当前修正使用交叉相乘直接选档；采样电流也保留分流器比例。
SC 为 OCD2 原始电压档位乘 `2/3/4/6`，不再把已取整的 `effective_a10` 乘倍数。
SCT 仍使用原厂非等距 16 档表。TC32 运算使用有界 32 位整数，没有新增 64 位除法依赖。

旧 `0x2525` 保持整数 µΩ 元数据；追加只读 `0x252C=element_uohm`、
`0x252D=parallel_count`。35-word profile、旧地址、缩放、Config/State/Event schema 4 均保持。
上位机可选读取追加比例；旧固件无该窗口时明确显示整数模型、精确比例未知。
SH 保护恢复校验使用实际量化阈值，不能用用户请求值代替 effective 阈值。

已有 offset/gain 不自动清除。分流器模型修正会改变采样换算和部分硬件编码，
仍需实板检查电流校准、OCD/OCC/SC 动作电流、恢复、Gate/Vgs 和温漂。

## 内部测试版使用

Windows 真源仍是 `feature/windows-afe-hw-protection-editor-v2` 的 `bms-tool-windows/`。
新增窗口仅在 `BmsFactoryTest.Windows` 注册；客户版不增加全寄存器入口。
两版现有硬件保护页都显示精确分流器比例，并保持 35-word 持久参数事务。

开发固件在源码窗口勾选 `BMS_AFE_REGISTER_DEBUG_ENABLE` 后单独构建；默认 0，
production 与该开关同时开启会编译拒绝。生产/普通开发未开启时，新增寄存器命令返回不支持。

1. 打开“AFE 全寄存器”可离线选择 DVC 或 SH 目录；设备连接后读取型号并新建原 `0x42` 60 秒会话。
2. 普通读取可逐项读取全部安全地址；RC 位显式读取，时间戳快照非原子。
3. 确认断开充电/负载后进入调试冻结。固件要求完整有效测量、电流在 ±200 mA 内，
   MOS/均衡关闭事务成功；关闭命令/寄存器反馈不能代替实际 Gate 测量。
4. 选择字段、输入原始编码，先预览物理电压/电流，再写入。目录 ID 不匹配时拒绝写。
   使用 expected 原字节的 CAS，保留其它位，写后读回验证。
5. 原始修改只作用于 RAM。导入的 1..32 项是逐项操作，失败立即停止，不能称整组原子提交。
6. 显式点击“恢复源码 / 持久配置”后，固件完整初始化后端并重新应用原 profile，
   保留软件活动故障、用户 MOS 请求和远程禁止；正常输出须重新通过原 guard 资格。
   断连/授权超时只撤销写会话，保持冻结；关闭窗口也不自动恢复输出。

冻结期间正常采样/控制和新的休眠计时暂停，SOC 不用陈旧电流积分，普通参数写入被拒绝；
不自动保存原始寄存器，不增加新的低功耗入口。恢复失败或应答未知时保持冻结并重新读取；
禁止自动重发写入。新的调试会话可以重新读取或执行恢复。

## 调试协议（原功能码 0x42 的新增子命令）

帧沿用原 Modbus 地址/CRC，token 与数据为大端。旧 0x01..0x06 不改动。
下表长度含地址、功能码、CRC；所有成功响应均为 `addr,42,command,00,payload,CRC`。

| 子命令 | 请求长度/数据 | 成功响应长度/数据 |
|---|---|---|
| 0x10 INFO | 5，无 token | 18：schema=1、model u16、enabled u8、held u8、catalog_id u32、element u16、parallel u8 |
| 0x11 READ | 9：token u16、address u8、consume_rc u8 | 8：address u8、value u8 |
| 0x12 BEGIN | 7：token u16 | 6：无 payload |
| 0x13 WRITE | 11：token u16、address/mask/expected/value 各 u8 | 8：address u8、实际读回 u8 |
| 0x14 RESTORE | 7：token u16 | 6：无 payload |

错误统一 6 字节：1 格式，2 授权，3 未支持，5 禁止地址/掩码/RC，6 CAS 不符，
7 总线/读回/恢复失败，8 未取得冻结资格。单帧最大 18 字节响应，适用于 BLE MTU=23。
上位机共用接收器同步增加长度推断；不修改 BLE/UART 底层协议或旧参数帧。
