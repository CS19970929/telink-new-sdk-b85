## 失败原因与证据限制

截图把欠压从 `2400` 改为 `2500 mV`、恢复值保持 `2800 mV`；此组符合 SH 的 `1000..3500 mV` 范围和恢复关系。协议实际提交完整 35-word，不仅提交当前左侧分类。

当前 D014 未提交源码同时包含：

1. `OCC1_DELAY_MS=100`，低于严格新写入的 `140 ms` 首档。既有上位机仅在该项未编辑且实际有效值明确为 140 ms 时规范化候选，并在确认框列出。
2. `CHG_UT_X10=150`，即 `−25℃`，低于 PDF p49 和固件严格新写入的 `−20℃` 下限。既有模型只检查温度协议总范围和恢复回差，漏掉这一型号范围，因此会把含有该值的完整候选发送给设备。

若设备加载了该源码参数，整组必在 `bms_afe_hw_profile_validate_write()` 被拒绝，发生在持久化及硬件应用之前。`0x42 / COMMIT(0x06)` 会把所有非零内部错误合并为 `status=0x04`；该状态既不定位到欠压，也不等于 `CONFIG_INCONSISTENT`。

本轮未连接设备，截图也未提供失败后的 `last_error` 和完整 35-word 实读。因此上述为当前源码中已确定的拒绝路径，不能把它写成已取得本次设备事务实读证据。配套上位机现已在失败后单独读取元数据，报告真正的阶段；有效值不可读时仍保留状态诊断。

## 修复内容与同类问题

- 客户版/内部版共享规则补齐 SH 电压、四类温度、全部保护延时及共用 OCD 使能检查；保留原电流/SC 基准/恢复关系检查。标量范围错误一次列出，显示参数、数值、允许范围及 word 索引。
- 范围列从“电流允许范围”改为“允许输入范围”，电压、温度、延时也显示范围；NaN/Infinity/超长指数及不能表示的 0.1 单位精度在本地拒绝。
- 公共 DVC 页面一并补齐固件已有的电压与延时范围；删除其过时的 8..1999 us 第二道提示，采用固件现有严格校验上限 1992 us。没有修改 DVC 固件或硬件策略。
- 设备仍拒绝时，单独读取 `0x2523` 元数据，报告 apply state 与 last error；不依赖 effective，不自动重发提交。状态读回失败明确标为结果未确认。
- 源码窗口编辑 SH AFE/分流器/装配类型时检查两种化学体系的完整参数；客户方案导入/导出同样检查，拒绝后不修改当前窗口。仅修改无关设置时不强制迁移历史 AFE 默认。
- 源码字段编辑器的 OTC 原先误用 OTD 的 45..80℃ 搜索范围，导致合法 40℃编码不能选择、部分超范围充电高温编码却可能被选择；现按 OTC 40..70℃、OTD 45..80℃ 分开。
- D011/D013 共享 SH 模型和预检查；其现有低于首档的默认值不在本次 D014 产品阈值变更范围，编辑 AFE 时会得到明确拒绝和项目清单，不静默调整。
