# HS-D008 / DVC1124-2 integration

This branch ports the existing TLSR8251 BMS application to the HS-D008 board with a DVC1124-2 AFE while keeping the existing protection/SOC/Modbus/BLE framework.

## Defaults

- AFE model: `DVC1124-22`
- cell count: 24
- I2C: PC0/SDA, PC1/SCL, 100 kHz
- normal DVC1124 transfer address: `0x40` write / `0x41` read
- current shunt: 200 uOhm (10 x 2 mOhm in parallel on HS-D008)
- NTC1: DVC GP4
- NTC2: DVC GP1
- GP5: low-side CHG output
- GP6: low-side DSG output

The board also has a 20S assembly option. Override `DVC1124_DEFAULT_CELL_COUNT` to 20 for that variant; the driver masks unused upper cell channels.

## Address selection

The Telink B85 I2C driver uses the 8-bit transfer address including the R/W bit position. The DVC driver therefore stores the write transfer address (LSB=0).

Build-time defaults can be overridden before `dvc1124.h` is compiled:

```c
#define DVC1124_DEFAULT_MODEL                DVC1124_MODEL_22
#define DVC1124_DEFAULT_ADDR_MODE            DVC1124_ADDR_FIXED
#define DVC1124_DEFAULT_HARDWIRE_CODE        0u
#define DVC1124_DEFAULT_EXPLICIT_WRITE_ADDR  0x40u
```

Runtime selection is also available:

```c
DVC1124_SetAddressConfig(DVC1124_MODEL_22,
                         DVC1124_ADDR_FIXED,
                         0,
                         0x40);
```

For a hardware-strapped cascade application use `DVC1124_ADDR_HARDWIRED`. The write transfer address is resolved as:

- DVC1124-22: `0xC0 | (GP2:GP1 << 1)`, strap code 0..3
- DVC1124-24: `0xC0 | (GP4:GP1 << 1)`, strap code 0..15

Important: this does **not** program an AFE address in software. DVC1124 hardwired-address mode is a hardware mode and requires the AFE pins to be strapped as specified by the vendor manual. The normal HS-D008 current-sense assembly uses SRP/SRN across the shunt bank, so its default mode remains the normal fixed `0x40/0x41` address.

`DVC1124_ADDR_EXPLICIT` only changes the MCU target address and is intended for a board variant whose physical AFE address already matches that value.

## Measurement and protection mapping

The driver implements the DVC1124 CRC8 framing (`poly=0x07`, init `0x00`) including the different first-byte CRC coverage for read and write operations. Cell voltage, pack/load/VTOP voltage, CC2 current, GP thermistors and die temperature are converted into the existing `g_stCellInfoReport` data model.

DVC hardware COV/CUV and OC1/OC2 settings are derived from the existing `g_tParam.protect` values. Current thresholds are converted through the configurable shunt value. Project-specific short-circuit threshold/delay values were not present in the source material, so DVC SCD is intentionally disabled by default instead of inventing a production value. Set `DVC1124_HW_SCD_THRESHOLD_MV` and `DVC1124_HW_SCD_DELAY_US`, or call `DVC1124_SetShortCircuitProtection()`, after product values are confirmed.

The DVC1124 common-mode secondary cell-voltage calibration lookup from the reference manual is applied before values are published to the existing BMS logic.

## Legacy application compatibility

The existing application was written around SH367309 names and GPIO assignments. `app_config.h` redirects only the application-facing AFE calls to the DVC driver, while `conf.h` maps the HS-D008 physical nets and replaces obsolete SH-specific control/ADC selectors with virtual pins.

This is deliberate: on HS-D008, PA1 is `MCC-EN-HT`, PC4 is `MCU-LDO`, PB4/PB5/PB7/PD3 are SOC indicator pins, and PB6 is the blue LED. The old SH board mapping must not toggle those pins as if they were AFE/MCC/ADC controls.

## Validation still required on hardware

Before release, verify with a logic analyzer and battery simulator:

1. I2C SCL <= 100 kHz and DVC CRC read/write framing.
2. 24 cell readings, 20S mask variant, VTOP/PACK/LOAD and current polarity.
3. GP1/GP4 NTC temperatures and optional GP2/GP3 external thermistors.
4. CHG/DSG low-side outputs on GP5/GP6, including all software protection transitions.
5. COV/CUV/OCD1/OCC1/OCD2/OCC2 thresholds and delays after quantization.
6. SCD only after the product threshold/delay is explicitly configured.
7. sleep/wake behavior and first I2C transaction after DVC sleep.
8. BLE/Modbus/SOC regression against the previous application.
