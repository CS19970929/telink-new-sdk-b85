# DVC1124-2 / HS-D008 AFE 开发与配置基线

> **用途**：这是本仓库 DVC1124-2 AFE 的开发基线文档。后续 AI、Codex 或人工修改 AFE 驱动、保护参数、低功耗、MOS、均衡、断线检测时，必须先阅读本文。
>
> **适用分支**：`feature/dvc1124-22-bms`
>
> **芯片**：DVC1124-2 / DVC1124-22
>
> **主控**：TLSR8251F512ET32
>
> **板卡**：HS-D008，当前默认 24S LFP；原理图同时标注 20S NMC 装配版本。

---

## 1. 资料优先级：必须遵守

本项目所有 DVC 寄存器、bit 位、量化公式、状态语义按以下优先级判断：

1. **`DVC1124-2参考手册_V1.2`**：寄存器和芯片行为的最高依据。
2. **`HS-D008-24S100A-V1` 原理图/BOM**：板级引脚、外部电路、分流器和装配配置依据。
3. **`DVC11XX_demoCode V1.3`**：只作为厂家实现方式、时序和使用示例的辅助依据。
4. 本仓库历史代码、第三方 GitHub 驱动：只能交叉验证，不能覆盖上面三项。

### AI 强制规则

- 手册与 DemoCode 冲突时，**以 DVC1124-2 V1.2 手册为准**。
- DemoCode README 指向 DVC11XX-D 系列，内部存在 D 系列扩展/旧注释，不能把未出现在 DVC1124-2 V1.2 的字段直接移植到本项目。
- 不允许根据变量名、旧 SH367309 代码或第三方驱动猜寄存器。
- 不允许根据“常见 BMS 做法”自行填写 SCD、I2C WDT、芯片过温、Body Diode 等量产安全参数。
- 任何新增寄存器配置都必须在代码注释或 PR/commit 中写明：**寄存器地址、bit、手册版本/页码、物理量公式**。

### 2.1 24S LFP 与 20S NMC 不是只改串数

原理图同时标注：

- 24S 铁锂版本；
- 20S 三元版本。

因此切换产品时，至少要把以下内容作为**产品 Profile**整体评审：

- `cell_count`；
- COV/CUV 与恢复阈值；
- pack OV/UV；
- SOC OCV 表；
- 满充/空电条件；
- 充放电温度策略；
- 充电器/整车协议中的电压限制；
- 可能不同的 GP2/GP3 装配。

禁止只把 `DVC1124_DEFAULT_CELL_COUNT` 从 24 改成 20 就认为完成 20S NMC 适配。

## 4. I2C 地址与 CRC

### 4.1 地址约定

Telink B85 I2C API 使用包含 R/W bit 的 8-bit transfer address，所以本驱动保存的是写地址：

```text
write = 0x40
read  = 0x41
```

不要把 `0x40` 再右移成所谓 7-bit 地址传给当前 Telink B85 driver。

### 4.2 CRC8

DVC 使用：

```text
Polynomial: x^8 + x^2 + x + 1 = 0x07
Initial:    0x00
```

写第一个数据字节：

```text
CRC(write_addr, register, data0)
```

后续数据字节：

```text
CRC(dataN)
```

读第一个数据字节：

```text
CRC(write_addr, register, read_addr, data0)
```

后续：

```text
CRC(dataN)
```

当前 `DVC1124_ReadRegisters()` / `DVC1124_WriteRegisters()` 的 CRC framing 按此实现。

### 4.3 MCU I2C 超时

不得直接依赖 Telink SDK 原始 `i2c_read_series()` / `i2c_write_series()` 的无限 BUSY 等待。

当前 DVC 路径使用：

```c
DVC1124_I2C_CMD_TIMEOUT_US
DVC1124_I2C_RETRY_COUNT
```

并在超时/NAK 后 reset I2C module 再重试。

默认：

```c
#define DVC1124_I2C_CMD_TIMEOUT_US 5000u
#define DVC1124_I2C_RETRY_COUNT    3u
```

### 4.4 Safety-critical write

对保护寄存器不能只执行“写函数返回”。至少要：

```text
prepare value
  -> write
  -> readback
  -> compare owned bits/value
  -> retry
  -> AFE communication/config fault
```

对于含 RC/R 状态位的 mixed-access register，只验证本次拥有的 bit mask，不能要求整个 byte 永远不变。

## 6. 禁止回归的寄存器事实

这一节是未来 AI 修改代码时最重要的防回归约束。

### 6.1 `0x5E` OCD2

```text
bit7       bit6      bit5..0
R          OCD2E     OCD2T[5:0]
```

正确：

```c
DVC_OC2_ENABLE = 0x40u;
```

错误：

```c
0x80u   // 禁止：bit7 不是 OCD2E
```

阈值：

```text
V_OCD2 = (OCD2T + 1) * 4mV
```

### 6.2 `0x5F` OCC2

```text
bit7       bit6      bit5..0
unnamed    OCC2E     OCC2T[5:0]
R/W        R/W       R/W
```

`bit7` 在 V1.2 中存在并且默认值为 1，但没有公开业务语义。

因此 **禁止整字节构造 `0x40|threshold` 后覆盖 bit7**；必须 RMW：

```text
preserve bit7
modify bit6 + bits5:0 only
```

阈值：

```text
V_OCC2 = (OCC2T + 1) * 4mV
```

### 6.3 `0x62` SCD

```text
bit7       bit6      bit5..0
R          SCDE      SCDT[5:0]
```

```c
DVC_SCD_ENABLE = 0x40u;
```

阈值严格按 V1.2：

```text
V_SCD = SCDT * 10mV
```

不是 `(SCDT+1)*10mV`。

本驱动启用时只接受：

```text
10..630mV，10mV 的整数倍
```

### 6.4 `0x6D`：最容易再次写错

V1.2 的真实布局：

```text
bit7  bit6  bit5    bit4    bit3    bit2  bit1  bit0
 -     -    CPVS2   CPVS1   CPVS0   COW   CMM   CVS
```

因此：

```c
CPVS_MASK = 0x38u;
COW       = 0x04u;
CMM       = 0x02u;
CVS       = 0x01u;
```

10V charge pump：

```text
CPVS=101
101 << 3 = 0x28
```

严禁恢复成旧错误：

```c
CPVS_MASK = 0xE0;  // WRONG
CPVS_10V  = 0xA0;  // WRONG: 实际 CPVS[5:3]=100 => 9V
COW       = 0x10;  // WRONG
CMM       = 0x08;  // WRONG
CVS       = 0x04;  // WRONG
```

旧错误的 `StartOpenWireCheck()` 实际会改变 charge-pump code，而不会启动 COW；当前已修正。

## 7. 状态/复位/休眠

`0x01 CST[3:0]`：

```text
1101 = reset all registers to defaults
1110 = enter sleep
1111 = enter shutdown
```

所以：

```c
DVC_CST_RESET_REGS = 0x0D;
DVC_CST_SLEEP      = 0x0E;
DVC_CST_SHUTDOWN   = 0x0F;
```

厂家 Demo 某个 `DVC11XX_ForceSleep()` 把 `0x0F` 当 Sleep，是 Demo 自身错误；不能照抄。

当前 reset 流程：

```text
PD7 MCU-AFE-EN = 1
 -> init I2C
 -> CST=0xD
 -> wait DVC1124_RESET_SETTLE_MS (default 300ms)
 -> probe 0x8F + 0x7E
 -> apply board config
 -> apply protection config
 -> start normal sampling
```

后续若缩短 300ms，必须用硬件实测和 VADF/CC2F 数据有效性验证，不要凭经验直接改。

## 8. 测量换算

### 8.1 CC2 电流

手册：

```text
signed 20-bit two's complement
positive = discharge
negative = charge
LSB = 5/16 uV = 0.3125 uV
```

当前：

```text
I[mA] = CC2 * 0.3125uV / Rshunt[uOhm] * 1000
```

HS-D008 默认：

```text
Rshunt = 200uOhm
```

禁止把 SH367309 的 CADC 系数继续套到 DVC CC2。

### 8.2 Cell voltage

默认 `CVS=0`：

```text
VCn raw LSB = 100uV = 0.1mV
```

DVC1124 高共模下必须进行 V1.2 第 32 页二次校准。

手册公式：

```text
VC_AC[n] = VC_BC[n] / K[n]
K[n] = 1 + p1*VCM[n] + p2*VCM[n]^2
p1 = 0.35e-6
p2 = -0.12e-6
```

本项目使用手册给出的 K 查表做整数运算：

```text
VCM 0..24V      K=1.0000
24..40V         K=0.9999
40..51V         K=0.9998
...
117..120V       K=0.9986
```

不要删除该校准，也不要恢复成未经核对的历史系数。

### 8.3 VTOP / PACK / LOAD

```text
LSB = 12.8mV
```

当前换算使用整数四舍五入。

### 8.4 芯片温度 VCT

V1.2：

```text
T[C] = VCT * 0.24467 - 271.03
```

注意厂家旧 Demo 中出现过 `-271.3`，以 V1.2 的 `-271.03` 为准。

## 9. NTC

### 9.1 Pull-up 修调

`0x7E FRT`：

```text
Rpu[ohm] = 6800 + FRT*25
```

### 9.2 NTC 电阻

```text
Rntc = VGP_code * Rpu / (V1P8_code - VGP_code)
```

### 9.3 板载温度点

```text
NTC1 -> GP4
NTC2 -> GP1
```

当前项目定义：

```c
DVC1124_DEFAULT_BATTERY_NTC_GP = 4
DVC1124_DEFAULT_MOS_NTC_GP     = 1
```

### 9.4 故障处理

以下情况不能当正常温度：

```text
V1P8 invalid
GP code == 0
GP code >= V1P8
```

当前 DVC 驱动会把配置的 battery/MOS NTC 异常上报为现有 `TEMP_BREAK`；`dvc1124_bms.c` 会阻止新的 CHG/DSG enable 命令，直到配置传感器重新有效。

### 9.5 尚未完全闭环的事项

当前温度 R-T 表来自历史 BMS 项目。HS-D008 原理图 NTC 型号为 `SNC103B13435F0603E`。

**量产前必须用 NTC 器件规格书或实物温箱校验 R-T 表。**

不要因为 AFE 电阻公式正确，就默认 NTC 温度曲线也一定正确。

## 10. GP 模式

### 10.1 0x74：GP1/2/3

当前默认：

```c
DVC1124_GP123_MODE_VALUE = 0x49;
```

解释：

```text
GP1 = 01  -> NTC
GP2 = 001 -> NTC
GP3 = 001 -> NTC
```

但 HS-D008 的 GP2/GP3 接到外部接口，因此 `0x49` 只适用于“外部 NTC 确实装配”的产品。

若 GP2/GP3 未装配，应根据产品定义把它们设为 OFF/高阻，不要让通用 driver 固定假设所有产品都有 4 个 NTC。

### 10.2 0x75：GP4/5/6

当前：

```c
DVC1124_GP456_MODE_VALUE = 0x7F;
```

解释：

```text
GP4 = 01  -> NTC
GP5 = 111 -> low-side CHG
GP6 = 111 -> low-side DSG
```

该配置与当前 HS-D008 原理图匹配。

## 11. FET/MOS 控制

### 11.1 0x51

```text
DSGC=00/01 -> OFF
DSGC=10    -> OFF，但允许满足 Body Diode 条件时自动 ON
DSGC=11    -> ON

CHGC=00/01 -> OFF
CHGC=10    -> OFF，但允许满足 Body Diode 条件时自动 ON
CHGC=11    -> ON
```

当前兼容层只使用：

```text
00 = OFF
11 = ON
```

### 11.2 当前板输出

HS-D008 使用：

```text
GP5 low-side CHG
GP6 low-side DSG
```

历史 SH367309 BMS 的 `MTP_CONF.CHGMOS/DSGMOS` 通过兼容层映射到 DVC。

### 11.3 Body Diode recovery

DVC 原生支持反向电流续流：

```text
0x51 CHGC/DSGC = 10
0x66 BDPT != 0
0x53 DBDM / 0x54 CBDM 配合解除 mask
```

当前默认：

```c
DVC1124_BODY_DIODE_THRESHOLD_UV = 0
```

即 **未启用**。

以后实现“充过流后允许放电 / 放过流后允许充电”时，应优先评估 DVC 原生 Body Diode 机制与上层 FET Arbitration 的组合，不要在多个业务文件里散落强制开 MOS 特判。

## 12. 硬件保护参数编码

### 12.1 COV

```text
register: 0x70/0x71
code=0 -> disabled
Vtrip = code*1mV + 500mV
```

Delay code：

```text
0 -> 200ms
1 -> 300ms
...
8 -> 1s
9 -> 2s
...
15 -> 8s
```

### 12.2 CUV

```text
register: 0x72/0x73
code=0 -> disabled
Vtrip = code*1mV
```

Delay table同 COV，最大 8s。

### 12.3 OC1

```text
OCD1: 0x59
OCC1: 0x5A
0 -> disabled
threshold = code*0.25mV
```

Delay：

```text
OCD1D 0x5B
OCC1D 0x5C
T = (code+1)*8ms
```

### 12.4 OC2

```text
OCD2: 0x5E
OCC2: 0x5F
enable = bit6
threshold bits = [5:0]
Vtrip = (code+1)*4mV
```

硬件最小阈值：

```text
4mV
```

HS-D008 `Rshunt=200uOhm` 时：

```text
4mV / 0.2mOhm = 20A
```

因此当前历史参数中的：

```text
OC2 requested = 15.0A
```

**DVC 硬件无法精确表示，实际最小只能约 20A。**

绝对禁止把这种情况隐藏成“15A配置成功”。上位机/诊断层后续应区分：

```text
requested
encoded register
actual/effective
quantized or out-of-range
```

### 12.5 OC2 Delay

```text
0x60 OCD2D
0x61 OCC2D
T = (code+1)*4ms
```

### 12.6 SCD

```text
0x62: bit6=SCDE, bits5:0=SCDT
Vtrip = SCDT*10mV
0x63: T = SCDD*7.81us
```

当前项目没有经过确认的 SCD 产品值，因此：

```c
DVC1124_HW_SCD_THRESHOLD_MV = 0
DVC1124_HW_SCD_DELAY_US      = 0
```

即 **硬件 SCD 默认关闭**。

这不是最终量产状态。量产 Release 前必须根据 MOS、shunt、母线寄生、电流能力和实际短路测试确定 SCD threshold/delay。

## 13. 当前默认参数的 DVC 有效值

以当前 24S、`Rshunt=200uOhm`、历史默认参数为例：

| 项目 | 上层 requested | DVC 可实现/当前策略 |
|---|---:|---:|
| COV | 3750mV / 1s | 3750mV / 1s |
| CUV | 3000mV / 10s | 3000mV / **8s** |
| OCD1 | 10.0A / 100ms | 10.0A / **96ms** |
| OCC1 | 10.0A / 100ms | 10.0A / **96ms** |
| OCD2 | 15.0A / 100ms | **20.0A** / 100ms |
| OCC2 | 15.0A / 100ms | **20.0A** / 100ms |
| SCD | 未提供 | disabled |

延迟量化策略当前优先选择“**不晚于 requested**”的可表示值；若 requested 小于硬件最小值，则只能使用硬件最小值。

后续不要再次实现一套不同的量化算法，否则上位机、AFE 和软件保护会出现三套含义。

## 14. Cell Mask

`0x6A..0x6C`：

```text
0x6A: CM24..CM17
0x6B: CM16..CM9
0x6C: CM8..CM5 + PKM/LDM/CTM/V1P8M
```

`CM[n]=1`：

```text
关闭第 n 节电池保护，并默认关闭该节电压测量
```

当前 `dvc_apply_cell_masks()`：

- 24S：不屏蔽 Cell5..24；
- 20S：屏蔽 Cell21..24；
- 4S：屏蔽 Cell5..24。

DVC1124-2 V1.2 明确支持 **4..24S**；不要把最小串数错误改成 5S。

## 15. 均衡

寄存器：

```text
0x67 CB24..17
0x68 CB16..9
0x69 CB8..1
```

重要硬件行为：

> 这三组寄存器开启均衡后，**约 60s 自动清零**。

因此必须区分：

```text
requested balance mask
actual AFE balance mask
```

当前驱动已经不再长期拿 `s_balance_mask` 当真实状态，而是读取 `0x67..0x69` 更新上报状态。

但是当前驱动**不会自动续期均衡**。如果 BMS 算法需要连续均衡超过 60s，上层必须在小于 60s 的周期重新下发仍需开启的 balance mask。

不要把 60s 硬件自动关闭机制删除或通过盲目高频写寄存器绕过。

---

## 16. Open-wire

控制位：

```text
0x6D COW = bit2 = 0x04
```

置 1 后芯片启动断线检测，该 bit 约 1s 后自动清 0。

当前 `DVC1124_StartOpenWireCheck()` 只负责正确触发 COW。

完整产品诊断仍应实现状态机：

```text
IDLE
 -> TRIGGER COW
 -> WAIT about 1s
 -> read cell voltages
 -> evaluate open-wire criteria
 -> report diagnostic result
 -> IDLE
```

不要把“API 能置 COW”误认为“断线诊断功能已经完整完成”。

---

## 17. Sleep / Current Wake / Timed Wake

### 17.1 Sleep

```text
CST=0xE
```

### 17.2 Current Wake

需要两个条件共同考虑：

- `0x55 CAES`；
- `0x65 CWT`。

`CWT=0` 明确表示关闭休眠状态电流唤醒。

当前默认：

```c
DVC1124_CURRENT_WAKE_THRESHOLD_UV = 0
```

所以虽然 CAES 已配置，**DVC 电流阈值唤醒当前仍为关闭状态**。

如果产品需要“接负载产生电流即可唤醒”，必须根据实际 shunt 与期望唤醒电流计算 CWT，并做睡眠/唤醒实测。

### 17.3 Timed Wake

`0x78 TWSE` 当前保持关闭。除非产品低功耗策略明确需要，否则不要擅自启用。

---

## 18. DVC I2C Watchdog

`0x77 IWT[2:0]`：

```text
0XX -> off
100 -> 4s
101 -> 8s
110 -> 16s
111 -> 32s
```

同时：

```text
0x53 DWM: I2C timeout 是否关闭 DSG
0x54 CWM: I2C timeout 是否关闭 CHG
```

当前默认：

```c
DVC1124_I2C_WATCHDOG_SECONDS  = 0
DVC1124_I2C_TIMEOUT_CLOSE_CHG = 0
DVC1124_I2C_TIMEOUT_CLOSE_DSG = 0
```

即 DVC 自身 I2C WDT 未启用。

是否启用属于产品安全架构决策，需明确分析：

```text
MCU失控/死机
AFE硬件COV/CUV/OC/SCD仍工作的覆盖范围
I2C WDT关闭FET是否会引入新的车辆/负载风险
外部watchdog/保险丝/AFE硬件保护配合
```

不能因为 Demo 默认某个值就直接开启或关闭。

---

## 19. Core Over-temperature

`0x76 COTT` 可配置芯片核心过温关断阈值。

当前未配置量产值，保持默认关闭。

如果后续启用，必须从 DVC1124-2 V1.2 公式计算并经过温箱/热测试，而不是复用电池 NTC 或 MOS NTC 的阈值。

## 20. Alarm 与故障恢复

`0x00`：

```text
bit7 IWTF
bit6 COV
bit5 CUV
bit4 OCD1
bit3 OCC1
bit2 OCD2
bit1 OCC2
bit0 SCD
```

这些 flag 的清除规则按手册：

```text
write 0 -> clear corresponding flag
write 1 -> ineffective
```

当前 BMS adapter 策略：

- COV：达到 `u16VcellOvp_Rcv` 后才清；
- CUV：达到 `u16VcellUvp_Rcv` 后才清；
- OCC1/OCC2：要求充电器输入被移除后再清；
- OCD1/OCD2/SCD：要求开关/负载侧条件解除后再清；
- SCD 同时映射到历史 `CBC_DSG` 错误状态。

目的：避免 MOS 刚因过流/短路断开、电流归零后软件立即清 fault，再反复重开 MOS。

后续若修改恢复策略，要同时审查：

```text
AFE latch
software fault
MOS arbitration
charger/key/load detect polarity
客户协议开关机命令
```

---

## 21. 软件温度/总压保护

DVC1124-2 没有直接提供 SH367309 风格的外部 NTC 充/放电温度 fault bits，所以 `dvc1124_bms.c` 继续使用现有 BMS 参数实现软件三级：

```text
charge OTP/UTP
discharge OTP/UTP
MOS OTP
pack OV/UV
```

采样周期当前约 200ms，因此软件 filter 是按采样次数折算。

硬件保护和软件保护不要混为同一个层级：

```text
DVC hardware: COV/CUV/OCD/OCC/SCD ...
BMS software: pack voltage / external NTC / product logic ...
```

## 23. 公共 API 语义

```c
DVC1124_ReadRegisters()
DVC1124_WriteRegisters()
```

原始寄存器通信接口；只允许 AFE 驱动/诊断使用，不建议业务代码直接散写 magic address。

```c
DVC1124_SetMosState(chg, dsg)
```

当前只实现普通 OFF/ON；DVC 原生 `10` Body Diode 模式不在该 bool API 中表达。

```c
DVC1124_SetBalanceMask(mask)
```

写并校验 balance register；真实状态受 60s 自动清零影响。

```c
DVC1124_StartOpenWireCheck()
```

只触发 COW，不等于完整 open-wire algorithm。

```c
DVC1124_SetShortCircuitProtection(threshold_mv, delay_us)
```

严格按 V1.2 编码；非法范围返回失败，不猜值。

```c
DVC1124_UpdataAfeConfig()
```

历史命名保留。负责 board configuration + hardware protection configuration。

```c
DVC1124_AFE_IsReady()
```

为了兼容历史代码：

```text
0 = ready
1 = error
```

新的通用 AFE API 不应继续采用这种反直觉返回语义。

## 24. 禁止的代码模式

未来 AI 修改时禁止：

```c
/* 1. 按旧 Demo 位域直接猜当前芯片 */
g_AfeRegs.xxx = ...;

/* 2. 对 0x5F 整字节写，破坏 bit7 */
write(0x5F, 0x40 | code);

/* 3. 恢复旧错误 0x6D */
#define COW 0x10

/* 4. 写保护寄存器不读回 */
DVC1124_WriteRegisters(...);
return 1;

/* 5. 静默把不可表示参数当成原值 */
requested_15A -> program_20A -> report_15A;  // forbidden

/* 6. 用缓存值永久代表 balance 实际状态 */
report_balance = requested_mask;             // forbidden

/* 7. NTC异常时直接当成没有温度保护 */
if (temperature == 0) skip_protection;        // forbidden

/* 8. 把 0x0F 当成 sleep */
CST = 0x0F;                                   // shutdown
```

## 25. 修改 AFE 代码的标准流程

AI/Codex 每次涉及 DVC 修改时应按以下顺序执行：

```text
1. 找到 V1.2 手册对应 register/bit/formula
2. 检查 HS-D008 原理图是否影响该功能
3. 查看 DemoCode 是否提供时序/usage 辅助证据
4. 实现明确 mask，不依赖 C bit-field ABI
5. 保留 reserved/undefined bits
6. safety-critical write 必须 readback
7. 计算 requested -> code -> actual
8. 加边界测试
9. 检查 sleep/reset 后配置是否恢复
10. 给出硬件验证步骤
```

如果第 1 步没有资料支持，停止实现并标记：

```text
EVIDENCE_MISSING
```

不要“先写一个大概能用的”。

## 28. 量产前仍未关闭的事项

下面这些不是“代码错误”，而是当前资料没有给出最终产品值，必须由硬件/产品测试闭环：

- **SCD threshold / delay**：当前默认关闭；
- **DVC I2C watchdog** 是否开启以及 timeout 后 CHG/DSG 策略；
- **Current Wake (CWT)** 是否需要及阈值；
- **Body Diode recovery (BDPT + CHGC/DSGC=10 + masks)** 是否启用；
- **Core over-temperature COTT** 是否启用；
- **GP2/GP3 外部 NTC** 每个产品/BOM 是否装配；
- **SNC103B13435F0603E NTC R-T 曲线**与当前历史表的一致性；
- 20S NMC 完整 product profile；
- Open-wire 的最终软件判定算法。

没有这些输入时，AI 必须保留明确 TODO / disabled，不得自行构造“合理默认值”。

## 30. 最终开发原则

DVC1124-2 驱动后续维护的目标不是“寄存器能读写”，而是：

```text
手册定义准确
+ 板级配置明确
+ 参数量化可追踪
+ 写入可验证
+ 通信故障可恢复
+ AFE硬件保护与软件保护边界清晰
+ 低功耗/均衡/断线等状态不会形成假状态
+ 新产品只改 board/product config，不复制整套驱动
```

如果未来要抽成通用 BMS AFE 层，优先把当前实现继续演进为：

```text
bms_afe_ops
   |
   +-- dvc1124_core
   +-- sh3673520_core
   +-- sh367309_core
   +-- bq769x2_core

platform_bus
   |
   +-- stm32f0_stdperiph
   +-- stm32f1_stdperiph
   +-- telink8251
```

但任何架构重构都不得牺牲本文件已经确定的寄存器真值和硬件安全行为。
