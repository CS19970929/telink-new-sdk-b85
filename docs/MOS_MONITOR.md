# MOS 无人值守监控与证据边界

后续断线检测行为和独立监控窗口见 [OPENWIRE_MONITOR](OPENWIRE_MONITOR.md)。配套新固件的 `DIAG_BLOCK_OPENWIRE`仅表示断线故障锁存；旧固件该原因也可能表示检测过程主动隔离，需要结合版本及独立窗口分析。

2026-10-08：用户观察到 Windows MOS 指示瞬间关闭后恢复，实际负载是否中断尚未确认。
本改动增加记录证据，不改变保护、MOS 仲裁、AFE 控制、恢复、Flash、OTA 或低功耗策略。

## 记录来源与硬件依据

四产品使用同一 `bms/core/bms_diag.c`。SH 后端在 `bms_afe_diag_poll` 完整发布缓存后记录；
DVC 后端在既有主循环 `app_power_prepare_loop → bms_afe_diag_poll` 中记录。
没有额外 AFE 读取，没有 ISR 记录、动态内存、printf、主动发送或 Flash 写入。
电流及保护背景来自各自最新缓存，附采样 tick；不能假定所有字段在同一物理瞬间采集。

Windows 原指示使用 `D115` 的 `SystemStatus` bit2/3，对应缓存的充/放 MOS 状态。
SH36735XX CV1.0A 原 PDF 第 28 页定义 BSTATUS1：CHG_FET/DSG_FET 是低侧状态，
HCHG_FET/HDSG_FET 是高侧状态。第 22 页说明高侧还与 PUMP_EN 相与；第 17 页说明
MOS_EN 反向强制开启可能独立于 CHGMOS/DSGMOS。新增历史保存已读 BSTATUS1 全字节。
DVC1124-2 RM V1.2 原 PDF 第 7–8 页定义 R6 的 CHGF/DSGF 为驱动输出标志。
当前板件后缀、MOS/Gate/Vgs、负载通路和故障复现仍须实板证据，资料入口见
[AFE 使用指南](AFE_REFERENCE_GUIDE.md) 及固定提交审查。寄存器状态不是物理测量。

## 开关与保存

MOS 专用 RAM 历史与 `BMS_DIAG_TRACE_ENABLE` 共用开发开关，开发默认开启，production 禁止开启。
新增静态数组 576 字节（当前记录 64 字节、8 条历史 512 字节），另有计数等状态；实际资源以目标 MAP 为准。
不受普通 Trace 的 SOC/PM 事件覆盖。首次记录建立基线，之后请求、命令、有效性、
原因、保护或 MOS 状态发生变化才记录；SH ADC 完成位不会单独触发记录。
电流和时间变化不会单独占用历史槽。保存的是被现有采样/主循环观察到的变化，
不能保证捕获小于约 200 ms 采样周期的硬件脉冲。
普通 suspend 保留 RAM；深睡、复位、掉电清空。持续上位机读取仍走原通信门禁，影响通信活跃时间。
8 条满后覆盖最旧记录，不能替代永久故障存储。

## 新只读协议 v1

Modbus 03，`[0x3400, 0x3530)`；06/10 及跨界写入由原诊断入口拒绝。
每 word 大端，u32 低 word 在前，与旧 `0x2A00` 诊断保持一致。
旧窗口、schema、帧格式和参数布局保持。
`0x2A00` 能力新增 bit7 `0x0080`，仅历史开启时置位。

| Header 偏移（16 words） | 内容 |
|---|---|
| 0/1 | magic `0x4D48` / version 1 |
| 2/3/4/5 | enabled / 容量8 / 记录32 words / 有效条数0..8 |
| 6..7 / 8..9 | 最新 sequence / 累计覆盖数（饱和） |
| 10..11 / 12..13 | 初始化 tick32k / Build ID |
| 14/15 | AFE 型号 / 编译 flags |

`0x3410` 为最后一条变化快照，不是每次查询时的实时测量；`0x3430` 起为8个物理槽。
sequence 从1开始自然回绕，槽号 `(sequence-1) % 8`；0在回绕后是有效序号。

| 记录偏移（32 words） | 内容 |
|---|---|
| 0..1 / 2..3 | sequence / 变化记录 tick32k |
| 4/5/6/7/8/9 | requested / 软件允许 / command / command有效 / CHG、DSG报告 / driver有效 |
| 10..11 / 12..13 | 充电 / 放电阻断原因（旧 DIAG_BLOCK_* 位） |
| 14/15/16/17/18 | SH FLAG1 / FLAG2 / BSTATUS2 / backend / guard |
| 19 | 最新辅助测量有效标志 |
| 20..21 / 22..23 | 当前带符号 mA / 该测量的 sample tick32k |
| 24/25/26/27 | 三级保护位 / AFE 型号 |
| 28/29/30 | 前一条 driver / 前一条 driver有效 / 是否有前一条 |
| 31 | SH BSTATUS1 原字节，或 DVC 原 driver 缓存字节 |

主循环生产者和 Modbus 读取不交错，单请求快照完整。跨请求可能覆盖，客户端必须校验每槽 sequence，
结束复核 boot tick、Build ID 和序号方向；中途复位不推进 cursor。32K tick 约37.3小时回绕，
boot tick 不是唯一启动ID，同 build、tick、序号恰好碰撞的复位不能保证检测。
相邻读取不得超过2^31条变化；历史缺失、初次回读、时基不连续不得宣称精确物理关断时长。

## Windows 使用与判断

客户版和内部版新增顶层“**MOS 监控**”，连接后默认自动记录，文件在
`%LOCALAPPDATA%\BmsAssistant\MosMonitor\<会话>\mos_*.jsonl`，每10MiB分卷，不自动删除。
每条写入立即 AutoFlush 至操作系统；不保证电脑突然断电后的磁盘持久性。
保存完整电池背景、通信计数、上位机源状态变化、固件历史原字和断线/读取/操作缺口。
原 TX/RX 日志路径写在 start 记录内，便于关联人为指令。
窗口显示最近300条；“清空列表”不删除文件；“打开记录目录”可直接找到完整数据。
窗口必须运行且保持连接；关闭、重连/身份变化建立分段。磁盘失败明显提示并停止记录。

固件未升级时自动降级为当前 `0x2A80` 原诊断与上位机变化记录，明确提示可能漏掉轮询间变化。
关闭历史的新版固件仍读取当前诊断。无效采样、driver无效、断线和超过5秒未刷新时 MOS 灯显示未知。
有效关闭边沿与阻断原因同时出现时保存具体原因；SH 原始相关 FLAG 可提示保护关联，
但不能仅凭相关标志确定根因。请求和命令仍开而 AFE 报告关且无原因时明确显示“原因未确认”。
恢复记录可给连续监控期间的固件采样计时差；这不是示波器测得的物理关断时长。

## 2026-10-09：采样失效现场与关命令计时

冻结 D011 Build `76d5a845` 的 10 月 8 日 23:36 至 9 日 08:23 日志后，17 条固件记录中包含
启动基线和三次运行中双向关闭命令。三次阻断原因均为 `DIAG_BLOCK_COMM=0x0008`，关闭命令持续
609.5～610.75 ms，AFE 报告恢复约 804 ms；不存在断线故障锁存，PC 链路也无超时/CRC 错误。
AFE 状态无效不能抹掉有效关闭命令证据；Gate/Vgs 和负载中断仍未实测。
该旧日志没有失败步骤，不能区分 ADC 新鲜度、寄存器读取或回读校验失败。

新增开发只读扩展 `[0x3700,0x37A0)`，旧 MOS v1 保持不变。主循环在失败发生时保存现场，
在 MOS 变化记录产生时复制到相同物理槽；读取不访问 AFE、不消费 FLAG2、不写 Flash。
生产 trace 关闭时不分配扩展历史数组，enabled=0。DVC 扩展 enabled=0，不能把零值解释为诊断覆盖。
SH 仍按原保护策略处理失效，400 ms 阈值没有因诊断而放宽。

Header 16 words：0/1 magic `0x4146`/version 1；2 enabled；3/4 容量8/记录16 words；
5 有效 MOS 条数；6..7 最新 MOS sequence；8..9 boot tick；10..11 Build ID；12/13 保留；
14 AFE 型号；15 ticks/ms=`32`。`0x3710` 为最新 MOS 记录的扩展，`0x3720` 起8槽。
u32 低 word 在前，word 大端，与 MOS v1 相同。

| 扩展记录偏移 | 内容 |
|---|---|
| 0..1 | 对应 MOS sequence；客户端必须逐槽核对 |
| 2..3 / 4..5 | 累计 AFE 失效 sequence / 最近失效 tick |
| 6 / 7 | 失败步骤 / 最近底层 I/O 错误（signed16，0表示最近事务成功） |
| 8 | 本次状态读取 FLAG2；bit8=读取成功，其余高位保留 |
| 9 / 10 / 11 | VADC年龄 / CADC年龄 / 本次采样耗时，tick32k；65535为饱和值，控制阶段耗时0 |
| 12..13 / 14..15 | 故障发生前底层 CRC 失败累计 / 重试累计 |

步骤：1唤醒，2状态读取，3单体，4总压，5电流，6温度，7电流换算，8单体范围，
9 VADC超400ms，10 CADC超400ms，11负载/充电源证据读取，12短路恢复，13硬件flag恢复，
14初始化，15重配置，16保护配置，17 MOS写入/校验，18清flag失败后的隔离，19休眠，20撤销输出。
步骤9/10且I/O错误0可以将“数据超时”与“最后事务通信失败”分开；一个错误码不代表完整硬件根因。
连续异常会产生多个 failure sequence，仍受8槽覆盖和采样周期限制。恢复记录保留最近失效现场，
上位机明确标为“最近 AFE 失效”，不能将历史原因自动归因于之后的独立故障。

Windows 在“MOS 监控”显示这些现场，JSONL 的 `firmware.FailureWords` 与
`diagnostic.failureCurrent` 保存原字；跨启动/Build ID/槽序号不匹配时不关联扩展。
计数只统计连续监控期间请求仍开、有效命令从开变关；历史启动回读不累计。
分别显示关命令持续时间和 AFE 状态报告恢复时间，统一使用32000 tick/s，不能称为物理时长。
资格刚恢复且命令刚开启时显示“等待下一次状态回读”，保留当前关闭报告供核对。

显式 `--monitor-serial=COM3 --monitor-baud=115200 --monitor-mac=A4:C1:38:86:8B:DF`
可启动新版 Windows 的自动监控；读取身份不符则断开并报错，普通双击仍由用户连接。

本轮通过诊断协议、SH完整采样/guard/恢复、逐步骤读取和电芯越界的相关 host 场景，
四产品开发源码清单/TC32链接/资源检查；上位机共享客户端、扩展槽/启动校验与命令计时回归通过。
这些检查只证明软件采集/分类及资源边界；实板最终故障原因和修复需新增诊断固件持续复现确认。
