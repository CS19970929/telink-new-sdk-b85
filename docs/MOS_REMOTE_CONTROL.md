# 充放电 MOS 独立远程许可

## 目标与边界

App 和 Windows 上位机可分别禁止或重新允许充电、放电 MOS。该功能只改变用户侧 RAM 许可，不发送休眠命令，不修改 Flash/OTA/参数布局，也不绕过软件保护、AFE hardware profile、通信静默、三次有效采样资格或产品功能门禁。

“允许”表示解除用户主动关闭条件，不表示强制输出。界面必须分别显示用户许可、产品请求和 AFE 报告；只有 AFE 报告有效时才能称为驱动状态，仍不能替代 Gate/Vgs 或负载通路实测。

## 状态所有权与调用链

`bms_afe_guard.c` 的 `s_remote_off_mask` 是唯一远程许可状态：bit0 关闭充电许可，bit1 关闭放电许可。该状态只由 App/Windows/其它 Modbus 客户端的显式命令修改。`bms_afe_set_channel_allowed()` 每次只修改一个通道，再进入既有 `apply_requested()`；后者继续按以下顺序仲裁输出：

1. 产品请求 `requested_charge_on/requested_discharge_on`；
2. 远程关闭意图和 AFE 方向状态的临时放行；
3. `output_enabled`、保护参数资格、升级状态、通信隔离与总线静默；
4. 软件保护、AFE hardware profile 和产品功能方向门禁；
5. AFE backend 写入及回读。

显式关闭在 AFE 重初始化后保留，避免通信恢复过程在没有电流依据时意外重新允许；MCU reset/BSS 重建后恢复为两个通道均允许。重新允许失败时回滚到原关闭许可；禁止写入失败时保留 fail-safe 关闭意图并返回设备故障。许可发生变化后立即把旧 AFE 报告标为无效，等待后续真实回读。

远程单管关闭不得让同口反向电流长期流经体二极管，也不能丢失用户的关闭意图。公共 guard 读取所选后端的方向状态并执行临时放行：

- 充电 MOS 被用户关闭而 AFE 确认放电时，充电 MOS 临时按产品请求参与正常仲裁；
- 放电 MOS 被用户关闭而 AFE 确认充电时，放电 MOS 临时按产品请求参与正常仲裁；
- 方向状态消失后，下一次仲裁重新执行仍然保留的用户关闭意图，对应 MOS 自动关闭；
- 用户在临时放行期间再次写入关闭仍返回成功，许可寄存器保持 `0`，不会把临时放行固化为允许；
- 临时放行只覆盖对应通道的用户关闭条件，不能绕过参数、通信、三次采样资格、软件保护、AFE hardware profile、双向保护阻断和产品门禁。

SH36735XX CV1.0A 原 PDF 物理页 22-23 明确定义 `BSTATUS2.CHGING/DSGING` 的进入和退出条件。D011、D013、D014 直接使用最新有效 `BSTATUS2`：`DSGING` 临时放行充电 MOS，`CHGING` 临时放行放电 MOS。

DVC1124-2 RM V1.2 原 PDF 物理页 7-8 没有与 `CHGING/DSGING` 等价的持续方向位；它定义 `CC2F` 为新转换标识，`CC2[19:0]` 为有符号二进制补码，正值放电、负值充电。D008 因而只在 `CC2F=1` 的新鲜 `CC2` 样本中更新方向：校准后的公共电流严格大于 `+200 mA` 临时放行充电 MOS，严格小于 `-200 mA` 临时放行放电 MOS，进入 `±200 mA` 死区便清除临时放行；ADC 缓存等待保持上一方向，通信/快照无效立即清除。`R6.CHGF/DSGF` 只是驱动输出报告，`CST` 是唤醒/命令状态，均不作为持续充放电方向来源。

## Modbus 窗口 v1

窗口为 holding register `[0x2F10, 0x2F18)`，word 大端。读取使用功能码 `0x03`。

| 地址 | 访问 | 内容 |
|---|---|---|
| `0x2F10` | R | magic `0x4D43` (`MC`) |
| `0x2F11` | R | version `1` |
| `0x2F12` | R/W | 充电用户许可，`0` 禁止，`1` 允许 |
| `0x2F13` | R/W | 放电用户许可，`0` 禁止，`1` 允许 |
| `0x2F14` | R | AFE 报告 bit0 充电、bit1 放电 |
| `0x2F15` | R | AFE 报告有效且采样已取得资格时为 `1` |
| `0x2F16` | R | guard 诊断位：输出授权/通信隔离/总线静默/故障锁存/采样资格 |
| `0x2F17` | R | 产品请求 bit0 充电、bit1 放电；未应用远程许可 |

功能码 `0x06` 只允许写 `0x2F12/0x2F13`，值只能是 `0/1`；其余地址只读。功能码 `0x10` 的单 word 请求沿用现有单写分派，多 word 写入拒绝。反向电流临时放行期间写 `0` 仍记录并读回用户关闭意图；此时 `0x2F14` 的有效 AFE 报告可以显示该 MOS 已按安全策略导通，方向消失后自动关闭。广播地址 `0` 对整个窗口不执行任何副作用，避免多台设备同时切换 MOS。旧固件返回非法地址时客户端只禁用独立控制，不影响实时数据读取。

`DIAG_BLOCK_REMOTE=0x0800` 记录用户关闭意图；临时放行期间它可以与有效的 AFE 导通报告同时存在，用于明确区分“用户希望关闭”和“当前因反向电流临时导通”。既有原因位和历史布局保持不变。

## 验证边界

本轮按用户要求只修改和审查源码，未执行 host 回归、`sources --check`、目标链接、资源检查、Windows/Android 编译、实板切换、烧录或 OTA。更新的 host 场景覆盖独立通道、重初始化保留、允许失败回滚、用户关闭意图持续保留、两个方向的临时开通、方向消失后自动恢复关闭，以及协议读写、只读地址、值域和广播无副作用；本轮未运行。DVC 的 `CC2F/CC2` 边界和 SH 的 `BSTATUS2.CHGING/DSGING` 映射仍需在后续获准验证时执行对应 host 和四产品链接检查。

最终验收还需四产品分别观察：命令写入和读回、保护阻断、通信丢失恢复、AFE 报告有效性，以及 Gate/Vgs 和真实负载通路。寄存器状态不能替代物理关断证据。
