## 阶段三：业务毫秒时间

- bms_time 在平台 clock_init 后建立基准，由主循环上下文消费原始 tick 无符号增量；每轮主循环至少更新一次，保留不足 32 tick 的余数。普通 Suspend 后累计经过时间，冷启动/DeepSleep 重启重新建立基准。
- 原始 tick 单次回绕约 37 小时，消费间隔必须短于该窗口；毫秒计数自然回绕约 49.7 天。先对增量取商余，避免接近 UINT32_MAX 的增量和余数相加溢出。
- AFE 活性、Guard、硬件恢复等待、PM、UART 30秒、参数事务、State/Event 和平台写失败退避均使用毫秒。DVC 均衡续期保留45秒、SH保留20秒；微秒总线和 UART 帧间隔仍使用 SDK。
- sample_time_ms 独立于 sample_tick_32k；SH 的原始 ADC 年龄戳只在服务诊断编译中保留。采样时间、失败年龄、Flash耗时、日志及参数寄存器的 32K 字段仍来自原始时钟。
- 硬件最短稳定等待和 watchdog 静默采用 elapsed > delay_ms，保守覆盖最多不足1ms量化误差；实际动作仍由下一轮主循环/采样触发。命令应答上限仍为500ms。
- 调度夹具增加真实平台累计函数的余数、原始回绕、毫秒回绕、Suspend跨度和最短等待场景；更新相关业务时间夹具。未执行测试或编译。

## 阶段四：SOC 毫秒积分

- SOC 输入新增 timestamp_ms，用真实应用时间差积分；timestamp_32k 仅为已有诊断/板测记录保留。无效区间、重复毫秒、超过400ms间隔、方向切换余数重置沿用原有处理。
- 分母由3200000改为100000 mA*ms/As10。幅值先拆商余：整商乘积最大8589600，余数乘积加历史余数最大40099599，覆盖 INT32_MIN 且不依赖64位乘除。删除1024 tick分块循环。

- 更新独立64位整数参考夹具、毫秒回绕行为轨迹，以及旧32K CSV的增量/余数时间适配。旧CSV格式和原始诊断字段保持不变；未运行夹具、编译或轨迹比较。

## 正常调度耗时核对：源码证据，不是运行测量

用户要求先查清正常调度耗时，本轮暂不改变积分规则。必须区分三种不同时间：200ms 是应用目标采样周期；DVC 512ms / SH 400ms 是各后端 ADC 活性窗口；SOC 400ms 是既有应用输入间隔限制。不能用同一个“有效期”描述三者。

### 期限与执行顺序

`app.c::app_sample_task()` 在执行采样前记录 s_sample_tick，SDK 下一期限为该起点加200ms，回调仅置 s_sample_due。每轮最多一次采样；采样本身超期只置待处理标志，下一轮继续，未实现补跑历史样本。正常主循环为 BLE → 采样/保护/Guard/功能/MOS/SOC → State/Event → D008 总线任务 → Modbus → PM。

这确认了期限不是“执行结束后再等200ms”，但协作调度本身不等于硬实时保证：这些同步工作完成后才能进入下一轮。没有当前运行轨迹证明正常主循环会停顿2秒，之前讨论的2秒只是示例，不能作为保留400ms规则的事实依据。

### 无重试、无故障的基础总线传输

| 路径 | 源码计算依据 | 可确认的范围 |
| --- | --- | --- |
| D008 DVC 主测量读取 | dvc1124.c 配置100kHz；0x00..0x4C共77个寄存器，每个数据字节附CRC；地址/寄存器阶段3字节，约 `(154+3)*9/100000` | 约14.13ms纯总线时钟；不含START/STOP间隙、CPU、额外均衡读取/命令和保护处理 |
| D011/D013/D014 SH 状态及测量 | sh3673520_port.c 固定500kHz；每次读取额外5字节；状态3次、单体/总压/电流/温度4次，合计 `2*N+51` 字节 | 默认10S约1.136ms、8S约1.072ms纯移位时间；另有每事务15us片选等待、SCONF3读回、按需C+及功能命令和CPU开销 |

这些数字只是主读取的传输量估算，不是整轮耗时、平均耗时或最坏耗时。DVC 的5ms限制针对单个I2C命令，SH 的1ms限制针对单字节交换，均不能直接当作完整事务上限。失败重试须另算，不能混入上述健康路径。

### 会同步占用主循环的独立路径

- **正常持久化活动**：State/Event checkpoint 及参数提交可调用 bms_storage_platform_telink.c 的同步写页/擦扇区。SDK B85 flash.c 的 flash_mspi_write_ram 关闭中断，调用 flash_wait_done 后才恢复；后者先等待100us，再最多轮询10000000次。该循环次数不是墙钟时间上限。当前未取得具体Flash料号的最坏写擦时间及本板运行测量，因此不能证明持久化轮次一定小于200ms或400ms。
- **AFE故障恢复**：DVC 初始化有接口20ms、唤醒1ms、复位20ms及300ms稳定等待，另有配置及零点资格等待（两个新CC2样本，各270ms等待）。这条路径显然可能超过200ms，但它属于初始化/故障恢复，Guard 已禁止输出；等待期间 SOC 收到无效输入，不需要把它包装为正常调度耗时。
- **其他主循环工作**：BLE SDK 主循环及通信/功能处理尚无整轮最坏耗时证据。UART 的发送超时由轮询判定，不应将该阈值误当作每轮阻塞延时。SH 检测模式稳定等待使用时间戳，不是每轮阻塞200ms。

### 本轮结论与证据缺口

源码已经分清主要基础传输与同步占用路径，没有证据将200ms目标宣称为所有场景都满足，也不能据此宣称正常调度已经有确定故障。400ms积分规则按用户决定保留，未用新阈值掩盖这些路径。

实际耗时仍需另行授权运行验证：至少分别记录无Flash正常轮次、State/Event提交和擦除轮次、通信活动轮次的采样起始间隔与任务耗时；故障重初始化单独统计。现有Flash诊断中的 max_program_ticks_32k / max_erase_ticks_32k 保持原单位，但本轮未读取实板数据。软件测试、目标链接和实板 Gate/watchdog/睡眠电流/唤醒/Flash掉电验收均未执行，不能用历史结果代替。

## 后续减法：Event 直接累计毫秒区间

Event 原来维护 interval_s、clock_tick_ms、clock_fraction_ms，推进时拆商余，追加事件时又清余数。本轮改为 interval_ms 与 clock_tick_ms，删除单独余数及重复复位；上次轮询时间仍独立保留，因为追加新事件会清空区间，而未追加时须继续累计。

上限为 `(168*3600+1)*1000 = 604801000`，小于 UINT32_MAX；先比较 delta 与剩余额度，未到上限才相加，长间隔不发生加法溢出。生成事件时间码和判断合并时仍按完整秒取整，因此60.999s仍属于原来的“完整秒<=60”，61.000s才追加；168h+999ms仍为168，168h+1s为170。新事件将整个毫秒区间归零，等价保留旧代码丢弃不足一秒余量的规则；合并事件不清区间。

仅修改运行RAM计时，不改记录编码、schema 4、Flash布局、上升沿、合并资格、保存顺序及失败重试。更新共享存储夹具，明确回绕、500ms累积、合并临界、新事件丢余量及饱和场景；未执行测试、编译、链接或实板验证。

### 用户明确的时间精度取舍

业务计时允许小误差，不为历史记录、普通倒计时增加精密补偿。Event 的不足1秒舍弃仅影响相邻历史事件的时间码，不影响独立 SOC 或休眠计时；粗时间码保持即可。SOC 仍保留实际时间差及积分余数，400ms区间规则按本轮既定决定不变。休眠重点是到期可执行、强制入口不被通信或保存永久阻断；硬件规定的最短等待与 watchdog 静默仍须满足。不要把“统一毫秒单位”误解为所有业务都需要毫秒级精度。

## 后续减法：AFE 配置提交与回滚共用应用核对

续做基线为 `fb613ec1`，现有分支、开始时工作区干净；四产品 sources.txt 均编入 bms_afe_hw_profile.c。只整理公共事务，未改两个后端的寄存器访问、量化、默认值、配置成功判据或 Guard。

- 将提交与回滚重复的“应用后端 → 读取请求 → 比较请求字段 → 取得有效值”收敛为私有 `afe_hw_profile_apply_verified(expected)`；请求比较完成后复用局部缓冲取得有效值。硬件有效值不与请求逐字比较，保留量化差异及既有 SH 温度读回限制。
