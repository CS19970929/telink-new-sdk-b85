# 断线检测：不主动关 MOS 与上位机监控

2026-10-08 实施。用户明确约定：**检测过程不关 MOS，真实故障仍保护关断**。本文件是当前实施说明；[调研报告](OPENWIRE_RESEARCH_AND_DESIGN.md)记录固定旧基线和原厂资料，不能把其中旧关断逻辑当作当前行为。

## 行为和所有者

- `bms_features`拥有资格、周期、超时、退避、结果及断线保护锁存；后端拥有激励、阶段、原始数据和退出校验。`openwire_latched_mask` 是已确认故障的唯一状态，非零即阻断，不另存必须同步维护的布尔锁存。最近结果可被失败检测替换，不能用它代替已锁存掩码。
- `bms_afe_openwire_start()`只停止均衡、启动激励，不写 FET。`openwire_active`不再属于双向阻断条件或 `DIAG_BLOCK_OPENWIRE`原因。新固件的该原因位只表示已锁存断线检测故障；旧固件该位也可能来自检测过程。
- 正常无电流、无加热请求、保护资格允许时才开始。首次启动等待 10 秒，再累计约 10 秒有效空闲样本；正常完成后等待 300 秒，再重新取得空闲资格。可疑测量、故障、失败在 10 秒退避后重检，不能绕过退避。
- 检测中出现电流、加热请求或安全资格变化时终止并记原因，不据此确认断线。没有有效结果、缺阶段、超时、启动失败均不置健康，也不清除旧断线锁存。
- 完整有效的非零检测掩码锁存双向保护，完整有效健康结果且退出校验成功才能解除该锁存。原有软件保护、AFE 硬件保护、参数、输出授权和通信门禁继续仲裁，健康结果不会直接强制开 MOS。
- 清理失败保留待清理状态。**单纯检测超时不主动关 MOS；退出激励的真实 AFE I/O 失败按既有通信故障处理，可保护关断，并保留 watchdog 总线静默和三次有效新样本恢复资格。** 待清理尚未回读确认时，即使通信已取得三次样本资格，也继续以 `DIAG_BLOCK_COMM`保持安全阻断；不能把未停止激励的采样当恢复证据。总线静默期不访问 AFE；重新取得访问资格后按退避重试清理。
- AFE 重初始化保留已锁存断线故障、原始结果和本次 MCU 启动的累计计数；MCU 重启、掉电或深睡唤醒后的冷启动会清 RAM。

## DVC 与 SH 的不同实现

依据及型号版本见 [AFE_REFERENCE_GUIDE](AFE_REFERENCE_GUIDE.md) 和调研报告的原 PDF 页码。

| 后端 | 本次实现 | 实板边界 |
|---|---|---|
| DVC1124-2 | 保留既有 200 ms 稳定等待；900 ms 内必须取得 COW 有效时的新 VADC。诊断单体单独存入结果缓冲，普通单体/min/max/压差/协议包电压保留正常值。只清 COW，保留 charge pump，退出回读。 | 200 ms 对实装 RC/噪声是否足够、零码判据、端点和相邻断线仍待验证。 |
| SH3673510 | 启动先消费旧 FLAG3 完成标志；记录 IND=0/1 两阶段原始 OWD 掩码，完整覆盖才接受结果；最多 3 次完成阶段，2.5 秒墙钟上限；退出 OWD_EN 回读。 | 手册 p16 示例与 p44 位编号冲突，维持既有示例映射。映射外异常返回不确定，不能报健康或解除旧故障；不能声称全部通道已确诊覆盖。需逐路实板确认。 |

公共 3 秒上限是软件兜底。上述上限是项目超时约束，不是原厂转换时长保证。检测期间以及最后诊断帧不推进软件电芯/包电压、压差保护的触发或恢复滤波，也不清原有故障；电流、温度、硬件保护继续运行。SH 同样暂缓发布普通电芯/包电压。只有新的完整采样才推进 feature，缓存等待不能消费诊断帧标志。SOC 继续使用已有 Open-Wire 样本质量门禁。

检测过程不禁用 AFE 硬件保护。软件没有诊断关 MOS 命令，不代表已证明所有板子在检测期间物理 Gate 无瞬态；需示波器确认激励、AFE 硬件保护、MOS Gate/Vgs 和负载电流。

## 只读协议

独立窗口 `0x3600..0x362F`，48 words，magic `0x4F57`，schema 1，能力位 `0x0100`。沿用 Modbus 03；06/10（包括跨边界写入）拒绝。既有地址、CFG2、Flash/OTA 布局和物理量缩放不变。每 word 在线路上 big endian，u32 为低 word 在前。

| offset | 内容 |
|---|---|
| 0/1/2 | magic / schema / 后端：1 DVC，2 SH |
| 3 | 状态：0 等待，1 检测，2 最近健康，3 断线故障，4 检测失败，5 待清理 |
| 4 | bit0 active，bit1 suspected，bit2 断线故障锁存，bit3 待清理，bit4 当前/最近结果 valid，bit5 determinate |
| 5 | 当前错误：0 无，1 启动，2 I/O，3 超时，4 不完整/映射不确定，5 清理，6 样本失效，7 资格变化中止 |
| 6..7 | 状态/阶段序号，主循环更新 |
| 8..9 | 快照更新时间 tick32k |
| 10..11 / 12..13 / 14..15 | 最近开始 / 结束 / 健康完成 tick32k |
| 16..17 / 18..19 / 20..21 | 启动尝试 / 有效完成 / 失败计数 |
| 22..23 | 已锁存故障掩码；错误、不确定和重新初始化不能清除 |
| 24..25 | 正在运行或最近结果掩码，不能单独当作保护锁存 |
| 26..27 / 28..29 | SH 原始 IND=0 / IND=1 掩码；DVC 为零 |
| 30 / 31 | 阶段覆盖：SH bit0 IND=0、bit1 IND=1，DVC bit0 完成 / 有效电芯数 |
| 32..33 / 34..35 | 周期/退避剩余 ms / 活动检测已用 ms；剩余为零仍可能等待空闲资格 |
| 36..37 / 38 | 最近失败 tick32k / 最近失败错误；后续健康完成仍保留 |
| 39 | 暂不具备资格：bit0 有电流，bit1 加热请求/运行，bit2 硬故障，bit3 均衡退出/回读错误 |
| 40..41 / 42..43 | 正常周期 ms / Firmware Build ID（0 不可用） |
| 44..45 / 46..47 | 读取时 tick32k / 最近一次检测用时 ms |

SDK tick 按 `32000 ticks/s`，无符号差值跨一次回绕；不能仅凭一个 tick 推断多次回绕后的绝对日期。读取是主循环 RAM 快照，不访问 AFE，不推进检测。计数和最近结果不构成全部事件历史。

## Windows 使用与无人值守记录

客户版和内部版都默认显示“断线检测”页，无需开发解锁。连接后保持电池实时轮询，“自动监控并写盘”默认开启，和 MOS 监控共用开关、连接分段、取消和 OTA 暂停机制。

页面显示检测/故障区别、可疑状态、计数、退避、耗时、失败原因和原始阶段掩码。旧固件显示“不支持”，通信中断、暂停或超过 5 秒未刷新显示当前状态未知。

每次成功读取的 48 个原始 words 自动写入 `%LOCALAPPDATA%\BmsAssistant\MosMonitor\<session>\mos_*.jsonl`，`kind=openwire`；读取失败/暂停写 `openwire-gap`，MOS 背景仍按原监控记录。通过“MOS 监控 → 打开记录目录”找到文件。文件保留 UTC、接收段、采样编号及原始 tick，可与固件 MOS 原因、请求、命令和 AFE 状态对照分析。列表只显示最近 300 次变化，文件持续分卷、无自动删除。

“诊断 → 读取完整诊断 → 导出 AI 诊断包”以及 CLI `diag --json`/`--output`包含 `EvidenceBlocks.OpenWire`。AI 可直接分析 JSONL 或 ZIP 的原始数据。两次轮询间可能完成多个检测，计数提示覆盖缺口，不能恢复中间已覆盖的原始原因；断电/重启不会把 RAM 快照恢复为完整历史。

量产可保留这份小型 RAM 快照和计数，不写 Flash、不打印、无动态分配；详细 trace/runtime log 仍遵守量产关闭约束。新增静态 RAM、栈及执行时间尚未通过目标 MAP/水位验证，不能把“小型”称为资源验收通过。
