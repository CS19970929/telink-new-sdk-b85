# D008 过流与短路恢复策略

2026-09-17 用户确认：CHG_IN_PIN / PB1 仅在放电驱动关闭时判断负载；低=负载在，高=负载移除。软件三级与硬件过流共用以下恢复门禁，一级/二级软件告警保持原算法。

| 保护 | 恢复条件 |
|---|---|
| 软件三级放电过流、AFE OCD1/OCD2、SCD | 有效 AFE 样本 DSGF=0 且 PB1 连续高至少 200 ms，或者可靠充电电流连续至少 200 ms |
| 软件三级充电过流、AFE OCC1/OCC2 | 从首次发现故障计时至少 30 s，软件触发状态已解除，硬件告警清除/读回成功 |

200 ms 为本次软件去抖选择，实板需验证干扰及电路稳定时间。充电证据使用有效原始电流 `current_ma < -BMS_CURRENT_UNRELIABLE_MAX_MA`；目前不可靠区间为 ±200 mA，因此要求充电电流大于 200 mA。充电请求、CHGF、PB1 均不能单独作为充电证据。不同恢复证据切换时重新计时；无效采样、高低电平抖动或 DSGF=1（且无充电证据）中断负载移除确认。

## 实现与边界

- `dvc1124_bms.c` 是 D008 运行期间恢复锁存的唯一 owner。每次先运行公共软件保护，再接收独立软件 Third 和 AFE alarm，最后合并输出故障。
- 三级软件电流状态仍按原阈值/Filter 解除，但最终输出故障由新增门禁保持，不能因关 MOS 后电流归零而重新开通。
- 单侧放电故障保留 CHG ON + DSG AUTO_DIODE；充电仍须满足充电侧其他门禁。允许可靠反向充电解除放电过流/短路。禁止把 AUTO_DIODE 或 DSGF 当作物理 MOS 反馈。
- 充电过流保持原单侧反向放电续流能力；30 s 到期只解除本项阻断，不能绕过其他保护、通信资格、参数门禁或显式 OFF。
- 硬件电流告警在 RAM 独立保留；AFE reinit 即使清空寄存器也不解除锁存。W1C 或回读失败继续保持，回读仍有对应告警也不解除。
- 用户明确本轮不要求 MCU 复位/ACC 深睡眠唤醒后保持锁存：不新增 Flash 写入，MCU 启动沿用既有策略。此处不能声称跨复位锁存。
- 不改变寄存器地址、参数 Flash 格式、阈值或固定硬件策略。旧 profile 中 OCD/SC recovery 参数不决定本策略；OCC recovery time 固定 30 s，旧 Requested 数值不覆盖它。上位机旧“有效值”恢复参数列不能视为当前恢复策略，后续 UI 应明确标注。
- Trace 新增 event 10：arg0 bit0=充电锁存、bit1=放电锁存；arg1 bits0..7=alarm，bit8=PB1高，bits16..23=AFE status，bits24..31=恢复证据（0无/1负载移除/2充电）。仅锁存状态变化记录。
