## 当前确认的资料转写问题

### LIB-BQ-01 [P2] BQ SHIP 的中文顺序把两次写误写为三次写

- 位置：`chips/bq769x0/reference.md:471`，第 9 节：先为 `00`，随后“连续两次写01，再写10”。这句话表示 `00 -> 01 -> 01 -> 10`。

- 原文：`sources/BQ76940.pdf`，SLUSBK2F，p31 上半页与 p35 SHUT_A/SHUT_B 字段说明。原文总共两次连续写：Write #1 `[SHUT_A]=0,[SHUT_B]=1`；Write #2 `[SHUT_A]=1,[SHUT_B]=0`；执行前两位为 0。因此规定顺序为 `00 -> 01 -> 10`。

- 原图证据：[BQ76940-p031.png](BQ76940-p031.png)。该页已实际打开视觉复核；p35 文本独立重提取。JSON 的 `SYS_CTRL1.SHUT_B` 已正确写成“从00连续写01再10进入SHIP”，说明问题位于中文参考。

- 影响：开发者按该句增加一次 `01`，违反原文规定序列；不能据此声称可靠进入 SHIP，可能导致预期关机/仓储功耗行为不成立。未对器件实测，不能断言所有硅版本收到此错误序列必然拒绝最后的 `01->10`。此问题也不自动等于四产品驱动缺陷，当前产品是否使用 BQ 独立确认。

- 建议：改成“初态 `SHUT_A/B=00`，连续两次写，第一次 `01`，第二次 `10`”；给出逐事务表，并核对 JSON 与中文流程一致。

- 验证：资料回归检查流程只允许两次命令写且顺序一致；有 BQ 实板时抓 I2C 波形，并分别测规定序列与重复 `01` 序列的 REGOUT/功耗状态。原厂对额外写的容错行为未明确，不自行补规定。
