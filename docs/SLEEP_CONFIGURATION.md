# 两档休眠配置与固定过放休眠

2026-10-13，适用 D008 / D011 / D013 / D014。实现基于本次修改前 `e82b83f1` 源码；未执行测试、编译、EXE 发布、BIN 生成或实板验证。

## 运行策略

删除原 `<2550 mV / 1 小时` 的独立分段。取有效串中的最低单体，只有两档可配置电压：

| 条件 | 延时 | 有效恢复 |
|---|---|---|
| 最低单体低于下档电压 | 下档分钟数 | 新鲜有效样本确认最低单体不低于下档 |
| 最低单体低于上档电压，且没有可靠充电（电流 `>=-200 mA`） | 上档分钟数 | 新鲜有效样本确认电压恢复，或电流 `<-200 mA` |
| AFE1 报错或无法取得新鲜有效测量 | AFE 异常分钟数 | AFE1 清除且测量新鲜有效 |
| 三级单体欠压或总压欠压保护一直未恢复 | 固定 **180 秒**，上位机不能修改 | 两个欠压位都清除、AFE 无错、测量新鲜有效，且单体及总压均达到现有软件欠压恢复阈值 |

四项分别累计，显示并执行最早到期项。同一时间到期时，过放原因优先显示。
下档不排除充电；上档的无可靠充电计时同时覆盖下档，避免跨档丢掉其连续资格。
无新鲜测量时保持最后确认的低压条件；已确认的过放也继续计时，AFE 重新初始化或欠压位暂时清零不能冒充恢复。
保存新配置不会重置已累计时间，新的阈值在下一轮有效采样评估，新的延时在下一轮电源决策生效；缩短到已累计时间以内可能立即关机。
这些计数是本次启动的 RAM 状态，不跨 MCU reset 或断电累计。

固定 3 分钟是额外保护条件；其它条件可以先到期。D008 当前默认下档仍为 **2800 mV / 1 分钟**，因此过放时可能先按下档关机；如需观察固定 3 分钟条件，应将下档延时设为更长。D011/D013/D014 下档默认 2800 mV / 60 分钟。四产品上档默认 3000 mV / 1440 分钟、AFE 异常默认 30 分钟。范围校验是接口与运算边界，不代表所有组合都适合具体电池。

到期动作保留原实现：撤销输出，尽力通知 AFE 并保存 State/Event；D008 最后拉低 PC4 请求关闭 MCU 供电，SH 进入 MCU deep sleep。通信、OTA、保存或 AFE 命令失败不取消已到期的保护性动作。普通 Suspend、开关/ACC、显式命令及唤醒配置不变。

## 上位机与协议

配套 Windows 源码位于 `feature/windows-afe-hw-protection-editor-v2`，本次独立提交 `11747818749d3116aba08e67d56f1a1b24fd751e`。上位机原有其它未提交修改保留，本次没有生成 EXE。

Windows 客户版和内部版共用“业务参数 → 保护性休眠参数”。读取设备值后编辑五项，整组保存并读回；提供单独的休眠默认值恢复。原业务默认恢复和 OTA 分组更新不覆盖已保存的独立休眠配置。

参数协议仍为 v2，`0x2E02` capability bit7 (`0x0080`) 声明支持。旧固件没有此位，上位机禁用编辑。现有地址、缩放、字序和功能码不变；增加以下原未分配地址：

| 地址 | 含义 |
|---|---|
| `0x2E90` | 下档单体电压，mV |
| `0x2E91` | 下档延时，整数分钟 |
| `0x2E92` | 上档单体电压，mV |
| `0x2E93` | 上档无可靠充电延时，整数分钟 |
| `0x2E94` | AFE 异常延时，整数分钟 |
| `0x2E98..0x2E9C` | 同顺序的编译默认值，只读 |

读使用 03；写仅接受 10 从 `0x2E90` 开始的完整五 word，19-byte 请求适配原 20-byte BLE payload。拒绝单项写、部分组、越界组及默认区写入。每个 word 大端；延时范围 1～65535 分钟，`1000 <= 下档mV < 上档mV <= 4500`，下档延时不得大于上档延时，不开放 0/关闭。最大延时 3932100000 ms 可装入现有 u32 诊断字段。过放 180 秒不是可写参数。

实时休眠诊断 `0x3300` schema 1 增加原因 **8：过放未恢复**；原原因 4 保留用于旧固件解码，新固件不再产生。原因 5/6/7 与原含义对应。配套更新上位机才能解码原因 8。

## 持久化与兼容

`bms_sleep_config.c` 拥有五个配置值及独立 journal；`app_power.c` 只拥有运行计时。沿用现有 Flash 端口、CRC32、序号、最后提交、写后验证及有限失败预算。保存成功才发布 RAM 候选；相同已保存参数不再写 Flash。只在启动加载，getter 和诊断读取不访问 Flash。

既有 Config/State/Event、CFG2 322 bytes/schema 3、SN/校准、OTA 标记和 APP/SDK 边界均不移动。新增记录 magic `SLP1`、schema 1、10-byte payload，4-byte 对齐后的槽为 44 bytes；两个 4 KiB sector，各 93 槽，在原未分配区轮换：

| Flash | 新参数区域 |
|---|---|
| 512 KiB | `0x5C000..0x5DFFF` |
| 1 MiB | `0xCC000..0xCDFFF` |
| 2 MiB | `0x1CC000..0x1CDFFF` |

空白使用当前产品默认，不因读取默认值写 Flash。损坏、未知版本或语义无效记录使用默认继续保护性决策并报存储错误，只在用户显式整组保存后建立有效记录，避免首次写中断导致永久无法配置。I/O 读取错误则拒绝本次启动中的保存，不能当成空白写入。旧固件不识别新增区域；回刷旧固件使用其原编译休眠策略。
