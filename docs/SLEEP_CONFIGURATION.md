# 两档休眠配置与固定过放休眠

2026-10-13，适用 D008 / D011 / D013 / D014。本次后续调整移除AFE时间编辑并固定30分钟，重命名上位机字段；下述首次实现的验证状态仅指当时。实现基于本次修改前 `e82b83f1` 源码；未执行测试、编译、EXE 发布、BIN 生成或实板验证。

2026-10-14补充：D008 ACC现也强制提交深睡，取消通信/保存/AFE成功门禁和失败退避；两档参数及本文持久化规则保持，详见 [完整休眠梳理](SLEEP_LOGIC_REVIEW.md)。本次未执行测试或编译。

## 运行策略

删除原 `<2550 mV / 1 小时` 的独立分段。取有效串中的最低单体，只有两档可配置电压：

| 条件 | 延时 | 有效恢复 |
|---|---|---|
| 最低单体低于下档电压 | 下档分钟数 | 新鲜有效样本确认最低单体不低于下档 |
| 最低单体低于上档电压，且没有可靠充电（电流 `>=-200 mA`） | 上档分钟数 | 新鲜有效样本确认电压恢复，或电流 `<-200 mA` |
| AFE1 报错或无法取得新鲜有效测量 | 固定 **30 分钟**，不可在线配置 | AFE1 清除且测量新鲜有效 |
| 三级单体欠压或总压欠压保护一直未恢复 | 固定 **180 秒**，上位机不能修改 | 两个欠压位都清除、AFE 无错、测量新鲜有效，且单体及总压均达到现有软件欠压恢复阈值 |

四项分别累计，显示并执行最早到期项。同一时间到期时，过放原因优先显示。
下档不排除充电；上档的无可靠充电计时同时覆盖下档，避免跨档丢掉其连续资格。
无新鲜测量时保持最后确认的低压条件；已确认的过放也继续计时，AFE 重新初始化或欠压位暂时清零不能冒充恢复。
保存新配置不会重置已累计时间，新的阈值在下一轮有效采样评估，新的延时在下一轮电源决策生效；缩短到已累计时间以内可能立即关机。
这些计数是本次启动的 RAM 状态，不跨 MCU reset 或断电累计。

固定3分钟是额外保护条件；其它条件可以先到期。一级对应较低电压条件，不排除充电；二级对应较高电压且无可靠充电条件。四项当前编译默认以各产品 `bms_product.h` 为准，现有设备以实际保存值为准。一级延时若小于3分钟，可能先于过放条件关机；AFE异常时间固定30分钟。范围校验是接口与运算边界，不代表所有组合都适合具体电池。

到期动作保留原实现：撤销输出，尽力通知 AFE 并保存 State/Event；D008 最后拉低 PC4 请求关闭 MCU 供电，SH 进入 MCU deep sleep。通信、OTA、保存或 AFE 命令失败不取消已到期的保护性动作。普通 Suspend、开关/ACC及唤醒配置不变。2026-10-13 起显式命令也复用强制入口，应答空闲即执行，等待最多500ms；不受持续一线通接入或保存/AFE失败阻止，见 [休眠策略](LOW_POWER_POLICY.md)。

## 上位机与协议

配套 Windows 源码位于 `feature/windows-afe-hw-protection-editor-v2`，一级/二级名称及AFE编辑移除提交 `c20b8ddc062299ab1ea2dc4ccdd53acd00b9b406`（初版 `11747818`）。上位机原有其它未提交修改保留；最新EXE及构建结果以 `releases/bms-tool-windows/` 对应发布manifest为准。

Windows 客户版和内部版共用“业务参数 → 自动休眠设置”。显示“一级休眠电压/延时”和“二级休眠电压/延时”四项，整组保存并读回；AFE异常时间不显示编辑控件，固件固定30分钟。提供单独的休眠默认值恢复。原业务默认恢复和 OTA 分组更新不覆盖已保存的休眠配置。

参数协议仍为 v2，`0x2E02` capability bit7 (`0x0080`) 声明支持。旧固件没有此位，上位机禁用编辑。现有地址、缩放、字序和功能码不变；增加以下原未分配地址：

| 地址 | 含义 |
|---|---|
| `0x2E90` | 下档单体电压，mV |
| `0x2E91` | 下档延时，整数分钟 |
| `0x2E92` | 上档单体电压，mV |
| `0x2E93` | 上档无可靠充电延时，整数分钟 |
| `0x2E94` | 保留的旧 AFE 时间槽，读回恒为30；不允许修改 |
| `0x2E98..0x2E9C` | 同顺序的编译默认值，只读 |

读使用 03；写仅接受 10 从 `0x2E90` 开始的完整五 word，19-byte 请求适配原 20-byte BLE payload。拒绝单项写、部分组、越界组及默认区写入。每个 word 大端；延时范围 1～65535 分钟，`1000 <= 下档mV < 上档mV <= 4500`，下档延时不得大于上档延时，不开放 0/关闭。最大延时 3932100000 ms 可装入现有 u32 诊断字段。为保持旧记录及协议布局，五 word 的最后一项由客户端固定发送30，固件拒绝其它值；过放180秒和AFE异常30分钟均不是可写参数。固定 AFE 时间不再写入 Flash，协议末槽继续固定 30。

实时休眠诊断 `0x3300` schema 1 增加原因 **8：过放未恢复**；原原因 4 保留用于旧固件解码，新固件不再产生。原因 5/6/7 与原含义对应。配套更新上位机才能解码原因 8。

## 源码默认值入口

各产品的 `bms/products/<product>/bms_product.h` 中四个宏控制首次默认及“恢复休眠默认设置”的值：

| 宏 | 界面名称 | 源码单位 |
|---|---|---|
| `BMS_SLEEP_LOW_CELL_MV` | 一级休眠电压 | mV |
| `BMS_SLEEP_LOW_SECONDS` | 一级休眠延时 | 秒，须为60的正整数倍 |
| `BMS_SLEEP_NORMAL_CELL_MV` | 二级休眠电压 | mV |
| `BMS_SLEEP_NORMAL_SECONDS` | 二级休眠延时 | 秒，须为60的正整数倍 |

D008入口是 `bms/products/d008/bms_product.h`。设备已保存的四项仍优先使用，修改源码默认不会覆盖；使用上位机“恢复休眠默认设置并读回”或显式保存新值才更新。固定AFE时间在 `bms/core/bms_sleep_config.h` 的 `BMS_SLEEP_AFE_FIXED_MINUTES`（30）；固定过放时间在 `bms/app/app_power.c` 的 `APP_OVERDISCHARGE_SLEEP_SECONDS`（180）。

## 持久化与兼容

2026-10-17 已将四项休眠参数合入 Config/schema 4；`bms_sleep_config.c` 仅保留默认/校验及纯策略，
`app_power.c` 拥有运行计时。协议继续五 word，最后固定 30 分钟的槽不持久化。
整组候选由 Config journal 一次保存并回读验证，成功后才发布；相同参数不写 Flash，getter 只读 RAM。
BUSINESS/SOC 更新仍保留本域参数；有效旧 CFG2 整套恢复新默认时也使用新休眠默认。
原 SLP1 分区不再读取或写入，范围释放但不自动擦除。当前格式 Config 损坏保持输出禁止，
保护性休眠仍可按安全默认继续决策。详见 [当前存储](STORAGE.md) 和 [本轮验证](STORAGE_SIMPLIFICATION_20261017.md)。
