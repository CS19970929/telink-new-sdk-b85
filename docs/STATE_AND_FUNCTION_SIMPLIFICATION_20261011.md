### 2.1 Config 的比较与提交

`protect`、`system`、`afe_hw` 的连续字段布局仍由原有编译期大小断言约束。
用户参数前七个 u16 复用已有布局约束，校准值分别比较，SN 和蓝牙后缀按实际编码长度比较；
SOC 三个持久字段和 OTA 更新编号也全部参与比较，不比较结构填充。

仅当已有有效记录、无待提交更新且持久字段相同时，保存才直接返回成功。
首次默认参数和 OTA 待提交参数不能被去重跳过；保存失败不发布候选配置、不清待保存标记。
增加了以真实 CFG2 codec 为依据的逐位变更用例，以及相同配置不写入、待提交配置仍写入的用例。
这些用例尚未运行。

### 2.2 采样与异常路径

DVC 主入口仍先采集并合并读清事件，再按新 CC2 发布电流，按新 VADC 发布电压/温度，
最后推进原有采样资格、Open-Wire 和均衡服务。拆出的三个发布函数没有增加总线访问。
诊断期间仍保留正常电压缓存，而原始诊断电压继续交给驱动内 Open-Wire 结果。

SH 主入口仍按以下顺序运行：唤醒/重启采样 → 读状态 → 读单体/总压/电流/温度 →
换算与范围检查 → 新鲜度和硬件状态 → 物理释放证据 → 启动资格 →
电压/电流/温度发布 → 软件保护/硬件恢复 → 标记快照有效。
保护更新中的短路恢复或清标志失败仍返回原诊断阶段，再由外层采样入口撤销资格并进入通信失败处理。
这保留了既有“测量发布之后恢复操作仍可能失败”的边界，不声称已经实现原子发布。

## 3. 核对后保留的候选

| 对话候选 | 当前源码事实与决定 |
|---|---|
| `s_current_recovery_requires_evidence` | 软件保护初始化还会用它决定三级过流锁存是否保留；删除会改变重初始化后的恢复条件，保留 |
| DVC 底层与适配层均衡请求 | 底层先记请求且后续写入可能失败，适配层只在成功后更新；底层还负责周期刷新和暂停恢复，不能合并 |
| feature 均衡 requested/applied/readback | 分别表达策略请求、提交结果和硬件状态，并被诊断/日志消费，保留 |
| SOC 当前输入与上一接受电流 | 当前快照在资格判断前更新，历史电流只在首次/间隙/接受样本时更新；积分方向和时间轴不能用当前字段替代 |
| SOC 诊断字段归子结构 | 只有组织效果，不能减少有效状态或 RAM；当前接口明确，不为统计值搬动全部引用 |
| State pending 与持久 cache | 待保存候选和成功提交状态在失败/退避期间不同，保留 |
| UART/DMA 双缓冲 | 有中断、发送及协议处理的独立生命周期；无并发及栈证据，不复用 |
| `bms_sw_evaluate` | 各类保护的阈值、触发/恢复滤波和统一出口目前可直接追踪；不为缩短行数再增加转发函数 |
| 参数写入、诊断读取、DVC ConfigServiceRead、双后端 apply_protection | 地址/字段映射及芯片事务各有现有所有者；本轮没有证明强拆能减少状态或重复实现，保留 |
| SIF ISR、journal、硬件恢复 | 时序、提交顺序和物理证据优先，不因大函数机械拆分 |

本轮没有发现可以直接删除整个核心模块而保持现有功能的依据。未新增 manager/service、
ops 表、callback、同步脚本或产品源码副本。
