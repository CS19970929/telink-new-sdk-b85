# D008 存储、三级保护与固件升级

对应独立 `feature/d008-clean-rebuild`，基线 `ec01199b`。构建源以 [d008/build.py](../d008/build.py) 的 `sources` 为准，业务来自 `d008/`，支撑来自 Telink B85 SDK 和 Patch 0001。旧 D008 用于核对阈值和协议。BMS-Lite 提供独立数据恢复与固定编号合同。DVC 寄存器以 DVC1124-2 DS V1.1、RM V1.2 为准。[BMS-Lite 参考版本](https://github.com/CS19970929/bms-lite/commit/4dc56fe239ee581e8620b2b98c7d1db48baa9bb2) · [AFE 资料](AFE_REFERENCE_GUIDE.md)

## 运行路径

| 环节 | 原实现 | 当前入口与行为 |
|---|---|---|
| 上电 | 由 CONFIG 决定清理六个扇区。AFE 首次失败可能丢失请求 | `device_init → load_config` 分域恢复。`device_service → afe_setup_step` 确认双关并优先写 `0x62/0x63`，建立 CONFIG 后重新核验 DVC。保留请求，失败后按 5 s 节拍重试 |
| 正常运行 | 200 ms 采样，软件三级单档 | `main → device_measure → afe_sample → control_sample → afe_outputs`。三档共享采样。`soc_sample → meter_sample` 计算净量及实际放电量。正常 Suspend 保留 RAM |
| 参数写入 | 先应用硬件，再尝试保存 | `rtu_channel → register_write → device_set_config`。候选合法、确认双关后先提交 MCU 期望配置，再应用及读回 DVC。保存或硬件应用失败返回错误，随后自行核验 |
| 掉电恢复 | CONFIG 影响 SOC 和历史 | `store_open_config` 读取合法参数，`store_open` 恢复 SOC，`store_open_log` 建事件索引。提交不确定时重新扫描对应区域 |
| 关机与 OTA | 关机单次保存。OTA 回调直接解锁 | `device_powerdown → device_service → finish_powerdown` 有界保存。`ota_receive → device_prepare_ota → otaWrite` 核验双关并检查 SDK 解锁范围 |

## Flash 与记录

| 域 | 扇区基址 | 格式常量和值 | 载荷 | 槽位及每扇区数量 |
|---|---|---|---:|---|
| CONFIG | `0x40000`、`0x41000` | `CONFIG_FORMAT_VERSION = 2` | 264 B | 512 B × 8 |
| SOC | `0x44000`、`0x45000` | `SOC_FORMAT_VERSION = 2` | 32 B | 64 B × 64 |
| LOG | `0x4C000`、`0x4D000` | `LOG_FORMAT_VERSION = 2` | 14 B | 32 B × 128 |

记录头 12 B，按小端编码 `D8`、域格式、域编号、16 位长度和 32 位序号。载荷后为覆盖头和载荷的 CRC32。最后一字节 `0x3C` 表示提交。其他空隙为 `0xFF`。CONFIG 使用 `Config` 固定布局，包含串数、化学体系、容量、端点、三级阈值、DVC、均衡、校准、SN、11 个更新编号和出厂代号。编程分 256 B、24 B 和提交标记 1 B。SOC 使用 `SocSnapshot`，包含剩余量、累计放电量、SOC/循环编号、额定容量、显示值及出厂回执。LOG 使用小端清除代、编号、出厂回执和事件码。`product.c`、`soc.c` 检查尺寸和偏移。

`store_append` 先写正文、回读，再提交和复读。BLE 暂缓第二页或提交标记时续写已回读的同一槽。轮转保留含最新可信记录的扇区，CONFIG/SOC 同值免写。日志保留最近 100 条。大量坏槽时可丢弃回收扇区中的最早记录并报告降级。三个区域总占 24 KiB。

同格式且有效直接加载。格式不同、空白或无可信记录，从当前默认参数或采样建立本域。开发阶段不迁移历史 EEPROM、Flash 或 FORMAT 1。优先用空槽，必要时才擦当前域。CONFIG 全损坏且读正常时用本装配默认值，原单板校准需现场复核。同格式其他装配记录触发门禁。Flash 读错时停止该域擦写。关键配置或 AFE 不可信时抑制输出，SOC、LOG 错误可独立降级。

`nor.c` 限定 512 KiB、活动 APP `KNLT`、允许 MID、Page 边界和业务白名单。SDK Flash 读取接口无物理错误状态，依赖布局、状态、CRC、冗余和读回判定。BLE 编程申请至少 10 ms BRX 空窗，长擦除等断开。SIF 发帧与 OTA 都禁止业务擦写。MCU watchdog 2 s，DVC bus watchdog 4 s。实际擦除时长与现场通信仍需实测。

## 三级保护及协议

`Limit` 包含 `alarm1`、`alarm2`、`trip`、`release`、`delay_ms`。单体和总压过欠压、双向过流、充放电高低温、MOS 高温、单体压差共 12 项。每档独立计时，三档共用该项目延时。一级、二级离开阈值即撤销。三级按方向和恢复值仲裁，电流恢复保留反向电流或已移除负载的证据。MOS 高温及压差三级为公共保护。均衡继续受既有充电方向与温控限制。

第 13 组低 SOC 默认 20/10/5%，只提示，恢复值结合该级阈值并独立计时。DVC 原生 SCD/OCD/OCC 和锁存沿用，重配不清 SCD。三级和硬件事件的持久编码沿用，一级、二级和低 SOC 在实时窗口显示。

Classic 和 Android 共享 `0x2100～0x2140`。每组依次是一级、二级、三级、恢复和 10 ms 延时。`0xD03A/0xD03B/0xD03C` 为状态，低 SOC 位 12，MOS 高温位 13。DVC 维持 `0x2500` 请求、`0x2540` 应用视图。等效循环读 `0x2319` 和实时字 57，`0xFFFF` 表示不可用，允许写 0～65534。保留 Build ID、均衡、校准、SN、手动休眠、Modbus、锂神标准/扩展、A1.3.3、BLE MTU 65 及官方 OTA。现有 Classic 恢复分组使用 `0x2E10` 的 1～3。其余运维命令可由维护工具调用，当前客户端无需改源码。

## 维护教程

| 操作 | 入口 |
|---|---|
| 发布普通升级 | 保持三域格式及已有仍有效的任务不变。按 `Ctrl+Shift+B` 选择正确装配、容量及协议。按既有流程生成签核 BIN，用 Classic 或 Android Sender 走官方 OTA |
| 修改新板容量 | 改构建 `--capacity-dah`，单位 0.1 Ah。有效同格式客户容量沿用 |
| 新增或删除配置字段 | 改 `Config`、默认值、校验及布局断言，提高 `CONFIG_FORMAT_VERSION`。协议保留字在寄存器层保留 |
| 单独改变 SOC 或 LOG | 改各自的格式编号、载荷及相关测试，其他域保留 |
| 改一级报警默认值 | 改 `product.c/config_defaults`，核对化学体系、单位、阈值单调性。已有板用上位机或固定任务更新 |
| 修改现场单项保护或硬件短路 | `update_policy.h` 配置 `D008_CONFIG_UPDATES`，如 `sw[OV].trip`、`hw_sc_a10`；按最终限值、离散步进及硬件实测验收 |
| 修正现场容量 | `UPDATE_CAPACITY` 采用新编号和固定 `capacity_dah`，恢复时按快照容量换算 |
| 设置、重估 SOC | 显式写 `0x1005`；固件设 `D008_SOC_UPDATE_ID/PERCENT`。值 101 等待合格静置 |
| 清零或设置循环 | `0x2319` 写目标值；固件设 `D008_CYCLE_UPDATE_ID/COUNT` |
| 清日志 | 维护命令 9 或提高 `D008_LOG_CLEAR_ID` |
| 完全恢复出厂 | 维护命令 `0xFAC7`，用 `0x2E11` 查进度 |
| 接管未知历史板 | 核对装配、APP 槽、MID 及 SDK 校准保留区。历史安装器仅在确认布局和包格式后使用。否则用可核对地址的 SWS 工装 |

默认值只用于初始化及显式恢复。编号 0 表示无任务，编号与固件版本和格式分开。每个目标编号递增，发布后绑定固定目标。保留需要跨版直达的任务。组合条目可使用同一目标编号；独立任务使用各自目标。先对可信候选应用任务，再校验最终参数。修改数据和完成编号同条提交。普通保存保留回执。提高对应格式时重新建立该域并应用当前任务，其他域不动。默认交付全部更新任务关闭。

```c
#define D008_CONFIG_UPDATES \
    D008_UPDATE(UPDATE_CAPACITY, 1, capacity_dah, uint16_t, 300), \
    D008_UPDATE(UPDATE_HW_SC, 2, hw_sc_a10, uint16_t, 6000),
```

容量变化按 `旧剩余量 × 新额定容量 ÷ 快照额定容量` 换算，显示百分比不重算。累计实际放电量保持，等效循环用当前额定容量作分母。充放电跨零按线性正区间计算。SOC 与循环独立。必要保存发生于初始化、管理操作、固件任务、关机和 OTA，Suspend 无周期写入。突然断电恢复最后可信快照。显式 OCV 需完整采样、低电流、压差合格且无活动保护，连续至少 5 s。资格中断重新计时。后台重试，未完成的任务不写回执，保护和 MOS 照常仲裁。LFP 中间平台沿用保守估算，精度需要电芯验收。

## 管理与出厂续做

`0x2E10` 要求单播及 `0x42` 维护会话。1 恢复软件保护，2 恢复硬件保护，3 恢复容量及均衡，4 恢复均衡，5 恢复 SOC 端点，6 恢复软件电流校准，7 按可信静置采样重估 SOC，8 清循环，9 清日志。各候选仍校验全套参数关系。

`0xFAC7` 先提交带奇数代号的默认 CONFIG。命令应答表示已持久接受且初次 DVC 核验通过。随后提交 SOC 50% 与零循环，写日志清除代，最后提交偶数代号。期间双路关闭。复位根据各域回执续做。校准、SN 和已完成的固件任务保留。CONFIG 独立改格式后以三域最大代号递增。`0x2E11` 高字节 `0xD8` 为支持标识，bit 0 为待完成，bit 1 为本次启动的存储异常。日志清空后允许真正的新事件入库。

## 关机与 OTA

- 双槽为 `0x00000` 和 `0x20000`，镜像上限 124 KiB。仅占用 `[0x00000,0x1F000)` 或 `[0x20000,0x3F000)`。业务始于 `0x40000`，MAC、RF 校准和 SDK 保留区在此之外。
- 实际 B85 `liblt_825x.a(ota_server.o)` 中，`otaWrite` 的写入解锁范围为 `[0, ota_program_bootAddr + ota_firmware_max_size)`。目标写入、失败清理及 `bls_ota_clearNewFwDataArea` 按 `ota_program_offset` 与镜像界限限制。启动标志在槽内。应用核对 BEGIN 地址，在 END 和失败路径重新锁定低 256 KiB。
- 开始前核验双关并停均衡。OTA 中继续采样和保护，MOS 保持软件双关，业务写擦互斥。空窗不足后尝试断连补存。SOC 不可用且实际双关已核验时，可使用上份快照继续升级。CONFIG 或 AFE 安全资格无法确认时用 SWS。未知历史安装器的布局须独立核对。
- 关机先等已接收的应答，再确认双关、停止 SIF 和广播、请求断开 BLE。软件预算 900 ms，550 ms 起不再发起下一次 Flash 操作，为最后一次预留 350 ms。尽力保存 SOC 和日志，再执行 AFE Shutdown 及原板级关机。保存失败沿用最后快照。实际阻塞上限受 NOR 状态影响。无法核验关断时保持 DVC 总线静默，由其 watchdog 接管。充电器保持输出时的 PC4 掉电及低功耗电流需台架测量。
