# SH AFE 四路温度保护开关

2026-10-20 实现。源码基线 `53e39227`，Windows 维护目录基线 `2d135e1b`。本轮仅源码、原厂依据和 Git 差异审查；新增回归尚未运行，没有编译、EXE 发布、BIN、烧录或 OTA。

## 芯片含义和产品默认

SH36735XX CV1.0A 原 PDF p14..15、p34：SCONF6 `0x45` 的高四位依次为 TS4_EN、TS3_EN、TS2_EN、TS1_EN。每一位同时控制该温度点的充电高温、充电低温、放电高温、放电低温。所有启用点共用 OTC/UTC/OTD/UTD 四个阈值，没有逐通道独立阈值，也没有逐通道的“仅低温关闭”位。

VADC 外部四路温度采集见 p19。关闭通道的硬件保护不会关闭采样，不会删除软件电池温保、MOS 高温或必需 NTC 断线诊断。芯片内部高温保护是另一机制，不能当作外部电池/MOS NTC 保护。

| 产品 | TS1 / 电池1 | TS2 / 电池2 | TS3 / 加热 | TS4 / MOS |
|---|---|---|---|---|
| D011 | 默认开，可配置 | 默认开，可配置 | 默认关，可配置 | 默认关，可配置 |
| D013 | 默认开，可配置 | 默认开，可配置 | 未接入，禁止开启 | 默认关，可配置 |
| D014 | 默认开，可配置 | 默认开，可配置 | NC，禁止开启 | 默认关，可配置 |

板级支持取当前产品 `SH3673510_PRODUCT_HEATER_NTC_SUPPORTED` / `SH3673510_PRODUCT_MOS_NTC_SUPPORTED`，不从型号名猜测实装。TS4 开启会受电池的低温阈值和高温阈值共同约束；其软件独立 MOS 高温阈值继续独立，不能把这两个概念混为一项。

## 两处源码配置和 Windows 页面

源码窗口 `bms_tools/configure_parameters.py` 在“软件 / AFE 硬件保护参数”和“原厂寄存器 / 每一位”页均有 TS1～TS4 复选框，共享同一组待编辑值。SCONF6 四个原始字段各自反解到唯一的 `SH3673510_HW_DEFAULT_ENABLE_TS1..TS4` 宏；不再把 TS1/TS2 反解到同一个总开关，也不保存第二份 raw 覆盖。

宏仍放在各产品 `dXXX_protection_config.h`。既有 `SH3673510_HW_DEFAULT_ENABLE_TEMP` 保留为源码总许可；四个复选框按实际组合展开并同步该许可。首次默认保持原 TS1/TS2 开、TS3/TS4 关。修改后按原保存流程更新选定产品的 OTA 内容摘要与一次性标识，已保存设备参数仍优先，普通保参升级不隐式改选通道。

公共默认构造和范围检查属于既有 OTA 摘要输入，因此本次一并刷新已选更新组的 D008/D014 包摘要与一次性标识，组选择不变。D014 当前工作区的客户容量、阈值、出厂组和原寄存器修改保留；提交中的 D014 仅包含通道宏和对应基线包标识，不带入这些客户待提交参数。

客户版和内部版 Windows AFE 页面在“温度保护”分类显示四个独立开关及 requested/effective，未接入通道禁用。旧固件仍显示原 TS1/TS2 联动状态，通道开关只读并提示需配套固件。SCD 和温度开关共享 word34，组装候选按各自位掩码合并，不能后编辑的开关覆盖之前的修改。

保存前原确认框列出通道变化及全关的影响。关闭全部通道不自动改变保留的温度阈值；只要有任一通道启用，四种阈值仍须满足原厂保证范围，包括 UTC 的 −20..10℃。本功能不把 AFE UTC 放宽为 −25℃，也不修改软件低温的充电方向门禁或开 MOS 前策略。

## 原 35-word 和 Flash 布局内的扩展

仍是 `0x2500..0x2522`、完整35-word、原 `0x42` 授权/分片/提交和 Config schema4。结构大小保持70字节，不新增 Flash 字段或扇区。仅使用原 word34 `enable_mask` 的预留位：

| 位 | 语义 |
|---|---|
| 0..6 | 原有 COV/CUV/OCD/OCC/SC，使能含义不变 |
| 7 | TEMP：至少一个硬件温度通道启用 |
| 8..11 | TS1、TS2、TS3、TS4 |
| 12 | TEMP_CHANNEL_SELECT：通道位使用明确的新语义 |

旧记录 bit12=0，bit8..11 必须为0，bit7=1 仍表示 TS1/TS2 同开；bit7=0 仍全关。读旧记录不落盘、不转换。新记录 bit12=1，bit7 必须与通道非零一致；空通道组合合法，未接入通道拒绝。

capabilities 在同一组位上声明支持的通道和新语义。当前 D014/D013 为 `0x1BDF`，D011 为 `0x1FDF`，DVC 不声明此功能。旧客户端仍可保留未知使能位完整写回，旧固件拒绝新通道位，因此新客户端对旧固件不发送通道修改。**新通道记录不能保证被旧固件接受，回刷前须按对应版本的参数备份/恢复规程处理；不宣称无损降级。**

旧客户 JSON 缺少且仅缺少这四个新增宏时，按旧规则补为 TS1/TS2=1、TS3/TS4=0，并保留旧总许可；载入提示明确告知，不覆盖当前窗口的其它状态。其它字段缺失仍拒绝，原 JSON 不改写。

## 应用、有效值和故障恢复

通道位走同一完整事务：校验、Config journal 提交、AFE 应用及全部 owned 位回读；失败执行原完整回滚。只有 SCONF6 及相关配置全部验证成功才发布有效通道掩码。Windows 比较 requested/effective 的通道组合，不一致保留失败，不自动重发。

任一温度通道启用时，仍写入并验证四个共享阈值；全部关闭时不再量化和写入未启用的阈值，避免一个未启用的温度值使“关闭通道”本身失败。

温度锁存恢复使用所有已启用通道的 min/max 和有效性；启用 TS4 时，不能只凭 TS1/TS2 电池温度恢复就清除 MOS 触发的硬件标志。未启用点不参与该硬件恢复判断。明确关闭全部通道后可以按原 VADC/连续确认/W0C/读回链路撤销旧硬件温度锁存，软件保护仍独立阻断输出。
