# OTA 参数更新：客户只需一个 BIN

四产品共用实现。Ctrl+Shift+B 窗口将更新组、新默认值和固定标识保存到各产品源码，构建时全部编入 BIN；客户直接升级即可，不要求读取客户板子的旧编号，也不需要升级后由上位机补写参数。有线烧录后启动使用相同规则。

2026-10-19 四产品默认值均由各自的 `dXXX_protection_config.h` 独立保存，包括保护、SOC/OCV、容量及 `OTA_SOURCE_POLICY` 区域；SH 仅共用范围检查。客户方案可通过源码窗口另存 JSON，载入方案不会立即写源码或改变 OTA 更新组，见 [客户配置流程](CUSTOMER_CONFIGURATION_WORKFLOW.md)。修改后在窗口选择对应更新组，将固定标识与参数一起保存到源码，不改历史 revision；Git 提交不作为构建或 OTA 门禁。App/Windows 整套 LFP/NMC 切换、密码和保留范围见 [四产品参数与类型切换](BATTERY_TYPE_SWITCH.md)。

当前编辑与直接构建流程见 [源码配置与固定 OTA 标识](SOURCE_CONFIGURATION_WORKFLOW.md)。构建和发送阶段不接受环境宏临时覆盖，但允许使用已写回源码的未提交参数。

## 源码中保存的更新选择

| 选择 | 更新内容 |
|---|---|
| 全不选 | 保留健康设备的全部持久参数和状态；编译默认仅供空白设备使用 |
| 软件保护 `sw` | 整组软件保护阈值、恢复值、滤波等 |
| AFE 硬件保护 `afe` | 整组 AFE requested profile；启动后由原驱动量化、应用和验证 |
| 容量 / 加热 / 均衡 `business` | 名义容量、加热开关/温度、均衡电压/压差；保留均衡许可 |
| SOC 配置 / 电池类型 `soc` | 完整 OCV 曲线、化学体系和全部 SOC 算法参数；不清空当前 SOC/循环 |
| 更换电池：重置 SOC / 循环 `soc_state` | 恢复源码初始 SOC、放电累计和循环默认，不代表实测电量校准 |
| **恢复出厂 `factory_reset`** | **必须独占选择**；Config、State、Event 全部重建为新固件默认，清除客户校准、SN、均衡永久许可及事件历史 |

普通分组更新保留电流校准、SN/蓝牙后缀和历史事件；独立 `factory_reset` 则明确清空这些业务数据。业务参数按整组更新：选容量/加热/均衡就会一起恢复，不能视为仅修改容量；均衡许可是例外，已有禁止/允许均保持。在线修改单项继续使用原参数接口。

修改 AFE、串数或类型时，窗口及源码保存入口自动选择四组 Config；修改容量时选择业务组。已经选择恢复出厂时保留该独占策略，不被容量等联动取消。参数编辑器修改软件/AFE 保护时同步加入对应更新组。串数改变必须选齐四组；同串数设备改变持久电池类型时，也必须选齐四组，否则固件保持启动输出禁止，不把旧阈值混入新配置。串数变化现仅更新拓扑及四组参数，保留校准和身份。串数/AFE 型号必须匹配实际芯片与接线，软件不能增加物理通道。

OTA 可以正常切换 NMC/LFP，无需恢复出厂：用目标类型与四组 Config 的一致更新包即可，普通更新继续保留校准、SN、事件及未选 SOC_STATE 的循环/SOC状态。向不同历史配置的设备发送镜像时，不能假定其持久类型与本机源码相同；需要统一为镜像类型时明确选四组 Config。“保留参数”用于不切换设备参数的程序更新。

## 一次性执行

`BMS_OTA_UPDATE_MASK` 表示所选组，默认 0；位 0/1/2/3 对应上述四组 Config，位 6 对应 SOC_STATE，位 9 对应独占的 FACTORY_RESET。其它位编译时拒绝，恢复出厂不能与任何其它更新组混合。工具在保存新参数更新包时生成并固定标识；保参策略的标识为零。编译和发送不生成标识。标识通过 `BMS_OTA_UPDATE_ID_0..5` 六个 16-bit word 编入固件，不由客户输入。

- 标识首 word 为 0，区别于旧实现合法的 1..65535 编号；其余 80 位由密码学随机源生成，意外重复概率极低，不宣称数学上绝不碰撞。
- Config 启动只比较最后执行标识是否与本 BIN 一致；不一致则复制所选组的新默认，校验后将参数和标识放在同一条 journal 记录提交。
- State 独立执行同样规则，未选 SOC_STATE 时不消费它的标识。
- 同一更新 BIN 连续重启或重复刷入，不重复恢复；客户之后在线改参数，重启仍保留。
- 每域只保存最后一次执行标识。先升级更新包 A、再 B、再回刷 A，受影响域会重新执行 A 的选择。保留模式 BIN 不覆盖已有执行标识。

源码保存固定参数、更新组和标识，编译、manifest、verify 和发送读取同一份源码配置，发送前核对完整构建输入和 SHA-256；不会在发送阶段重新生成标识。只有保存新的更新内容，或明确选择制作新参数更新包并保存，才生成新标识。Git dirty 不阻止构建或发送，manifest 会记录 dirty 状态和实际输入哈希。同一配置普通重编和重新发送不会改变标识。交付已经校验的 BIN，不用重新编译代替原交付文件。

## 当前格式与明确恢复出厂

当前 Config/State/Event 内部 schema 4，payload 为 414/24/202 bytes；三主分区地址、CRC 和最终提交方式保持，原独立曲线/休眠区释放。

- Config 同一记录包含完整低频参数和本域执行标识，删除重复 SOC 选型和废弃学习开关。
- State 的 SOC/放电累计/循环位于 0/4/8，执行标识位于 12..23，没有学习槽和历史编号。
- Event 只保存写位置和 100 条 ID/时间码，不保存重复次数或更新编号。同格式内 OTA 不清空历史。
- 普通镜像完全不读取旧 CFG2；非空白旧格式与无有效当前 Config 的损坏均拒绝输出。当前 schema 4 保留模式不因历史编号改变而覆盖参数。
- 整区空白时建立默认；明确 `factory_reset` 包即使面对旧/未知格式也重建三域，所有提交成功前不放行。状态标记记录在 Config 的 OTA ID 第一 word（进行中为 `0xFA57`，完成为 `0`），中途断电续做。

旧 `BMS_BUILD_PARAMETERS_REVISION` / `BMS_BUILD_SOC_STATE_REVISION` 工具选项已移除，残留宏会被拒绝。`0x2E80..0x2E88` 地址仍返回历史常量以保持协议兼容，不能用于判定新更新是否完成。旧实现固件不理解新标识：回刷后可能按原编号策略恢复参数，包含校准和身份；不能将旧固件视为无损保参回退方案。

## 断电、失败与验收

参数和本域标识在同一条 CRC/最后提交标记保护的记录中保存。掉电后，已完整提交的域不重复更新，未完成的域使用旧有效记录重试。Config/State 分别提交，不宣称跨域原子性。当前启动门禁只由安全配置决定：Config 校验或保存失败保持输出 inhibit，普通在线保存不能绕过；State/Event 失败报告存储错误并独立重试，不作为参数更新成功的证据。AFE 仍须原初始化、应用和新鲜样本资格才允许输出。

保留模式不会仅因 OTA 或重启额外保存 Config。读取成功但参数无效时仍阻断，不为放行而静默清空无关客户参数。硬件校准、watchdog bus silence、三次新鲜采样资格、SC/OCD/OCC 物理恢复不变。主动断线检测已在本分支删除，见 [删除说明](OPENWIRE_REMOVAL.md)。

升级验收分别核对 Build ID、实际参数、启动存储状态，以及 AFE requested/effective/寄存器读回。Build ID 表示代码身份，相同代码可构建不同参数包，不能单凭 Build ID 证明参数更新。恢复默认值来自源码的开发值，不代替产品签核。

相关用例已更新到 `tests/storage_host_check.py`、`tests/fixtures/d008_storage/stores.c`、`tests/test_bms_tools.py` 和 `tests/d014_defaults_host_check.py`：未知旧编号、16 种 Config 选择、SOC 独立重置、校准/身份/事件保留、重复执行、字节级写中断和拓扑/类型组合。2026-10-10 本次仅完成实现、源码审查和 Git 差异检查，未执行 host、固件编译、镜像生成或 OTA；真实掉电、AFE 应用与客户 OTA 仍待验证。

## D008 开启短路保护（2026-10-08）

当前 D008 默认 SCD 开启：200 A、请求延时 256 µs。源码编辑入口已集中到 `d008_protection_config.h` 的独立 AFE 区域，见 [D008 保护配置](D008_PROTECTION_CONFIGURATION.md)。200 µΩ 下对应 40 mV，DVC1124-2 RM V1.2 原 PDF 第 20 页规定 SCDT×10 mV、SCDD×7.81 µs；现有量化名义延时 249.92 µs，整数 effective 读回 250 µs。本次未改变这些默认或寄存器编码。

本版本更新 D008 AFE 默认时，应在窗口明确选择 AFE 硬件保护；不再通过提高旧 AFE 编号触发。升级后检查 `0x284C/0x284D` requested=40 mV/256 µs、`0x285C/0x285D` effective=40 mV/250 µs，以及 DVC `0x62/0x63` 的 SCDE/SCDT/SCDD。以上仅为配置读回，实板短路动作、Gate/Vgs 和恢复资格仍需独立验收。


## D008 均衡测试组（2026-10-10）

初始测试值为开启／3300 mV／10 mV／3 mV，2026-10-12 当前源码已调整为首次默认允许／3300 mV／30 mV／15 mV。D008 产品头 `BMS_D008_BALANCE_TEST_ENABLE` 默认 1，置 0 恢复正常组；其他产品默认不变。制作更新包时勾选 `business`，升级后读回 `0x2E71..0x2E73 = 3300, 30, 15`；`0x2E70` 保留原许可，不能固定期望为 1。此组同时恢复容量/加热，不能作为只更新均衡的开关；选择保留参数不会使旧设备自动采用新默认。新的高电压竞争选串算法随固件生效，切换回差取设备实际保存的启动压差减停止压差；保留 10/3 mV 的设备使用 7 mV 回差，30/15 mV 使用 15 mV 回差。本次未生成或发送 OTA 镜像，详细逻辑与验收边界见 [D008 reference](D008_PRODUCT_REFERENCE.md#136-逐串均衡与上位机对齐2026-10-10-源码审查)。

## 持久均衡许可（2026-10-12）

复用 `0x2E70` / Config `balance_enable`：0 为持续禁止，1 为允许自动检测。禁止成功保存后，普通重启、AFE 重初始化、恢复业务默认和同格式 OTA 的所有参数组更新均保留禁止；只有显式均衡参数写入才能重新允许。恢复出厂包清除这一禁止许可，普通分组升级继续保留。允许不会强制置位均衡 mask，仍须满足电压、逐串压差、采样资格、温度、放电、加热互斥及故障门禁。最大同时串数仍由产品配置控制。

Windows 两版业务参数页提供“永久禁止均衡”和“允许自动均衡”。两者先读设备四个均衡 word，仅修改许可，再按原四 word 事务保存并读回；保存阈值反过来保留刚读到的许可。地址、数量、字节序、缩放、外部许可字段含义均不改变，内部存储使用 CFG4/schema 4。相同配置由现有缓存比较避免重复写 Flash。

保存失败返回异常，不发布候选许可；保存应答/参数读回表示持久配置，不代表物理均衡已经关闭。正常运行的下一次合格采样调度将请求 OFF；AFE 通信异常时沿用关闭重试、最后硬件回读上报及硬件超时，不能保证即时物理关断。Flash 擦除/无可恢复记录及回刷不支持本策略的旧固件不在保留保证内；首次配置仍使用产品默认许可。
