# OTA 参数更新：客户只需一个 BIN

四产品共用实现。Ctrl+Shift+B 窗口选择要更新的参数组，选择、新默认值和一次性标识全部编入 BIN；客户直接升级即可，不要求读取客户板子的旧编号，也不需要升级后由上位机补写参数。有线烧录后启动使用相同规则。

## 窗口选择

| 选择 | 更新内容 |
|---|---|
| 全不选 | 保留健康设备的全部持久参数和状态；编译默认仅供空白设备使用 |
| 软件保护 `sw` | 整组软件保护阈值、恢复值、滤波等 |
| AFE 硬件保护 `afe` | 整组 AFE requested profile；启动后由原驱动量化、应用和验证 |
| 容量 / 加热 / 均衡 `business` | 名义容量、加热开关/温度、均衡开关/电压/压差 |
| SOC 配置 / 电池类型 `soc` | 化学体系、OCV profile、死区、静置时间、误差带；不清空当前 SOC/循环 |
| 更换电池：重置 SOC / 循环 `soc_state` | 恢复源码初始 SOC、放电累计和循环默认，不代表实测电量校准 |

电流校准、SN/蓝牙后缀和历史事件没有更新勾选，始终保留。业务参数按整组更新：选容量/加热/均衡就会一起恢复，不能视为仅修改容量。在线修改单项继续使用原参数接口。

修改 AFE、串数或类型时，窗口自动选择四组 Config；修改容量时选择业务组。用户可调整选择。串数改变必须选齐四组；同串数设备改变持久电池类型时，也必须选齐四组，否则固件保持启动输出禁止，不把旧阈值混入新配置。串数变化现仅更新拓扑及四组参数，保留校准和身份。串数/AFE 型号必须匹配实际芯片与接线，软件不能增加物理通道。

## 一次性执行

`BMS_OTA_UPDATE_MASK` 表示所选组，默认 0；位 0/1/2/3 对应上述四组 Config，位 6 对应 SOC_STATE。其他位编译时拒绝。工具为每次选择更新的构建生成独立标识；全不选时不生成标识。标识通过 `BMS_OTA_UPDATE_ID_0..5` 六个 16-bit word 编入固件，不由客户输入。

- 标识首 word 为 0，区别于旧实现合法的 1..65535 编号；其余 80 位由密码学随机源生成，意外重复概率极低，不宣称数学上绝不碰撞。
- Config 启动只比较最后执行标识是否与本 BIN 一致；不一致则复制所选组的新默认，校验后将参数和标识放在同一条 journal 记录提交。
- State 独立执行同样规则，未选 SOC_STATE 时不消费它的标识。
- 同一更新 BIN 连续重启或重复刷入，不重复恢复；客户之后在线改参数，重启仍保留。
- 每域只保存最后一次执行标识。先升级更新包 A、再 B、再回刷 A，受影响域会重新执行 A 的选择。保留模式 BIN 不覆盖已有执行标识。

窗口在同一次编译、manifest、verify 和发送中复用相同标识，发送前核对完整构建配置和 SHA-256；不会在发送阶段重新生成标识。再次打开窗口明确选择更新并编译，会生成新标识，即使默认参数内容相同也表达一次新的恢复操作。交付已经校验的 BIN，不用重新编译代替原交付文件。

## 当前旧记录兼容

保持 Config/State/Event 内部 schema 3、payload 长度 322/44/404 bytes、Flash 分区、journal 槽位、CRC 和提交标记不变；没有新 Flash 管理层。

- Config 偏移 310..321 原六组编号槽复用为执行标识；其余参数位置和数据原样保留。
- State 偏移 12..23 原废弃学习槽保存执行标识，24..39 继续写零；SOC/放电累计/循环仍在 0/4/8，历史编号仍在 40。
- Event 不再比较历史编号，不因此清空有效事件。
- 旧 schema 3 记录可直接读取：保留模式不因旧编号不同而覆盖；更新模式将其视为尚未执行本包，并只更新选中的组。
- 更早的开发 schema/Flash 布局仍按项目既有约定不迁移；空白或不兼容记录使用默认，端口明确 I/O 错误不覆盖记录。安全配置失败禁止输出，State/Event 按当前独立降级策略处理。

旧 `BMS_BUILD_PARAMETERS_REVISION` / `BMS_BUILD_SOC_STATE_REVISION` 工具选项已移除，残留宏会被拒绝。`0x2E80..0x2E88` 地址仍返回历史常量以保持协议兼容，不能用于判定新更新是否完成。旧实现固件不理解新标识：回刷后可能按原编号策略恢复参数，包含校准和身份；不能将旧固件视为无损保参回退方案。

## 断电、失败与验收

参数和本域标识在同一条 CRC/最后提交标记保护的记录中保存。掉电后，已完整提交的域不重复更新，未完成的域使用旧有效记录重试。Config/State 分别提交，不宣称跨域原子性。当前启动门禁只由安全配置决定：Config 校验或保存失败保持输出 inhibit，普通在线保存不能绕过；State/Event 失败报告存储错误并独立重试，不作为参数更新成功的证据。AFE 仍须原初始化、应用和新鲜样本资格才允许输出。

保留模式不会仅因 OTA 或重启额外保存 Config。读取成功但参数无效时仍阻断，不为放行而静默清空无关客户参数。硬件校准、watchdog bus silence、三次新鲜采样资格、SC/OCD/OCC 物理恢复及断线检测策略不变。

升级验收分别核对 Build ID、实际参数、启动存储状态，以及 AFE requested/effective/寄存器读回。Build ID 表示代码身份，相同代码可构建不同参数包，不能单凭 Build ID 证明参数更新。恢复默认值来自源码的开发值，不代替产品签核。

相关用例已更新到 `tests/storage_host_check.py`、`tests/fixtures/d008_storage/stores.c`、`tests/test_bms_tools.py` 和 `tests/d014_defaults_host_check.py`：未知旧编号、16 种 Config 选择、SOC 独立重置、校准/身份/事件保留、重复执行、字节级写中断和拓扑/类型组合。2026-10-10 本次仅完成实现、源码审查和 Git 差异检查，未执行 host、固件编译、镜像生成或 OTA；真实掉电、AFE 应用与客户 OTA 仍待验证。

## D008 开启短路保护（2026-10-08）

当前 D008 默认 SCD 开启：200 A、请求延时 256 µs。200 µΩ 下对应 40 mV，DVC1124-2 RM V1.2 原 PDF 第 20 页规定 SCDT×10 mV、SCDD×7.81 µs；现有量化名义延时 249.92 µs，整数 effective 读回 250 µs。本次未改变这些默认或寄存器编码。

本版本更新 D008 AFE 默认时，应在窗口明确选择 AFE 硬件保护；不再通过提高旧 AFE 编号触发。升级后检查 `0x284C/0x284D` requested=40 mV/256 µs、`0x285C/0x285D` effective=40 mV/250 µs，以及 DVC `0x62/0x63` 的 SCDE/SCDT/SCDD。以上仅为配置读回，实板短路动作、Gate/Vgs 和恢复资格仍需独立验收。


## D008 均衡测试组（2026-10-10）

本轮用户指定用于 OTA 后测试的均衡值：开启、起始单体电压 3300 mV、启动压差 10 mV、停止压差 3 mV。D008 产品头 `BMS_D008_BALANCE_TEST_ENABLE` 默认 1，置 0 恢复正常组；其他产品默认不变。制作更新包时勾选 `business`，升级后读回 `0x2E70..0x2E73 = 1, 3300, 10, 3`。此组同时恢复容量/加热，不能作为只更新均衡的开关；选择保留参数不会使旧设备自动采用测试值。本次未生成或发送 OTA 镜像，详细逻辑与验收边界见 [D008 reference](D008_PRODUCT_REFERENCE.md#136-逐串均衡与上位机对齐2026-10-10-源码审查)。
