# OTA 参数更新控制

四产品共用一套实现，共同维护 `bms/products/bms_parameter_policy.h`；当前仅 D008 的 `AFE` 编号为 `2u`，其他产品 `AFE` 及所有产品其余有效编号均为 `1u`。
策略随固件编译，不依赖固件版本号，也不依赖 OTA 工具的隐藏选项；OTA 和有线烧录后启动使用相同规则。

**编号不变：保留设备上保存的值。改变编号：在下次启动写入该类编译期默认值。**
编号范围 1～65535；建议递增。修改源码默认值时，必须自行决定是否同时改变对应编号。
默认值变化而编号不变，只影响空白设备；不会覆盖已配置设备。

| 更新编号宏 `BMS_UPDATE_…_REVISION` | 独立控制的内容 | 固件目标编号读取地址 |
|---|---|---|
| `SW` | 65 个软件保护字段，包括低 SOC 阈值 | `0x2E80` |
| `AFE` | AFE 硬件保护 requested profile | `0x2E81` |
| `BUSINESS` | 名义容量、加热开关/温度、均衡开关/电压/压差 | `0x2E82` |
| `SOC` | 化学体系、OCV profile、死区、静置时间、误差带 | `0x2E83` |
| `CALIBRATION` | 电流 offset 和 gain | `0x2E84` |
| `IDENTITY` | 用户序列号和蓝牙名称后缀 | `0x2E85` |
| `SOC_STATE` | SOC、放电累计、循环 | `0x2E86` |
| 无宏；保留槽 | 恒为 1，无运行状态或重置行为 | `0x2E87` |
| `EVENTS` | 事件环和重复计数 | `0x2E88` |

八类有效编号加一个保留槽，九个地址只读，返回**当前固件的目标编号**，不表示一次未完成的启动写入已经成功。
启动是否完成看公共参数/存储诊断及输出 inhibit。`0x2E05=2` 表示 CFG2 payload 格式版本；Config/State/Event 的内部 journal schema 为 3。
当前上位机无需支持这些新增地址才能进行普通 OTA；若要在 UI 显示策略，需要在 Windows 上位机维护分支另行接入。

## D008 开启短路保护（2026-10-08）

产品确认 SCD 默认开启，触发电流 **200 A**、请求延时 **256 µs**。200 µΩ 采样电阻对应 40 mV，DVC1124-2 RM V1.2 第 20 页给出 SCDT×10 mV、SCDD×7.81 µs；现有驱动向下量化得到代码 4 / 32，名义硬件延时 249.92 µs，整数 effective 读回 250 µs。三个 D008 装配 profile 共用此默认，不改变 `20s-nmc` 其他保护值的未签核状态。

D008 的 `BMS_UPDATE_AFE_REVISION` 从 `1u` 提高到 `2u`。同 schema 3、相同产品/串数设备升级后，下次启动会将**整组 AFE 硬件保护 profile**恢复为新固件默认，包括 COV/CUV/OCD/OCC/SCD；原有自定义 AFE 参数也会覆盖。其余参数组编号不变，软件保护、容量/加热/均衡、SOC 配置、校准、身份、SOC/循环和事件按原规则保留。D011/D013/D014 编号不变。

OTA 后先确认启动存储成功、输出 inhibit 已正常解除，再检查以下读回；`0x2E81=2` 仅表示固件目标编号，不能单独证明落盘或硬件应用成功。

| 读取内容 | 预期值 |
|---|---|
| `0x2E81`：AFE 目标编号 | `2` |
| `0x284C` / `0x284D`：SCD requested | `40` mV / `256` µs |
| `0x285C` / `0x285D`：SCD 硬件寄存器读回 | `40` mV / `250` µs |
| DVC 原寄存器 `0x62` / `0x63` | `SCDE=1`、`SCDT=4` / `SCDD=32` |

重复启动或重复刷同编号固件不再次重置该组；回刷 AFE 编号为 `1u` 的旧固件会恢复旧 AFE 默认，包含此前关闭的 SCD。此次仅修改源码和文档并做源码审查、Git 差异检查，未运行编译/host 测试、生成镜像或执行 OTA；实板短路动作、Gate/Vgs、持续短路、恢复及 OTA/回退仍需验收。

## 示例

假设 D011 当前全部编号是 `1u`，这次只希望 OTA 更新软件保护和 AFE 硬件保护：

```c
#define BMS_UPDATE_SW_REVISION  2u
#define BMS_UPDATE_AFE_REVISION 2u
```

其余六个有效编号保持原值（保留槽无宏），并在 `bms_parameters.h` / 产品 AFE 配置中填写新的默认值。
升级后更新软件、硬件保护；客户容量、SOC 配置、校准、SN/蓝牙名称、运行状态和事件保持。
如果这次只改代码而不覆盖任何参数，八个有效编号全部不变。
如果需要全量重置，八个有效编号全部改成不同的新值。

编号不是“每次开机重置”开关。第一次提交后，设备记录的编号已经匹配；以后重启或重复刷同一固件不再重置。
回刷固件也按**是否相等**判断：旧固件编号不同，同样会写入旧固件的默认值。
需要回退代码而保留参数时，应使用相同更新编号重新构建回退固件。

## 新格式与固定板级配置

当前尚未量产，按项目约定不实现旧板、旧 schema 迁移。
**首次从旧格式切换到 Config/State/Event 内部 journal schema 3 时，旧记录不读取，三域采用当前默认值。**
以上选择性保留适用于已经使用 schema 3 新布局的设备。格式版本与更新编号是两种不同机制。

产品标识和装配串数是板级事实，不能通过业务参数保留覆盖。
串数不同的 Config 记录不会直接使用；切换 D008 装配 profile 应同时审查 SOC 状态是否需要重置。
AFE 接线、ADC 模式、Rsense、唤醒/看门狗等固定板级设置随固件每次初始化应用；
只有持久化的 AFE **硬件保护 profile** 由 `AFE` 编号控制。
芯片上电零点校准是硬件初始化流程，不等于用户 offset/gain，不由 `CALIBRATION` 编号关闭。

更换化学体系、显著改变名义容量时，需明确决定 `SOC_STATE` 是否也更新，循环 SOH 只是估算，不能当新电池的实测容量。
D013/D014 不支持的硬件能力仍由产品配置禁用，更新 heater/balance 参数不会创造硬件能力。

## 提交与断电行为

- Config 的六类参数与六个编号保存在同一条 journal 记录中，统一校验和提交。
- State 只保留 SOC_STATE 编号及 SOC/放电累计/循环数据，同记录保存；Event 自带独立编号。老化计时已删除。
- 三域分别提交，不宣称跨域原子事务。任一域校验/保存失败，启动授权保持关闭，不能由后续普通 `SaveParam` 绕过。
- 掉电后重启：已完成的域不重复重置，未完成的域按原记录重试；全部成功且 AFE 样本合格后才允许输出。
- 参数编号保持不变时不会仅因 OTA 或重启增加一次配置写入。

回归入口 `tests/storage_host_check.py` 覆盖六类 Config 的 64 种组合、各域逐字节写中断、
未选类别保留、启动失败授权、重复启动不再写入，以及编号读取。
真实 OTA 切换、Flash 擦写掉电和 AFE 输出需用实板验收；host 回归不替代这部分。

删除容量学习没有改变 CFG2/State payload 长度和 schema，也未提高 SOC/SOC_STATE 编号；原学习槽作为保留位忽略，保存时写零。此次不主动清空已保存循环数。
