## 第一轮：SH watchdog 恢复保留软件保护

原 guard 在 SH 总线静默后调用 `bms_sw_protection_init()`，会清除除三级过流之外的
软件故障。例如 MOS 已在 95 ℃动作、随后为 85 ℃时发生通信恢复，旧锁存可能消失，
绕过原本 80 ℃的恢复门槛。

增加 `bms_sw_protection_reset_filters()`，只清触发/恢复计数；SH 的 guard watchdog
恢复改用该入口，保留私有活动故障、TEMP_BREAK 及已记录边沿。后续完整有效观察按原
Recover、滤波和物理证据解除故障。MCU 冷启动仍走原初始化；显式禁用仍按原分组清理。
DVC watchdog 恢复策略和完整 `bms_afe_init()` 的既有启动流程未变。

四产品 sources.txt 均包含公共保护和 guard；三个 SH 产品使用同一 SH 后端。
更新实际 SH backend + guard + 软件保护场景，覆盖 95→85 ℃、通信失败、35 s 静默、
重初始化后继续阻断、80 ℃重新完成确认；公共温度场景覆盖恢复计数不能跨重初始化拼接。
同步独立 guard 夹具的新增接口，避免只在组合夹具中提供实现。

本轮只核对调用链、状态所有权、故障/无效输入、计数阶段和 Git 差异。
未运行 host、sources 检查、静态分析、目标编译/链接、资源检查或实板；未生成 BIN。
协议、产品阈值、Flash/schema、OTA 选择/固定标识、watchdog 窗口和 GPIO 均未改变。

## 第二轮：SH 硬件恢复按数据组消费证据

第一轮提交 `9313ec09`。原 `service_hw_flag_recovery()` 只有 CADC 完成时才进入，
内部又要求 VADC 才推进电压/温度恢复，造成无关转换的同轮依赖。
现在调用入口不再由 CADC 总体门控；原函数中 VADC 推进 OV/UV/电池温度，CADC
推进 OCD/OCC。无对应事件暂停该组，两者都没有时不做恢复事务。
不增加事件缓存、ADC 活性或输出资格；SC 仍单独处理。清除失败仍置位原失败锁并上报。

依据本机 SH36735XX CV1.0A 原 PDF p19（VADC 通道及读清完成事件）、p21（独立 CADC
完成事件）、p39–40（FLAG1/FLAG2）；并沿用 [AFE 资料指南](AFE_REFERENCE_GUIDE.md) 的
精确实装型号/硅版本与板级签核缺口。VADC 完成不等于每个 TS 通道都重新转换，
不改变原温度扫描稳定等待或宣称新的温度刷新保证。

调整九组恢复计数场景，补仅 VADC 时电压/温度恢复、仅 CADC 时电流恢复及无事件暂停；
实际 SH + guard + SW 场景验证 VADC 清 OV 而 OCD 保持，CADC 反向电流再解除 OCD。
保留清 FLAG1/FLAG2 次序、清除失败、无效温度、物理证据与 ±200 mA 边界断言。
只完成源码和差异核对，以上场景、四产品构建及实板均未执行。

## 第三轮：关闭诊断或日志时不保存专用副本

第二轮提交 `39901987`。全仓消费者核对后，SH 后端的 `s_flag1`、`s_flag2`、
`s_mos_ntc_raw`、`s_sample_attempt_tick`、`s_sample_attempt_flag2` 仅用于服务诊断；
声明及写入统一由 `BMS_SERVICE_DIAG_ENABLE` 裁剪，关闭时省去专用现场记录和时钟读取。
公共 feature 的 `balance_requested_mask` 只供请求变化日志使用，声明、比较及重置统一由
`BMS_DEBUG_LOG_ENABLE` 裁剪。开关开启时保留原记录内容和更新顺序。

业务所需的 `s_bstatus2`、FET 命令缓存、NTC 电阻、硬件保护标志及恢复计数继续保留；
均衡选择、实际回读、关闭待确认和温度暂停不变。未改变诊断地址、关闭时的能力窗口、
默认开关或量产禁用约束。本轮只核对所有消费者、预处理边界和 Git 差异，未执行
开关组合编译、host 或实板，也没有实测或宣称 Flash/RAM 节省字节数。

## 第四轮：有效性查询不复制测量

第三轮提交 `5b0e5c2`。guard 在采样入口和每次输出仲裁前仍分别检查当前样本资格，
但不再为了一个布尔结果复制辅助测量。内部 `bms_afe_driver_get_aux_measurements(NULL)`
明确表示只读 RAM 有效性查询；SH 直接返回已有资格，DVC 复用 `DVC1124_GetSnapshot()`
返回值并跳过整份快照复制。非空输出的复制和无效辅助测量清零语义保持。

应用层 `bms_afe_get_aux_measurements(NULL)` 仍返回失败。没有新增有效性副本、跨轮缓存、
总线访问或接口层；通信中断、配置禁止、同轮事务失败和恢复后的检查时机不变。
调整 DVC/SH 既有场景和接口替身，覆盖正常、启动未就绪、读失败时两种内部查询的一致性；
DVC 场景使用真实快照读取函数并核对无效辅助输出清零。场景未执行，未做资源测量。

暂不合并 DVC 采样末尾和均衡设置前的回读：前者供本轮选串消费，后者确认执行前状态。
直接删除前者可能在硬件 60 秒自关闭后使用旧状态；为省一次读取增加跨轮缓存及失效路径，
不符合本次精简目标。
