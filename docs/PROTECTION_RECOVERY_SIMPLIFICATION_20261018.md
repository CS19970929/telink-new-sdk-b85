## 第一轮：SH watchdog 恢复保留软件保护

原 guard 在 SH 总线静默后调用 `bms_sw_protection_init()`，会清除除三级过流之外的
软件故障。例如 MOS 已在 95 ℃动作、随后为 85 ℃时发生通信恢复，旧锁存可能消失，
绕过原本 80 ℃的恢复门槛。

增加 `bms_sw_protection_reset_filters()`，只清触发/恢复计数；SH 的 guard watchdog
恢复改用该入口，保留私有活动故障、TEMP_BREAK 及已记录边沿。后续完整有效观察按原
Recover、滤波和物理证据解除故障。MCU 冷启动仍走原初始化；显式禁用仍按原分组清理。
DVC watchdog 恢复策略和完整 `bms_afe_init()` 的既有启动流程未变。

四产品 sources.txt 均包含公共保护和 guard；三个 SH 产品使用同一 SH 后端。
更新实际 SH backend + guard + 软件保护场景，覆盖 95→85 ℃、通信失败、35 s 静默、
重初始化后继续阻断、80 ℃重新完成确认；公共温度场景覆盖恢复计数不能跨重初始化拼接。
同步独立 guard 夹具的新增接口，避免只在组合夹具中提供实现。

本轮只核对调用链、状态所有权、故障/无效输入、计数阶段和 Git 差异。
