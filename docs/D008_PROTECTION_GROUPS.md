# D008 软件保护独立开关与 Windows 批量参数写入

## 编译开关

- `DVC1124_SW_PROTECT_ENABLE`：单体/总压、压差、充电/放电电流的软件三级保护。
- `DVC1124_SW_TEMP_PROTECT_ENABLE`：电池充放电高低温、MOS 高温、必需 NTC 无效保护。默认 1。
- `DVC1124_HW_PROTECT_ENABLE`：现有 DVC 硬件电压/电流及固定 fail-safe 通道，不是电池/MOS 温度保护的替代品。DVC 芯片自身 Core-OT 与外部 NTC 保护不同，本次不改变其固定策略。

关闭电压/电流软件保护时温度保护仍运行；关闭温度保护时只清除温度状态/滤波及 TEMP_BREAK，测温仍继续。全部生产开关默认1。`SW=0,HW=0` 现在仍有温度保护，完全隔离台架才显式设置 TEMP=0。

公共算法新增 `bms_sw_protection_update_groups`，原 update API 默认两组都开启，其他 backend 保持原调用语义；D008 在每次采样传入两组宏。驱动层 NTC 错误上报同步受温度宏控制，避免每帧产生被立即清除的假错误日志。配置校验、Flash 格式和参数升级门禁保持原样。

## Windows 批量写入 0x03 异常

旧批量按钮逐个发送0x06，每个字段都触发固件完整参数校验。例如原First/Second/Third=100/200/300，目标400/500/600，先写First=400会产生临时400/200/300并被0x03拒绝，即使最终组合合法。截图本身不包含具体参数，因此不能认定每次0x03都由此原因引起；最终参数非法仍必须拒绝。

新实现：读取65字新鲜参数，仅合并用户修改，预校验全部最终值；每个项目5字First/Second/Third/Recover/Filter使用一帧0x10写入，再整组回读。19字节请求适配MTU23，不修改MTU、固件协议或寄存器。

跨项目按组依次提交，不承诺全部项目原子性。失败停止并报告当前项目/地址及此前已确认数量；当前组可能已提交但响应丢失，需要重新读取。不执行猜测性自动回滚。SOC旧字段不新增保护语义。
