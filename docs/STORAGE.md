# D008 Flash 存储

D008 使用 512 KiB B85 Flash 布局。启动核对 SDK 容量、支持的 MID、`0x20000` 双槽模式、Flash 状态和当前 APP 启动标识。SDK `flash_read_page` 没有结果码。见证读取可识别整体失读，局部异常由记录 CRC、提交字和写后读回处理。

| 区域 | 地址 | 记录 |
|---|---|---|
| APP A / OTA 元数据 | `0x00000–0x1EFFF` / `0x1F000–0x1FFFF` | 原 SDK 双槽 |
| APP B / OTA 元数据 | `0x20000–0x3EFFF` / `0x3F000–0x3FFFF` | 原 SDK 双槽 |
| Config | `0x40000–0x41FFF` | 两扇区，每扇区 8 个 512 B 槽 |
| State | `0x44000–0x45FFF` | 两扇区，每扇区 64 个 64 B 槽 |
| Event | `0x4C000–0x4DFFF` | 两扇区，每扇区 256 个 16 B 槽 |
| SDK 保留 | `0x74000–0x7FFFF` | 配对、MAC、射频及 ADC 校准等 |

Config 和 State 使用独立 magic 和 schema 1、小端编码、序号、CRC32 和最后写入的提交标记。追加和轮转保留上一有效记录。全空白才建立默认 Config，启动发现未知或损坏 Config 时禁止输出。State 损坏使用候选估值，Event 损坏只影响历史。普通固件不会导入旧格式或使用地址间隙。旧工程迁入本项目的板须由工装按批准的业务扇区准备。

State 保存剩余电量、等效循环余量、容量基准、显示和端点依据。确认端点和显示首次到位优先尝试保存。普通检查点间隔至少 5 min 且有约 2 个百分点的电量、吞吐变化或可见循环变化。有序关机和 OTA 取锁前利用空槽尽力保存。60 Ah 电池持续 100 A 意外掉电时，5 min 节流窗口对应约 13.9 个百分点，另计写入失败时间。

AFE 保护写入先验证候选，确认双路 MOS 和均衡关闭，再应用候选并读回寄存器。Config 持久成功后更新缓存，下一次完整采样恢复仲裁。候选应用失败或 Flash 确认未提交时，恢复并验证旧 AFE。提交结果未知或回滚失败时冻结输出，重启后重新检查记录和 AFE，设备返回写失败及相应状态。

Event 逐条追加最近 100 条。每条包含序号、事件 ID、原协议时间码、格式标识、CRC32 和提交字。恢复按两个扇区的有效序列，读取仍在 `0xC008` 返回最新在前的 `ID << 8 | time`。相邻同 ID 的普通事件在完整秒数不超过 60 时合并。擦除旧扇区前，另一扇区必须已覆盖所需历史。写断留下的空洞不算有效记录。

本方案按 4096 B 扇区和 256 B 页分段编程。页部分编程次数、最低供电、最差擦写时间、寿命和掉电行为需以实装 MID 和器件批次核定，主机 RAM Flash 测试只证明软件记录边界。
