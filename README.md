# HS-D008 独立固件开发

新工程位于 `d008/`。本分支以 `7c3ec352` 为资料基线。原 D008 业务代码和旧工程的构建入口用于追溯现场合同。新目标只选择本目录和 Telink SDK 的源文件，不链接旧 BMS。

## 硬件与资料

| 功能 | 已能核对的设计输入 | 仍需实物确认 |

| MCU | 24S V1 图中 U1 为 TLSR8251F512ET32，Y1 为 24 MHz。芯片有 32 KiB SRAM、512 KiB Flash | 晶振和内部 RC 的全温偏差，本次台架 Flash MID 已读为 0x1360C8 |

## 运行顺序与计量

1. 保持 MCU 电源并初始化板级安全电平。启动 SDK 的时钟、RF、BLE。读配置并确认 AFE 的固定设置、硬件保护和首份测量后，允许输出进入保护仲裁。
2. 每轮运行 BLE SDK，检查同一周期截止点。SDK 的应用层唤醒提前返回主循环，广播和连接的 latency 只影响无线调度。普通 Suspend 保持 RAM。GPIO 提前唤醒仍读同一时钟。
3. 每次到期只采一次，按计划相位推进到未来的第一个截止点。采样周期 200 ms。板载蓝灯 LED1 随采样节拍翻转，关机时熄灭。计量用相邻有效读数的真实间隔，梯形近似区间平均电流，保留有符号余数。短暂重复 CC2 寄存器值是正常输入。失败、冷启动、关机及长停顿切断积分，不补造历史电流。
4. System Timer 固定 16 MHz，32 位约 268.435456 s 回绕。B85 `drivers/B85/lib/include/pm.h` 将内部 RC 绑定到 `pm_tim_recover_32k_rc`。休眠期间高频计时由 SDK 根据低频时钟恢复；应用不二次加上睡眠时长。回绕差成立的条件是两次观察间隔小于一整圈；停机或复位须重新建立基准。
5. 主循环处理保护、端点和均衡，再由唯一出口写输出。通信读取上一份完整测量。请求写入采用候选校验、受控应用及回读、持久提交和读回后应答。长 Flash 事务要让出无线时隙；ISR 只交付数据和发波形。

积分误差分开验算。1 A 连续 1 h 应得 1 Ah。1 mA 的零点偏置一天累积 24 mAh，1000 ppm 时基偏差使 10 Ah 产生约 10 mAh 时间误差。另外记录增益、死区、样本间电流变化和无法计量的时间。虚拟恒流只能隔离时基和算术误差。真实负载必须与独立电量计同步比较。

## AFE 与功率设计

DS V1.1 第 13～16、17～24 页及 RM V1.2 第 2～7、15～27 页给出测量与输出约束。CC2 为 20 位补码，0.3125 µV/bit，名义 256 ms；换算使用装配分流电阻。状态 0x01 中 VADF/CC2F 读清，由驱动单独读取。正常读取 CRC 合格且数值合理即可发布。连续同值不能判定 ADC 停转，须用驱动内连续转换事件缺失和使能状态复核。

总线用 100 kHz、写/读传输地址 0x40/0x41，CRC8 多项式 0x07，初值 0。读首字节覆盖写地址、寄存器、读地址及数据，此后逐字节 CRC。DVC1124-2 电芯字节自 0x1D 至 0x4C 连续，缩串须按实际接线和屏蔽位映射。采样等待首次 VADC 和 CC2 转换完成。主动断线检测已移除，单体电压和压差仍参与保护。失败事务有界退出；持续 1 秒确认故障，撤销输出许可并留足完全静默时间给独立看门狗，成功重配和首次测量后才恢复。

硬件比较器承担快过流/短路；MCU 用有延时与回差的实际动作阈值。AFE 初始化先写入双关命令并确认驱动读回。第一笔 I²C 起始地址阶段无应答时，沿用旧板的供电稳定等待和 SDA 唤醒脉冲后重试一次，随后优先写入并校验短路阈值与延时 `0x62/0x63`，保持短路保护使能和已有锁存。OC/SC 保留直到物理移除或有效反向证据；关断后零电流不构成恢复。单侧关断遇有效反向电流临时放行，双侧关断及共同保护优先。MCU 方向证据最长 400 ms，采样失败撤销临时许可。过流和短路告警锁存跨 AFE 重配置保留，按物理证据清除并读回。均衡按充电、温度、门限和最大通道数选择；0x67～69 有 60 s 自清零，读回及必要续期。PB1 仅提供负载检测信息。GP1 配置为高阻，GP2～GP4 分别提供两路电池温度和一路 MOS 温度，任一校验失败时沿用整份采样失败处理。

## 产品配置、存储与协议

固定路由与装配、电池容量、客户可写保护参数分别归属。客户 SOC 电压参数保留 SOC100、SOC0。新板用首份可信静置测量作保守估计；已有 SOC 直接恢复，长眠间隔不计电量。充电/放电显示遵循对应方向；满端结合充电前史与整包接近满端证据，空端要求可信欠压，不以孤立异常串或负载瞬降校准。手动校正同时同步显示和存储。

APP/OTA 槽保持 0x00000/0x20000，槽尾 4 KiB 为元数据，0x74000 起为 SDK 保留区。上电发现非当前格式时，先确认 AFE 两路驱动已关，再清理 SOC `0x44000/0x45000`、历史 `0x4C000/0x4D000`、配置 `0x40000/0x41000`，六个扇区以外的内容保留。全空扇区跳过擦除。默认配置最后提交并读回，之后重新初始化 AFE，再由保护决定是否开管。初始化期间暂停 BLE 广播，一次主循环最多擦一个扇区。已识别的当前格式记录全部损坏、装配不匹配或初始化读写失败时维持双关，保留只读采样。新记录自有标识，配置、SOC、事件用独立扇区。追加先写载荷和校验，再写提交标志并读回。轮转时保留旧有效副本。日志按序保留最近 100 条。采样失败不应阻塞保护。SOC 在主动关机、OTA、手动校正时保存；异常断电误差按最大电流 × 未保存时长评估，在装配及允许误差确定后选择周期。

UART 115200 8N1 与 BLE GATT 共用 Modbus。单播写 `0x1102=0x000A` 请求休眠，应答发完或等待满 500 ms 后共用保护性关机入口，执行 MOS 双关、AFE Shutdown 和 PC4 断电。OTA 进行中拒绝新休眠请求。单播 `0x1005` 设置 0～100% 的 SOC。暂缺 Flash 写窗口时在 1 秒内重试，提交并读回后才更新 SOC 和应答。BLE 连接期间仅在芯片允许的窗口编程，SOC 两个扇区都写满后在断连空闲时准备备用扇区。主要现场窗口包括 0xD000～D03E 实时量、0x2100～2140 软件保护、0x1005 SOC、0x2318 容量、0x2E00 能力/结果、0x2E24 起校准、0x2E30 起 SN、0x2E70 起均衡、0xC008 历史。AFE 参数依语义窗口及硬件量化返回实际值。MOS 窗口的 `0x2F14` 读回 AFE 驱动状态，`0x2F15` 表示读数有效，`0x2F16` 按 Classic 合同报告总授权、通信门禁、总线静默、故障锁存和采样资格。SIF 有锂神 V1.1.1 和 A1.3.3 客户合同，未装串在后者编码 0xFFFF，其余为 61001。OTA 使用 SDK 双槽和 CRC，普通 OTA 保参。加热能力位已清除，`0x2E20～0x2E22` 保留零值供旧客户端读取，写入返回非法地址。原配置的对应三个字保留 Flash 字节布局。

## 2026-11-26 台架验收

以下为移除板端台架代码前的历史验收，台架源码可从提交 `1dcad260` 查阅。实板为 16S 铁锂，BLE 地址 `A4:C1:38:21:65:3F`。板上最终版本为 `D008-COMM-031ddfc2-LS`，对端为 Classic UI 分支 `ac7f5d30` 的 CLI、BLE 传输和 OTA 实现。通信镜像禁止充放电、加热、均衡和熔断，电流注入仅作用于独立的 SOC RAM 会话。Telink USB 下载器通过 SWS 完成整片备份、读回、复位和清醒期 RAM 观测。

### Flash 提交、恢复与寿命

配置、SOC、事件各用两个 4 KiB 扇区轮转。配置和 SOC 内容相同则跳过写入。提交顺序为写记录体、回读、写提交标志、再次回读。等待 BLE 时隙或一线通发完当前帧时保存进度。清理中断时下次上电重新检查各扇区。首次写默认配置被打断，仅识别可由本次默认记录产生的残片，续写时使用空槽。配置未确认时充放电和均衡均保持关闭，SOC 和历史不写入 Flash。

| 记录域 | 产品载荷 | 主机模拟轮转掉电位置 | 加速测试的变化记录 | 两扇区擦除次数 |
| --- | ---: | ---: | ---: | ---: |
| 配置 | 164 B | 4,278 | 10,000 | 312 / 311 |
| SOC | 12 B | 4,126 | 100,000 | 781 / 780 |
| 事件 | 2 B | 4,116 | 250,000 | 976 / 976 |

主机测试还验证了首写、CRC 损坏回退、最近 100 条事件的顺序，以及 440,000 次配置和 SOC 重复保存均无额外写擦。连续 2,000 次暂缓写提交标志，记录体只写一次。实物 MID 为 `0x1360C8`，SDK 对应 GD25LD40C/E。两款数据手册均给出至少 100,000 次擦写。按当前记录尺寸与双扇区均摊，配置、SOC、事件各域分别约为 320 万、1,280 万、2,560 万次变化记录。这个估算只计算擦写次数，温度、数据保持期和现场写入频度仍需随装配核对。[GD25LD40C 数据手册](https://download.gigadevice.com/Datasheet/DS-00305-GD25LD40C-Rev2.1.pdf)、[GD25LD40E 数据手册](https://download.gigadevice.com/Datasheet/DS-00848-GD25LD40E-Rev1.3.pdf)

实板用产品日志与 NOR 驱动，在独立测试扇区写入 33 条配置测试值、129 条 SOC 测试值、257 条事件。前两类台架值各占 4 B。实测 838 次编程、3 次擦除、227 次暂缓，历时 71.060 s，最长单步 156.914 ms，200 ms 采样漏期为 0。复位后恢复最终值与最近 100 条事件，恢复过程写擦均为 0。

产品三对扇区起点为 `0x40000/0x41000`、`0x44000/0x45000`、`0x4C000/0x4D000`。专用台架固件使用已备份且确认空白的 `0x60000/0x61000`、`0x64000/0x65000`、`0x6C000/0x6D000`。保留台架记录完成 OTA 后，读回的整个高 256 KiB 与升级前逐字节相同。最后清理六个测试扇区，高半区 SHA-256 回到实验前的 `49E807E45B1801EA2E5B50850B456BFE5FA3F8678507527F4EEECB0E0414221C`。

### 官方 BLE OTA 与 Classic 通信

Classic 自动模式在 ATT MTU 65 选择 `LegacyFast`，每个标准包传 16 B。实测 78,260 B 升级收到 `OTA_SUCCESS`，重启后读到目标版本、16 个有效单体、50.22 V 包压和 0 A。未装串返回 61001，SOH 未知时 Classic 显示为“—”。35 个 DVC 参数用 v2 分片合同传输，79 B 请求经 8 片传完，同值回读 35 个字完全一致。通信镜像仅允许这一项同值验通。

另一轮在 32 个有效包后断开，21 s 后原 APP 可连接，重传完整镜像成功。强制 `Extend64` 时这套客户端与 B85 SDK 对首个数据包返回序号错误，当前交付路径为官方标准包与 Classic 自动模式。UART 用于 Modbus。

### 锂神一线通

默认 `--sif lishen` 编码 V1.1.1 六字节标准帧，依次为保留、SOC、包电压 V、最高电池温度 °C、保留、累加校验。保留字节为零，MSB 先发。`--sif lishen-extended` 将首字节用于有符号电流 A、第五字节用于状态。两种合同须按仪表版本选择。每帧占线 379 ms，随后空闲 1,000 ms，此间允许 Suspend。

在 MCU 上模拟仪表在位，从 PC2 输入逐半毫秒回读两帧，电脑独立解码各 1,516 个电平。默认帧两次均为 `00 32 32 17 00 7B`，起始沿间隔 1,379.712 ms。扩展帧两次均为 `00 32 32 17 C0 3B`，间隔 1,379.7865 ms。5 V 外部接口带载波形、首帧和实际仪表显示须接客户仪表验收。

### SOC 与 Suspend

最终固件以 16 段电流覆盖停车、起步、加速、爬坡、巡航及再生制动，范围 −7.5 A 至 +32 A。常醒、普通 Suspend、Suspend 下 60 倍速分别采样 119、120、122 次，三次均无漏期。60 倍速运行对应 1,452.002 s、净放电 4.261640 Ah、唤醒 1,355 次。独立按实际注入时间积分，三轮最大差为 0.975 µA·s。Classic 的 14 项 SOC 检查全部通过，会话结束后原 SOC 和容量恢复。

广播阶段断开 GATT，各观察 30 s，两次都收到了该 MAC 推进的 Windows 系统广播时间戳。常醒时 PC/板端间隔分别为 31.361/31.399 s，唤醒计数为 0。允许 Suspend 时分别为 32.331/32.200 s，唤醒 451 次。两次采样漏期为 0，端点包含 GATT 重连和 200 ms 采样量化，不能据此给出晶振 ppm 或电流。

### 复测入口及未验项

- 在 VS Code 打开独立 D008 工作树，按 `Ctrl+Shift+B` 进入配置窗口。可选择串数、电池类型、首次建档的额定容量及一线通协议，默认 16S 铁锂、20 Ah、锂神扩展。点「仅链接 ELF」生成 ELF/MAP，点「编译 BIN」额外写入根目录 `bin/`，例如 `bin/d008-16s-lfp-lishen-extended.bin`。重复构建相同装配与协议会在镜像校验通过后更新对应文件。ELF/MAP 和中间文件保存在 Windows 用户临时目录。
- 「编译并 OTA」会先把当前装配的正式 BIN 放到 `bin/`，再把本次校验通过的文件交给已安装的 Android Sender。手机需要已配对的 ADB（USB 或无线调试）。用项目安卓 App 先连接串数和电芯类型一致的 D008，保持连接后点「编译并 OTA」。App 对同一连接请求官方 Telink BLE OTA。未连接 BMS 时固件只进入收件箱，仍可在 App 选择目标和确认升级。也可把 `bin/` 的 BIN 复制到手机，在 App 的「固件升级与其他工具」中手动选择，手动方式无需 ADB。Windows Sender 的安装路径可通过 `BMS_ANDROID_SENDER` 覆盖。
- `python -B d008/tests/run.py` 运行主机回归。`python -B d008/build.py --profile 16s-lfp --sif lishen` 默认只生成 ELF/MAP。本轮 16S LFP、20S NMC、23S LFP、24S LFP 四种产品目标通过链接。
- 当前构建只提供正式固件，台架开关及注入寄存器已移除。历史台架的 SOC 注入、Flash 加速轮转、波形回读和 OTA 中断工具可从提交 `1dcad260` 复现。
- 量产验收仍需可编程电源验证擦写中途断电，新格式生产板验证关机/OTA 前保存与恢复，实负载、电量计与电流表验证 SOC 和功耗，故障工装验证 AFE 失联、保护恢复、MOS、均衡及关机唤醒。保护性关机当前只尝试一次保存 SOC，若恰遇 BLE 暂缓或介质出错，重启会恢复上次成功提交的值。能为保存预留多少关机时间、异常掉电允许回退多少电量，仍需确定。
- 铁锂装配沿用旧 D008 的总压恢复值，按每串 3,500 mV（过压）和 3,000 mV（欠压）折算。硬件短路默认 150 mV，按 250 µΩ 标称分流电阻折算 600 A，0x62/0x63 为 0x4F/0x20（约 250 µs）。这些值用于首次建档。本代 Flash 中有效的参数由普通 OTA 保留。
- 首次刷入支持自动初始化的镜像后，旧格式的容量、保护、校准、SN、SOC 和历史会清除，参数按编译装配的默认值建立，SOC 按首份合格测量估算。当前没有整板恢复出厂命令，SOH 与循环数也没有有效量产数据。其余串数只有链接验证。
